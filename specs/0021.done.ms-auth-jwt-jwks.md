# 0021: ms-auth — JWT-issuer, JWKS-endpoint, refresh-rotation

## Scope

`ms-auth`. Пакеты выпуска/подписи JWT (RS256), публикация публичных ключей через `GET /.well-known/jwks.json`, хранение и ротация opaque refresh-токенов в `auth.refresh_tokens` с reuse detection.
После этого спека — есть `TokenService`, который можно вызывать в коде, и реально работающий JWKS-endpoint. HTTP-эндпоинты аутентификации — в спеке 0022.

## Context

- Предыдущие спеки: [`0018`](0018.ready.ms-auth-skeleton.md), [`0019`](0019.ready.ms-auth-migrations-seeds.md), [`0020`](0020.ready.ms-auth-identity-provider.md).
- ADR: [ADR-0007](../docs/08_ADR/ADR-0007-service-accounts-env-secrets.md), [ADR-0012](../docs/08_ADR/ADR-0012-ms-auth-pluggable-identity.md).
- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md).
- API-контракт формата токена: [`docs/04_API/ms-auth.md`](../docs/04_API/ms-auth.md), раздел 7.
- Приватный ключ берётся из env — **путь к PEM-файлу** (`MS_AUTH_JWT_PRIVATE_KEY_PATH`) или inline PEM (`MS_AUTH_JWT_PRIVATE_KEY`). Путь приоритетнее. Публичный ключ выводится из приватного.
- Библиотека подписи — `github.com/golang-jwt/jwt/v5` (стандарт, maintained). Иначе — `github.com/lestrrat-go/jwx/v2`; предпочтительно первый как более лёгкий.
- Refresh-токен — opaque строка 32 случайных байта → base64url (43 символа). В БД хранится только `sha256(hex)` от opaque строки.

### Config (добавление)

```go
type Config struct {

    JWTAudienceService string // MS_AUTH_JWT_AUDIENCE_SERVICE, default = "controlitix-internal"
    JWTAccessTTLSec    int    // MS_AUTH_JWT_ACCESS_TTL_SEC, default = 900
    JWTRefreshTTLSec   int    // MS_AUTH_JWT_REFRESH_TTL_SEC, default = 1209600 (14 дней)
}
```

`LoadConfig` требует наличия либо `JWTPrivateKeyPath`, либо `JWTPrivateKeyPEM`.

### Keystore

```go
package jwks

type Keystore struct {
    privateKey *rsa.PrivateKey
    keyID      string
    jwkBytes   []byte // предсериализованный JSON ответа /jwks.json
}

func NewKeystore(privateKeyPEM []byte, keyID string) (*Keystore, error)
func LoadFromConfig(cfg config.Config) (*Keystore, error)

func (k *Keystore) PrivateKey() *rsa.PrivateKey
func (k *Keystore) KeyID() string
func (k *Keystore) JWKS() []byte    // кэш JSON
```

Требования:

- Загружает PEM (PKCS#1 или PKCS#8); при пароле — ошибка (шифрованные ключи не поддерживаем в MVP).
- Ключ ≥ 2048 бит — иначе ошибка.
- JWKS строится один раз в `NewKeystore`, в рантайме только отдаётся (`[]byte`).
- Формат JWKS — `{"keys":[{"kty":"RSA","use":"sig","alg":"RS256","kid":"...","n":"...","e":"..."}]}`.
- `n` и `e` — base64url без padding (RFC 7518).

### TokenService

```go
package usecase

type TokenService struct {
    keystore *jwks.Keystore
    refresh  *repository.RefreshTokenRepository
    cfg      TokenConfig  // TTL, issuer, audiences
    logger   *slog.Logger
    clock    func() time.Time
    rand     io.Reader    // crypto/rand.Reader в проде
}

type TokenConfig struct {
    Issuer          string
    AudienceUser    string
    AudienceService string
    AccessTTL       time.Duration
    RefreshTTL      time.Duration
}

func NewTokenService(ks *jwks.Keystore, refresh *repository.RefreshTokenRepository, cfg TokenConfig, logger *slog.Logger) *TokenService

// IssueForUser: выпускает access + refresh. Создаёт новую family.
// meta — user-agent и ip для аудита/refresh-записи.
func (s *TokenService) IssueForUser(ctx context.Context, user *domain.User, source string, roles []string, meta TokenMeta) (*domain.IssuedTokens, error)

// IssueForService: выпускает только access (без refresh).
func (s *TokenService) IssueForService(ctx context.Context, clientID string, scopes []string, meta TokenMeta) (*domain.IssuedTokens, error)

// Rotate: валидирует refresh (hash + не использован + не отозван + не истёк),
// выпускает новую пару с тем же family_id, помечает старый used_at.
// Если предъявлен уже used refresh — revoke всей family и вернуть domain.ErrRefreshReused.
// Если не найден/истёк/отозван — domain.ErrInvalidRefresh.
func (s *TokenService) Rotate(ctx context.Context, refreshToken string, meta TokenMeta) (*domain.IssuedTokens, *domain.User, error)

// Revoke: по opaque refresh — помечает всю family revoked.
// Если токен не найден — нет ошибки (клиент logout безопасен).
func (s *TokenService) Revoke(ctx context.Context, refreshToken string, reason string) error

type TokenMeta struct {
    UserAgent string
    IP        string
}
```

Алгоритм `IssueForUser`:

1. `now := clock()`.
2. access-claims: `iss`, `aud=[AudienceUser]`, `sub=user.Subject`, `iat`, `nbf=iat`, `exp=iat+AccessTTL`, `jti=uuid`, `src=source`, `roles`, `scope=""`, `username`, `display_name`.
3. Подпись RS256 с `kid=keystore.KeyID()`.
4. `familyID := uuid.New()`.
5. Генерация refresh: `raw := random(32 bytes)`; `token := base64url(raw)`; `hash := sha256hex(raw)`.
6. Создание записи `refresh_tokens` с `expires_at = now + RefreshTTL`.
7. Возврат `IssuedTokens{AccessToken, RefreshToken=token, ExpiresIn, RefreshExpiresIn, FamilyID}`.

Алгоритм `Rotate`:

1. `hash := sha256hex(base64url_decode(refreshToken))`.
2. `rec := refresh.FindByHash(hash)`; если `nil` → `ErrInvalidRefresh`.
3. Если `rec.RevokedAt != nil` → `ErrInvalidRefresh`.
4. Если `rec.ExpiresAt <= now` → `ErrInvalidRefresh`.
5. **Если `rec.UsedAt != nil`** → reuse detected:
   - `refresh.RevokeFamily(rec.FamilyID, now, "reuse_detected")`.
   - Возврат `ErrRefreshReused` + user (для audit).
6. `refresh.MarkUsed(rec.ID, now)`.
7. Загрузка User по `rec.UserID` (требуется `UserRepository`, но TokenService сам не тянет роли — roles приходят параметром Rotate? Нет, чище: `TokenService.Rotate` делегирует загрузку User и ролей usecase-слою через зависимость):
   - Решение: передаём в `TokenService` зависимость `UserLookup` (простой интерфейс с методами `GetByID(ctx, id)` и `GetRoles(ctx, id)`), чтобы не тянуть весь `UserRepository`. Это сохраняет TokenService узким.

```go
type UserLookup interface {
    GetByID(ctx context.Context, userID string) (*domain.User, error)
    GetRoles(ctx context.Context, userID string) ([]string, error)
    GetSourceType(ctx context.Context, sourceID int) (string, error)
}
```

В `NewTokenService` добавляем параметр `userLookup UserLookup`. Реализация — обёртка над существующими `UserRepository`/`IdentitySourceRepository`.

   - Если `user.IsActive == false` → `refresh.RevokeFamily(...)` + `ErrUserDisabled`.
8. Выпуск нового access + нового refresh (с тем же `familyID`, `ParentID = rec.ID`).
9. Создание новой записи в `refresh_tokens`.
10. Возврат `(IssuedTokens, user, nil)`.

## Constraints

- RS256 строго. Никаких HS256, ES256, EdDSA — не вводим в MVP.
- Приватный ключ живёт только в Keystore, наружу не отдаётся никогда. Ошибки не содержат PEM.
- Refresh-токен в ответе — opaque base64url, **никогда не JWT**.
- В БД — только `sha256hex(raw)`, никогда сам opaque.
- `crypto/rand.Reader` для генерации refresh и JTI. В тестах — `io.Reader` как зависимость.
- Нет reencrypt/rotation ключей в рантайме — замена ключа требует рестарта (ADR-0012).
- TokenService не знает про HTTP. Все входы — по контексту/параметрам.
- Не добавлять в этом спеке: `/login`, `/refresh`, `/logout`, `/userinfo`, `/service-token` — это 0022/0023.
- Не добавлять rate-limit и audit_log в этом спеке (0022).
- Unit-тесты должны использовать fake clock и `bytes.Reader` как `rand` для детерминированности.
- `Rotate` с неизвестным токеном возвращает `ErrInvalidRefresh` за постоянное время — без short-circuit через "`FindByHash == nil` → быстрый возврат". Достаточно: `FindByHash` всегда ходит в БД (единообразный путь); доп. dummy-verify не требуется, потому что БД-запрос уже занимает сотни мкс.

## Verify

- `cd ms-auth && go build ./... && go vet ./...` зелёное.
- Юнит-тесты:
  - `jwks/keystore_test.go`:
    - PKCS#1 PEM загружается.
    - PKCS#8 PEM загружается.
    - Ключ < 2048 бит → ошибка.
    - JWKS содержит один ключ с корректными `kid`, `n`, `e`, `alg=RS256`.
  - `jwks/handler_test.go`:
    - `GET /.well-known/jwks.json` → 200, `Content-Type: application/json`, `Cache-Control` с max-age 900, тело = keystore.JWKS().
  - `usecase/token_service_test.go` (моки RefreshTokenRepository + UserLookup, fake clock, фиксированный rand):
    - `IssueForUser` → валидный JWT (проверка подписи публичным ключом, iss/aud/sub/exp/iat/roles/src).
    - `IssueForUser` создаёт запись refresh (assert на параметры Create).
    - `IssueForService` → без refresh (`RefreshToken == ""`, `RefreshExpiresIn == 0`, `aud = controlitix-internal`).
    - `Rotate` валидного refresh → новая пара, старый помечен UsedAt.
    - `Rotate` повторно использованного → `ErrRefreshReused`, `RevokeFamily` вызван.
    - `Rotate` отозванного → `ErrInvalidRefresh`.
    - `Rotate` истёкшего → `ErrInvalidRefresh`.
    - `Rotate` неизвестного → `ErrInvalidRefresh`.
    - `Revoke` неизвестного → без ошибки.
    - Неактивный пользователь при Rotate → RevokeFamily + `ErrUserDisabled`.
- Интеграционная проверка (ручная):
  1. `openssl genrsa -out /tmp/ms-auth.pem 2048`.
  2. `MS_AUTH_JWT_PRIVATE_KEY_PATH=/tmp/ms-auth.pem` + остальные env.
  3. Запуск `ms-auth`.
  4. `curl http://localhost:8083/.well-known/jwks.json` → корректный JWKS JSON с одним ключом.
  5. В логах при старте видно `jwt keystore loaded kid=<…> key_size=2048`.
- Совместимость: `shared/authctx` (спек 0024) должен валидировать токены, выпущенные этим TokenService, с использованием только публичного JWKS-ответа.
