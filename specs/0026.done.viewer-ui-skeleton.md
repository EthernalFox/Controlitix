# 0026: viewer-ui — Каркас (зависимости, лейаут, FSD-скелет, routing)

## Scope

Каталог `viewer-ui/` — bootstrap проекта с нуля. На текущий момент в нём только `README.md`.
Не трогаем: `editor-ui/`, бэкенды, design-system артефакты в Figma.

## Context

`viewer-ui` — операторский фронтенд (просмотр опубликованных мнемосхем, realtime, тренды, тревоги). Архитектура зафиксирована:

- [docs/02_Архитектура/Микросервисы/viewer-ui.md](../docs/02_Архитектура/Микросервисы/viewer-ui.md) — стек: React 18.2, TS5, Zustand, PixiJS (canvas), Mantine UI 8, Chart.js (тренды), REST + WS к `ms-viewer`.
- [docs/06_Дизайн/Design-System.md](../docs/06_Дизайн/Design-System.md) — viewer-ui по умолчанию dark; Mantine, та же палитра тревог, AppShell.
- [docs/06_Дизайн/Design-Brief-editor-ui.md](../docs/06_Дизайн/Design-Brief-editor-ui.md) — паттерны лейаута (для понимания, как устроен брат-проект).

Эта спека закрывает каркас. Логин — спека 0027, тренды-клиент — 0028, остальные экраны (мнемосхема, тревоги, history-list) — последующие спеки.

В качестве референса по структуре кода — `editor-ui/` (FSD: `app/pages/widgets/features/entities/shared`, фасад над Mantine в `shared/ui/components/*`, типизированный `api`-клиент в `shared/api/client.ts`).

## Files

### Корень `viewer-ui/`

- `package.json` — манифест (см. § Dependencies).

- `Dockerfile` — multi-stage (node-build → nginx) аналогично editor-ui.
- `nginx.conf` — раздача SPA, fallback на `index.html`, proxy `/api` на ms-viewer и `/api/auth` на ms-auth.
- `.gitignore`, `.dockerignore` — стандарт.
- `README.md` — обновить: команды dev/build/lint, ссылка на architecture doc.

### Routing (`shared/libs/router/paths.ts`)

```ts
export const APP_PATHS = {
  LOGIN: "/login",
  DASHBOARD: "/",                       // список объектов
  DIAGRAM: (objectId: string, diagramId: string) => `/objects/${objectId}/diagrams/${diagramId}`,
  ALARMS: "/alarms",
  TRENDS: "/trends",
  TRENDS_TAG: (tagId: string) => `/trends/${tagId}`,
  NOT_FOUND: "/404",
  FORBIDDEN: "/403",
  SERVER_ERROR: "/500",
  SESSION_EXPIRED: "/session-expired",
} as const;
```

`RouterProvider` строит дерево:

- `/login` → `LoginPage` (вне AppShell, минимальный лейаут).
- `/` → `AppShellLayout` (Header + Navbar + Main):
  - `/` → `DashboardPage`
  - `/objects/:objectId/diagrams/:diagramId` → `DiagramPage`
  - `/alarms` → `AlarmsPage`
  - `/trends` → `TrendsPage`
  - `/trends/:tagId` → `TrendsPage` (с предзагруженным тегом)
- `/403`, `/404`, `/500`, `/session-expired` — отдельные минимальные лейауты.

`ProtectedRoute` — заглушка в этой спеке: возвращает children. Реальная проверка авторизации — в 0027.

### `shared/api/client.ts`

Скопировать из `editor-ui/src/shared/api/client.ts` со следующими отличиями:

1. `BASE_URL = (import.meta.env.VITE_API_URL ?? "/api").replace(/\/$/, "")` — оставить.

## Constraints

- **Никаких прямых импортов `@mantine/core`** в `pages/`, `widgets/`, `features/`. Только через `shared/ui/components`. Та же дисциплина, что в editor-ui (см. memory: «Facade pattern for UI components»).
- **FSD-импорты вниз**, не вверх: `pages` → `widgets` → `features` → `entities` → `shared`. Проверяется eslint-import (повторить конфиг editor-ui).
- **Не дублировать helpers** между editor-ui и viewer-ui — это разные приложения. Общий код будущего MVP может уехать в `shared-ui/` пакет, но в этой спеке — копируем нужные хелперы (formatTimestamp и т.п.) в `viewer-ui/src/shared/libs/helpers`.
- **`React.StrictMode`** — обязательно в `main.tsx`.
- **Не подключать chartjs-plugin-* по умолчанию глобально** в `main.tsx` — это сделает 0028 в `shared/modules/charts/setup.ts`.
- **Не реализовывать WebSocket-клиент** в этой спеке — отдельная задача (последующие спеки realtime).
- **Не подключать pixi.js глобально** — только в `pages/DiagramPage/` через ленивую загрузку (отдельная спека).
- **Сохранять формат RFC 7807** в `shared/api/types.ts` — поля `type`, `title`, `status`, `detail`, `instance`, `errors[]`. Совместимо с ms-editor и ms-auth.
- Dev-server порт — `5174`. Proxy:
  ```ts
  server: {
    port: 5174,
    proxy: {
      "/api/auth": { target: "http://localhost:8083", changeOrigin: true },
      "/api":      { target: "http://localhost:8084", changeOrigin: true },
    },
  }
  ```
- В `Dockerfile` использовать тот же multi-stage паттерн, что в `editor-ui/Dockerfile`.

## Verify

- `cd viewer-ui && npm install` — успешно ставит зависимости, нет peer-конфликтов.
- `npm run lint` — без ошибок.
- `npm run build` — собирается, в `dist/` есть `index.html` и assets.
- `npm run dev` — поднимается на `:5174`, открывается `/` (рендерит AppShell с Navbar + Header), `/login` (минимальный лейаут placeholder), `/trends`, `/alarms` — все placeholder-страницы видны.
- Переключатель темы работает: dark → light, перезагрузка сохраняет выбор (через localStorage).
- В `/` навигация по Navbar открывает `/alarms`, `/trends` без перезагрузки.
- В DevTools Network: запрос `GET /api/health` (или любой stub) уходит на прокси `http://localhost:8084/health` — подтверждает proxy. (Если ms-viewer ещё не реализован — достаточно проверить, что запрос уходит и возвращает 502/connection refused, не CORS-error.)
- Структура файлов точно соответствует § Files; в `pages/`, `widgets/`, `features/` нет ни одного импорта `@mantine/core` напрямую.
- `viewer-ui/Dockerfile` собирается локально: `docker build -t viewer-ui:test viewer-ui/` — успех.

## Review notes

В целом реализация качественная: package.json, vite-proxy на 5174, FSD-структура, AppShell-лейаут, фасад над Mantine, ESLint, токен-модуль с in-memory access token, dev-сервер поднимается чисто. Ниже — единственное замечание, требующее правки.

### 1. Прямой импорт `@mantine/core` в `RouterProvider.tsx`

Файл [`viewer-ui/src/app/providers/RouterProvider/RouterProvider.tsx`](../viewer-ui/src/app/providers/RouterProvider/RouterProvider.tsx) импортирует напрямую:

```ts
import { AppShell, Burger } from "@mantine/core";
import { useDisclosure } from "@mantine/hooks";
```

Это нарушает правило, зафиксированное в memory `feedback_facade_pattern.md` («Mantine wrappers in shared/ui/components, never import @mantine/core directly») и подтверждённое в § Constraints этой спеки.

Текущий статус остальных файлов корректный — `pages/`, `widgets/`, `features/` чисты от прямых импортов; нарушение в одном месте.

**Что исправить:**

- В `viewer-ui/src/shared/ui/components/AppShell/AppShell.tsx` уже есть реэкспорт `AppShell` из Mantine. Переиспользовать его в `RouterProvider`.
- Создать `viewer-ui/src/shared/ui/components/Burger/Burger.tsx` с реэкспортом `Burger` из `@mantine/core` и подключить через индекс.
- В `RouterProvider.tsx` заменить импорты:
  ```ts
  import { AppShell, Burger } from "@/shared/ui/components";
  ```
- Импорт `useDisclosure` из `@mantine/hooks` оставить как есть — правило facade относится к UI-компонентам (`@mantine/core`); хуки утилитарные. Если хочется унифицировать — экспортировать через `shared/libs/hooks/`, но это не блокер.

### 2. После исправлений

- `npm run lint` — проверить, что `eslint-plugin-import` не ругается на восстановленный импорт.
- `npm run dev` — убедиться, что AppShell открывается корректно (включая burger toggle на mobile/desktop).
- `grep -rn "from \"@mantine/core\"" viewer-ui/src/{pages,widgets,features,app}/` — должен возвращать только `app/providers/ThemeProvider/ThemeProvider.tsx` (MantineProvider, ColorSchemeScript — это setup-инфраструктура, корректно).
- Переименовать спеку обратно в `0026.review.viewer-ui-skeleton.md` для повторного ревью.

Замечание узкое и локальное, остальная реализация принимается как есть.
