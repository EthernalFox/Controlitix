# 0024: shared/authctx — общий Go-пакет валидации JWT + интеграция в ms-editor

## Scope

Общий пакет для валидации JWT-токенов ms-auth приёмниками (`ms-editor`, `ms-poll`, `ms-viewer`). Живёт в корне моно-репо (`shared/authctx/`), импортируется каждым сервисом.
В этом спеке: сам пакет + подключение к `ms-editor` (первый потребитель: `editor-ui` после реализации логина будет слать токен).
Подключение к `ms-poll` и `ms-viewer` — отдельные задачи, когда эти сервисы дозреют до HTTP/Kafka-consumer авторизации.

## Context

- Предыдущие спеки: [0018](0018.ready.ms-auth-skeleton.md) … [0023](0023.ready.ms-auth-admin-and-service-tokens.md).
- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md), [`docs/02_Архитектура/Безопасность.md`](../docs/02_Архитектура/Безопасность.md).

  - Получать JWKS по HTTP (`GET /.well-known/jwks.json` ms-auth), кэшировать с TTL + фоновым обновлением.

  1. Отдельный модуль `github.com/EthernalFox/Controlitix/shared/authctx` + `replace` директивы в каждом сервисе. Предпочтительно.
  2. Go workspaces (`go.work`). Избыточно на MVP.
  3. Копирование кода. Нарушает DRY и разъедется.
- Выбор: **вариант 1** — отдельный go.mod для `shared/authctx`, подключение через `replace` в `ms-editor/go.mod`, позже `ms-poll/go.mod`, `ms-viewer/go.mod`, `ms-auth/go.mod`.

## Interface

### Principal

```go
package authctx

type Principal struct {
    Subject     string   // "local:<uuid>" / "svc:<name>" / "ad:<guid>"
    Roles       []string // admin | engineer | operator | пусто (для service)
    Scopes      []string // space-split "scope" claim
    Audience    []string
    Issuer      string
    Source      string   // "local" | "ldap" | ...
    Username    string
    DisplayName string
    ClientID    string   // для service-токенов
    TokenID     string
    ExpiresAt   time.Time
}

func (p Principal) IsService() bool     // sub starts with "svc:"
func (p Principal) HasRole(role string) bool
func (p Principal) HasScope(scope string) bool

type principalContextKey struct{}

func WithPrincipal(ctx context.Context, p Principal) context.Context
func FromContext(ctx context.Context) (Principal, bool)
func MustFromContext(ctx context.Context) Principal  // panic, если нет — для кода после RequireAuth
```

### JWKS cache

```go
type JWKSCache struct {
    url    string
    ttl    time.Duration
    client *http.Client
    logger *slog.Logger

    mu       sync.RWMutex
    keys     map[string]*rsa.PublicKey // kid -> key
    fetchedAt time.Time
}

type CacheOptions struct {
    URL            string
    TTL            time.Duration // default 15m
    RequestTimeout time.Duration // default 5s
    Logger         *slog.Logger
    HTTPClient     *http.Client  // optional
}

func NewJWKSCache(opts CacheOptions) (*JWKSCache, error)

// GetKey возвращает публичный ключ по kid.
// Если kid неизвестен и кэш старше TTL — форсирует refresh.
// Если и после refresh не найден — возвращает ErrUnknownKey.
func (c *JWKSCache) GetKey(ctx context.Context, kid string) (*rsa.PublicKey, error)

// Start запускает фоновый refresh (каждые TTL/2). Возвращает функцию Stop.
func (c *JWKSCache) Start(ctx context.Context) (stop func())

// Refresh форсирует немедленное обновление.
func (c *JWKSCache) Refresh(ctx context.Context) error
```

Semantics:

- Успешный refresh атомарно заменяет map.
- При неудачном refresh **старые ключи сохраняются** (stale-OK); логируется warning.
- Если на первом старте refresh упал — `NewJWKSCache` возвращает ошибку (без ключей нельзя валидировать вообще; сервису лучше не стартовать, чем принимать все запросы без auth).
- Исключение: если `AuthDisabled=true` в конфиге сервиса — middleware пропускает все запросы (для локальной разработки / тестов; в проде не использовать). Документировать в README.

### Validator

```go
type Validator struct {
    cache         *JWKSCache
    expectedIss   string
    expectedAuds  []string   // пустой — принимаем любой; непустой — хотя бы одна должна пересечься
    clock         func() time.Time
    leeway        time.Duration // default 30s
    logger        *slog.Logger
}

type ValidatorOptions struct {
    JWKSCache      *JWKSCache
    ExpectedIssuer string
    ExpectedAudiences []string  // например, {"controlitix-api"} для ms-editor
    Leeway         time.Duration
    Clock          func() time.Time
    Logger         *slog.Logger
}

func NewValidator(opts ValidatorOptions) *Validator

// Parse валидирует токен и возвращает Principal.
// Проверяет: подпись через JWKS, alg=RS256, iss, aud, exp, nbf (с leeway).
// Возвращает:
//   nil, ErrTokenExpired
//   nil, ErrTokenMalformed
//   nil, ErrInvalidSignature
//   nil, ErrInvalidIssuer / ErrInvalidAudience
//   nil, ErrUnknownKey
//   *Principal, nil — при успехе
func (v *Validator) Parse(ctx context.Context, tokenString string) (*Principal, error)
```

### Errors

```go
var (
    ErrMissingAuth       = errors.New("missing authorization header")
    ErrTokenMalformed    = errors.New("token malformed")
    ErrInvalidSignature  = errors.New("invalid signature")
    ErrInvalidIssuer     = errors.New("invalid issuer")
    ErrInvalidAudience   = errors.New("invalid audience")
    ErrTokenExpired      = errors.New("token expired")
    ErrTokenNotYetValid  = errors.New("token not yet valid")
    ErrUnknownKey        = errors.New("unknown signing key")
    ErrForbidden         = errors.New("forbidden")
)
```

### Middleware

```go
// RequireAuth извлекает Authorization: Bearer <jwt>, валидирует, кладёт Principal в контекст.
// Ошибки → 401 RFC 7807 (/errors/auth/invalid-token|token-expired|…).
func RequireAuth(v *Validator) func(http.Handler) http.Handler

// RequireRole должен идти ПОСЛЕ RequireAuth. Пропускает, если Principal.Roles содержит хотя бы одну из roles.
func RequireRole(roles ...string) func(http.Handler) http.Handler

// RequireScope пропускает, если Principal.Scopes содержит ВСЕ требуемые scopes (AND).
// Для service-to-service интеграций (ms-poll -> ms-editor: scope "config.read" и т.п.).
func RequireScope(scopes ...string) func(http.Handler) http.Handler

// RequireAudience — дополнительная фильтрация (например, запретить service-токены на пользовательских ручках).
func RequireAudience(audiences ...string) func(http.Handler) http.Handler

// WriteProblem — helper (копия RFC 7807 генерации, как в ms-editor/ms-auth).
```

**Важно:** middleware пишет `application/problem+json`; тип URI `/errors/auth/...`. Это даёт единый формат ошибок во всех сервисах.

### Dev-bypass

В ValidatorOptions предусмотреть поле `Disabled bool`. Если true — `Parse` возвращает фиктивный Principal `{Subject:"dev:anonymous", Roles:["admin"]}` и не валидирует ничего. Используется только если сервис запущен с `MS_*_AUTH_DISABLED=true`. В RequireAuth логируется warning при старте (один раз), что auth отключён.

### Интеграция в ms-editor

Config:

```go
type Config struct {
    // ...
    AuthJWKSURL  string // MS_EDITOR_AUTH_JWKS_URL, например http://ms-auth:8083/.well-known/jwks.json
    AuthIssuer   string // MS_EDITOR_AUTH_ISSUER, default "controlitix-auth"
    AuthAudience string // MS_EDITOR_AUTH_AUDIENCE, default "controlitix-api"
    AuthDisabled bool   // MS_EDITOR_AUTH_DISABLED, default false
}
```

main.go (dep injection):

```go
var validator *authctx.Validator
if cfg.AuthDisabled {
    validator = authctx.NewValidator(authctx.ValidatorOptions{Disabled: true, Logger: logger})
    logger.Warn("authentication disabled — do not use in production")
} else {
    cache, err := authctx.NewJWKSCache(authctx.CacheOptions{URL: cfg.AuthJWKSURL, Logger: logger})
    if err != nil { return err }
    stop := cache.Start(ctx)
    defer stop()
    validator = authctx.NewValidator(authctx.ValidatorOptions{
        JWKSCache: cache,
        ExpectedIssuer: cfg.AuthIssuer,
        ExpectedAudiences: []string{cfg.AuthAudience},
        Logger: logger,
    })
}
```

Router в ms-editor:

```go
r := chi.NewRouter()
r.Use(httpapi.RequestID, httpapi.AccessLog(logger))
r.Get("/healthz", healthHandler)
r.Get("/readyz",  readyHandler)

r.Route("/api/editor", func(r chi.Router) {
    r.Use(authctx.RequireAuth(validator))
    // Мутации — engineer или admin; чтение — любая роль.
    r.Group(func(r chi.Router) {
        r.Use(authctx.RequireRole("engineer", "admin"))
        r.Post("/objects", ...)
        r.Patch("/objects/{id}", ...)
        r.Delete("/objects/{id}", ...)
        // ... все POST/PATCH/DELETE
    })
    r.Get("/objects", ...)
    r.Get("/objects/{id}", ...)
    // ... все GET
})
```

Nginx должен пробрасывать `Authorization` и `Cookie` заголовки как есть (ADR-0006 не против; если где-то в nginx есть `proxy_set_header Authorization ...` — проверить).

## Constraints

- `shared/authctx` НЕ импортирует `ms-auth` и не дёргает другие его эндпоинты, кроме JWKS. Токен нигде не отправляется в ms-auth на валидацию — всё локально.
- Никаких token introspection endpoint'ов (RFC 7662) в MVP.
- Поддерживаем ТОЛЬКО RS256. Попытка валидировать токен с `alg != "RS256"` → `ErrInvalidSignature`. Это защита от алг-confusion.
- Никакого кэширования `Principal` (сам access короткий — 15 мин, в кэше нет смысла).
- Кэш JWKS — в памяти, без shared store. При множественных инстансах сервиса каждый держит свой.
- При `AuthDisabled=true` — явный warning в логи; этот режим не должен быть дефолтом в docker-compose.
- Тесты должны включать атаку алг-confusion (пытаемся подписать токен HS256 "секретом" = публичный ключ и ожидаем `ErrInvalidSignature`).
- `RequireRole` в ms-editor: GET endpoint-ы требуют только аутентификацию (любая роль). Мутации — engineer или admin. Operator в MVP не взаимодействует с ms-editor.
- Нельзя захардкодить список endpoint-ов в middleware — использовать chi-группы.
- Не добавлять интеграцию в `ms-poll` / `ms-viewer` в этом спеке: у них пока нет HTTP endpoint-ов, требующих авторизации, и вопрос service-to-service (ms-poll читает Kafka, валидирует ли он JWT? — нет, он Kafka-consumer). Единственное место для authctx в ms-poll — будущий debug-endpoint; сделаем отдельной задачей.
- Модуль `shared/authctx` должен остаться **без импортов** из `ms-auth` / `ms-editor` / `ms-poll` / `ms-viewer`. Проверять `go list -m all`.
- `replace` в ms-editor/go.mod использует относительный путь `../shared/authctx` — договорённость для моно-репо без версионирования.
