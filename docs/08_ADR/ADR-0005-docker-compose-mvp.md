# ADR-0005: Docker Compose как способ развёртывания MVP

- Статус: accepted
- Дата: 2026-04-15
- Авторы: команда Controlitix

## Контекст

Целевая инсталляция MVP — один физический хост на объект мониторинга. Для первого заказчика это два хоста (по одному на ЦОД), всего две независимые инсталляции. Масштаб — ~250 устройств и ~2 500 тегов на инсталляцию. Команда небольшая, приоритет — скорость запуска и простота обслуживания.

## Рассмотренные варианты

1. **Docker Compose** — единый YAML, встроено в Docker Engine, команде знакомо, операция тривиальная.
2. **Kubernetes (k3s/k0s)** — промышленный оркестратор, но для одного хоста избыточен; добавляет слой сложности (манифесты, Helm, секреты, ingress), которую в MVP некому обслуживать.
3. **systemd + ручная установка бинарей** — минимум зависимостей, но ручное управление версиями, логами, рестартами и миграциями.
4. **Nomad** — компромисс по сложности, но дополнительный стек без команды, которая его знает.

## Решение

MVP разворачивается через **Docker Compose**. Один файл `docker-compose.yml` поднимает весь стек:

- `nginx` — единая точка входа (gateway).
- `ms-editor`, `ms-poll`, `ms-viewer`, `ms-auth` — backend-сервисы.
- `editor-ui`, `viewer-ui` — статические бандлы, раздаются nginx.
- `postgres` — PostgreSQL + TimescaleDB extension.
- `redis` — кэш и локальный pub/sub.
- `kafka` + `zookeeper` (или KRaft-режим) — шина событий.

Конфигурация — через `.env` (секреты, ТУЗ, токены Telegram, параметры подключения к устройствам).

## Последствия

**Позитивно:**

- Один хост — одна команда `docker compose up -d`.
- Обновление: `git pull && docker compose pull && docker compose up -d`.
- Простой backup через volume snapshot + `pg_dump`.
- Не нужен DevOps-инженер на инсталляцию.

**Негативно:**

- Нет автоматического failover между нодами (приемлемо: мониторинг дублируется у заказчика, см. НФТ).
- Нет rolling update без простоя (приемлемо: окна обслуживания допустимы).
- Масштабирование по нагрузке только вертикальное.
- При переезде в SaaS/облако потребуется переписать deployment на Kubernetes.
