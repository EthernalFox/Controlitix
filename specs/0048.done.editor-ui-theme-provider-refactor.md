# 0048: editor-ui — ThemeProvider Refactor (single MantineProvider)

## Scope

`editor-ui/src/app/providers/ThemeProvider/`  
`editor-ui/src/shared/libs/theme/index.ts`

## Context

Текущий `ThemeProvider.tsx` использует **два вложенных `MantineProvider`**: внешний управляет цветовой схемой через `localStorageColorSchemeManager`, внутренний задаёт тему (`themeOverrides.light/dark`). Это анти-паттерн: Mantine 8 поддерживает объединённый `MantineProvider` с `theme`, `cssVariablesResolver`, `defaultColorScheme` и `colorSchemeManager` в одном компоненте.

Дополнительная проблема: `document.body.dataset.theme = "light"/"dark"` выставляется вручную (для `[data-theme]`-селекторов в `tokens.css`). После спеки 0047 `tokens.css` упразднён; Mantine сам ставит `[data-mantine-color-scheme]` на корневой элемент.

Зависимость: **выполнять после** спеки 0047 (должны присутствовать единый `theme` и `cssVariablesResolver`).

Документация: `docs/06_Дизайн/Design-System.md` (раздел «Конфигурация темы»).

## Files

- `editor-ui/src/app/providers/ThemeProvider/ThemeProvider.tsx` — полная замена реализации
- `editor-ui/src/shared/libs/theme/index.ts` — добавить экспорт `cssVariablesResolver`; убрать экспорт `themeOverrides` (если ничего не импортирует)
- `editor-ui/index.html` — убрать инлайн-скрипт `document.body.dataset.theme`; сохранить только `controlitix-theme`-чтение для начального цвета схемы (если нужен `defaultColorScheme` prop)

## Interface

### Новый `ThemeProvider.tsx`

```tsx
import { MantineProvider, localStorageColorSchemeManager } from "@mantine/core";
import "@mantine/core/styles.css";
import { theme, cssVariablesResolver } from "@shared/libs/theme";

const colorSchemeManager = localStorageColorSchemeManager({
  key: "controlitix-theme",
});

interface ThemeProviderProps {
  children: React.ReactNode;
}

export function ThemeProvider({ children }: ThemeProviderProps) {
  return (
    <MantineProvider
      theme={theme}
      cssVariablesResolver={cssVariablesResolver}
      defaultColorScheme="light"
      colorSchemeManager={colorSchemeManager}
    >
      {children}
    </MantineProvider>
  );
}
```

### Обновлённый `index.ts` (shared/libs/theme)

```typescript
export { theme, cssVariablesResolver, defaultColorScheme } from "./theme";
export { THEME_PALETTE } from "./constants";
export type { ThemeColors } from "./types";
```

### Обновлённый `index.html`

Удалить блок:
```html
<script>
  // theme pre-load script that sets document.body.dataset.theme
  ...
</script>
```

Mantine 8 самостоятельно предотвращает вспышку несинхронизированной темы через свой механизм `colorSchemeManager`. Если вспышка остаётся проблемой — добавить только:
```html
<script>
  const s = localStorage.getItem("controlitix-theme");
  if (s === "dark") document.documentElement.setAttribute("data-mantine-color-scheme", "dark");
</script>
```

## Constraints

- Ключ localStorage `"controlitix-theme"` не меняется — иначе пользователи потеряют сохранённый выбор темы.
- `defaultColorScheme="light"` — строго; editor-ui всегда начинает со светлой темы.
- Не добавлять никаких `useEffect` для ручного выставления атрибутов на `document.body` — это теперь задача Mantine.
- `useMantineColorScheme()` хук должен работать во всех дочерних компонентах без изменений.
- Не трогать `useColorScheme` в Header или других местах — они продолжат работать через Mantine context.
- Удалить `themeOverrides` из экспортов только если ни один файл не импортирует его напрямую (проверить через `grep -r "themeOverrides" src/`).

## Verify

```bash
cd editor-ui
npx tsc --noEmit
grep -r "themeOverrides" src/     # 0 совпадений (либо оставить если есть импортёры — задокументировать)
grep -r "data-theme" src/         # 0 совпадений
grep -r "dataset.theme" src/      # 0 совпадений
```

Ручная проверка:
1. Открыть DevTools → Elements.
2. `<html>` (или Mantine root) имеет атрибут `data-mantine-color-scheme="light"`.
3. Переключить тему через UI → атрибут меняется на `"dark"`, CSS-переменные `--ctrx-bg-base` пересчитываются.
4. Перезагрузить страницу → тема восстанавливается из localStorage без вспышки.
5. `npm run build` проходит без ошибок.
