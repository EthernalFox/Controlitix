# 0003: ms-editor — Device CRUD + Kafka config.changed

## Scope

`ms-editor/internal/` — domain, usecase, api/http, infrastructure. Also `ms-editor/cmd/ms-editor/main.go` and `ms-editor/internal/config/config.go`.

## Context

Devices are the second-level entity in the hierarchy (Object → Device → Tag). This task implements full CRUD for devices and device_params, read-only endpoint for the device_type reference, and sets up Kafka event publishing infrastructure that will be reused by subsequent specs.

Prerequisite: spec 0002 (migration applied).

Related: `docs/03_Модель-данных/devices/`, `docs/04_API/ms-editor.md`.

```go
type DeviceType struct {
    ID   int

type Device struct {
    ID          string

    TypeID      int

    Name        string
    Description *string

    DeviceID  string
    Settings  json.RawMessage

    UpdatedAt time.Time

type DeviceWithParams struct {
    Device Device
    Params *DeviceParams       // nil if no params row exists yet
}

type DeviceUpdate struct {
    ObjectID    **string         // pointer-to-pointer: nil=don't touch, *nil=set null, *val=set value
    TypeID      *int
    Name        *string
    Description *string
}
```

Methods:
- `CreateDevice(ctx, objectID *string, typeID int, name string, description *string, settings json.RawMessage) (DeviceWithParams, error)` — creates device + params in transaction, publishes `config.changed`.
- `GetDevice(ctx, deviceID string) (DeviceWithParams, error)`
- `UpdateDevice(ctx, deviceID string, update DeviceUpdate) (Device, error)` — publishes `config.changed`.
- `DeleteDevice(ctx, deviceID string) error` — soft delete, publishes `config.changed`.
- `ListDevicesByObject(ctx, objectID string) ([]Device, error)`
- `AssignDeviceToObject(ctx, deviceID string, objectID *string) (Device, error)` — set or clear object_id, publishes `config.changed`.
- `UpdateDeviceParams(ctx, deviceID string, settings json.RawMessage) (DeviceParams, error)` — publishes `config.changed`.
- `ListDeviceTypes(ctx) ([]DeviceType, error)`

## Device settings JSONB reference

These are the expected shapes for `devices_params.settings` per device type. Validation is deferred to spec 0007 — here we only store.

**modbus_rtu:**
```json
{
  "serial_port": "/dev/ttyUSB0",
  "baud_rate": 9600,
  "data_bits": 8,
  "parity": "none",
  "stop_bits": 1,
  "slave_id": 1,
  "timeout_ms": 1000
}
```

**modbus_tcp:**
```json
{
  "host": "192.168.1.100",
  "port": 502,
  "slave_id": 1,
  "timeout_ms": 1000
}
```

**snmp_v1 / snmp_v2c:**
```json
{
  "host": "192.168.1.100",
  "port": 161,
  "community": "public",
  "timeout_ms": 1000,
  "retry_count": 3
}
```

**snmp_v3:**
```json
{
  "host": "192.168.1.100",
  "port": 161,
  "security_name": "user",
  "security_level": "authPriv",
  "auth_protocol": "SHA",
  "auth_password": "secret",
  "priv_protocol": "AES",
  "priv_password": "secret",
  "timeout_ms": 1000,
  "retry_count": 3
}
```

## Constraints

- Follow existing code patterns (naming, error handling, JSON decode via `decodeJSONBody`).
- Device soft delete: set `deleted_at = now()`. Do NOT physically delete rows.
- `DeleteDevice` must NOT cascade to tags here — that is spec 0006.
- All repository methods must exclude soft-deleted records (`WHERE deleted_at IS NULL`) in reads.
- `ListDevicesByObject` must accept only non-empty `objectID`.
- `CreateDevice` via `POST /objects/{id}/devices`: `object_id` comes from path, not body.
- `CreateDevice` via `POST /devices`: `object_id` comes from body (may be null).
- Structured logging with `slog`: include `"method"`, `"device_id"`, `"object_id"` in log fields.
- Do not add validation of settings JSONB in this spec — just store the raw JSON.
- Kafka publish failures must be logged but NOT fail the HTTP request.

## Verify

- `go build ./...` passes.
- `POST /objects/{objectID}/devices` creates a device and returns it with `type_name`.
- `GET /devices/{id}` returns device with `settings` from `devices_params`.
- `PATCH /devices/{id}` updates fields, returns updated device.
- `DELETE /devices/{id}` soft-deletes (subsequent GET returns 404).
- `POST /devices/{id}/config` upserts settings.
- `PATCH /devices/{id}/assign` with `{"object_id": null}` unassigns device.
- `GET /device-types` returns 5 types.
- Kafka topic `config.changed` receives events on create/update/delete (verify with `kafka-console-consumer` or check logs if Kafka is not running).
