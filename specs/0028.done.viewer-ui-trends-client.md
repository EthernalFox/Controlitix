# 0028: viewer-ui — Trends client (Chart.js + REST к ms-viewer)

## Scope

`viewer-ui/src/`:
- `pages/TrendsPage/` — экран `/trends` и `/trends/:tagId`.
- `widgets/TrendChart/`, `widgets/TrendTagPicker/`, `widgets/TrendRangePicker/`, `widgets/TrendLegend/`.
- `features/trends/` — store, селекторы, REST-клиент.
- `shared/modules/charts/` — singleton-инициализация Chart.js (scales, controllers, plugins).

Бэкенд (`ms-viewer`): эта спека **фиксирует требуемый контракт** REST-эндпоинтов трендов, но **не реализует** их в Go. Реализация ms-viewer — отдельная спека (0029+). Для разработки и тестов — мок (см. § Constraints).

## Context

Архитектура [docs/02_Архитектура/Микросервисы/viewer-ui.md](../docs/02_Архитектура/Микросервисы/viewer-ui.md): viewer-ui использует **Chart.js** для трендов; данные забирает REST из `ms-viewer`. История хранится в TimescaleDB ([docs/02_Архитектура/Хранилища/PostgreSQL.md](../docs/02_Архитектура/Хранилища/PostgreSQL.md) § «История значений»):

- `history.tag_values_raw` — hypertable, retention 30d.
- `history.tag_values_1m` — continuous aggregate (1-минутные `min/max/avg/count/last`), retention 365d.
- Маршрутизация: окно ≤ 24ч → raw, > 24ч → `_1m`.

Маршрутизация — задача backend; клиент просит данные за период и получает уже корректно агрегированный набор. Клиент не должен знать про raw/aggregated — он работает с единым форматом и опционально шлёт `step` (желаемый интервал точек).

Цвета и состояния — из [Design-System.md](../docs/06_Дизайн/Design-System.md) § «Цветовая семантика тревог».

Каркас и API-клиент уже готовы (0026); auth работает (0027).

## Interface

### Требуемый контракт ms-viewer (REST)

> Эта секция — публичный контракт, на который завязывается клиент. Backend-спека реализует его 1-в-1 в `docs/04_API/ms-viewer.md` и в коде ms-viewer.

**`GET /api/trends/{tagId}`**

Параметры:
| Имя | Тип | Описание |
|---|---|---|
| `from` | RFC3339 timestamp | начало окна, обязательно |
| `to`   | RFC3339 timestamp | конец окна, обязательно (по умолчанию на сервере: now) |
| `step` | duration string (`5s`, `1m`, `1h`) | желаемый интервал точек; сервер может округлить или проигнорировать |
| `agg`  | enum `last\|avg\|min\|max` | агрегатор для downsampling (default `avg`) |
| `limit`| int (≤ 5000) | max точек в ответе (default 1000) |

Ответ 200:
```json
{
  "tag_id": "uuid",
  "tag_name": "boiler_1.t_out",
  "device_id": "uuid",
  "device_name": "Boiler-1",
  "unit": { "id": 7, "name": "°C", "symbol": "°C", "category": "temperature" },
  "data_type": { "id": 2, "name": "float32" },
  "from": "2026-04-25T10:00:00Z",
  "to":   "2026-04-25T11:00:00Z",
  "step": "10s",
  "agg":  "avg",
  "source": "raw",            // "raw" | "agg_1m" — диагностика
  "points": [
    { "ts": "2026-04-25T10:00:00Z", "v": 75.2, "q": "ok" },
    { "ts": "2026-04-25T10:00:10Z", "v": 75.4, "q": "ok" },
    { "ts": "2026-04-25T10:00:20Z", "v": null, "q": "comm_loss" }
  ]
}
```

Поле `q` — quality, одно из: `ok | hi | hihi | uncertain | bad | comm_loss | offline | acknowledged`. `v == null` допустимо (например, при `comm_loss`).

**`GET /api/trends`** — батч-вариант:

Параметры:
- `tag_ids` — comma-separated UUIDs (≤ 10).
- остальные — те же, что выше.

Ответ 200: `{ "series": [<тот же объект, что выше>, ...] }`.

Ошибки (RFC 7807, относительные URI):
- `400 /errors/trends/invalid-range` — `from >= to`, `to - from > 90d`, `limit > 5000`.
- `404 /errors/trends/tag-not-found`.
- `403 /errors/trends/forbidden` — пользователь без доступа к объекту, которому принадлежит тег.

### Internal types

```ts
// shared/modules/charts/types.ts
export type Quality =
  | "ok" | "hi" | "hihi" | "uncertain"
  | "bad" | "comm_loss" | "offline" | "acknowledged";

export interface TrendPoint {
  ts: string;            // RFC3339, как пришло
  v: number | null;
  q: Quality;
}

export interface TrendSeries {
  tagId: string;
  tagName: string;
  deviceId: string;
  deviceName: string;
  unit: { id: number; name: string; symbol: string; category: string };
  dataType: { id: number; name: string };
  from: string;
  to: string;
  step: string;
  agg: "last" | "avg" | "min" | "max";
  source: "raw" | "agg_1m";
  points: TrendPoint[];
}
```

### `trendsApi.ts`

```ts
import { api } from "@/shared/api";
import type { TrendSeries } from "@/shared/modules/charts/types";

export interface FetchTrendParams {
  from: string;          // ISO
  to: string;            // ISO
  step?: string;         // "10s" | "1m" | ...
  agg?: "last" | "avg" | "min" | "max";
  limit?: number;
}

export const fetchTrend = (tagId: string, params: FetchTrendParams) =>
  api.get<TrendSeries>(`/trends/${tagId}`, params as Record<string, string | number>);

export const fetchTrendsBatch = (tagIds: string[], params: FetchTrendParams) =>
  api.get<{ series: TrendSeries[] }>("/trends", {
    ...params,
    tag_ids: tagIds.join(","),
  });
```

### `trendsStore.ts` (Zustand)

```ts
type RangePresetKey = "5m" | "1h" | "6h" | "24h" | "7d" | "30d" | "custom";

interface TrendsState {
  selectedTagIds: string[];                          // ≤ 6
  range:
    | { kind: "preset"; preset: RangePresetKey }
    | { kind: "custom"; from: string; to: string };
  step?: string;                                     // override; default = derived from range
  seriesByTag: Record<string, TrendSeries | undefined>;
  loadingByTag: Record<string, boolean>;
  errorByTag: Record<string, string | undefined>;    // problem.title

  addTag(tagId: string): void;
  removeTag(tagId: string): void;
  setRange(range: TrendsState["range"]): void;
  refresh(): Promise<void>;     // перезагрузить все selectedTagIds одним батч-запросом
  reload(tagId: string): Promise<void>;
}
```

`refresh` пакует тегам в один `fetchTrendsBatch`; на ошибку **per-tag** (если бэкенд вернул не общий 4xx, а элемент с пустыми `points`) — заполняет `errorByTag`. Общий 4xx — заполняет `errorByTag` для всех селектированных.

### Range presets

| Ключ | Окно | Default `step` | Notes |
|---|---|---|---|
| `5m`  | last 5 минут | `1s`  | raw |
| `1h`  | last 1 час   | `5s`  | raw |
| `6h`  | last 6 часов | `30s` | raw |
| `24h` | last 24 часа | `1m`  | raw / границу решает сервер |
| `7d`  | last 7 дней  | `5m`  | agg_1m |
| `30d` | last 30 дней | `30m` | agg_1m |
| `custom` | пользовательский | производный (≈ `(to-from)/300`) |

Лимит: `to - from ≤ 90 дней`. Иначе UI показывает ошибку до отправки запроса.

### `TrendChart` — Chart.js конфиг

- Тип: `Line`.
- X-axis: `type: "time"` через `chartjs-adapter-dayjs-4`. `time.unit` подбирается по диапазону (см. `time.minUnit`).
- Y-axis: `type: "linear"`. Если выбран один тег — заголовок оси = `tagName (unit.symbol)`. Если несколько — заголовок «Value», в подписях точек/легенде — единица каждого.
- Decimation: `decimation: { enabled: true, algorithm: "lttb", samples: 500 }`.
- Zoom & pan: `chartjs-plugin-zoom` — wheel zoom по X, drag pan, double-click — reset.
- Tooltip: ts (формат `DD.MM.YYYY HH:mm:ss`), значение моноширинно, badge quality.
- Цвет серии — фиксированная палитра из 6 цветов (циклически), не из `alarm-*` токенов.
- При `v === null` — разрыв линии (`spanGaps: false`).
- Theme: data colors берутся из `mantineTheme.colors` через CSS-vars (получать на mount `useMantineColorScheme`).
- Container: 100% ширина, высота 360px, при `vh > 900` — 480px.

### Поведение страницы

1. На mount: `setup()` Chart.js (один раз, через `useEffect` + ref-флаг).
2. Если `:tagId` в URL — добавить его в `selectedTagIds` и вызвать `refresh()`.
3. Изменение `selectedTagIds` или `range` → debounce 200ms → `refresh()`.
4. Ошибки per-tag показывает `TrendLegend` (иконка warning + tooltip с `errorByTag[id]`).
5. Авто-обновление: если `range.preset` ∈ {5m, 1h, 6h} — каждые 15s `refresh()` без debounce. На остальных пресетах — нет.

## Constraints

- **Не подключать realtime через WebSocket** в этой спеке — тренды, обновляющиеся «вживую», — отдельная задача (вероятно через подписку на `tags.values` для отображаемых тегов и склейку с историческим хвостом). MVP: простой polling (15s) для коротких пресетов.
- **`Chart.register` — ровно один раз** за время жизни приложения. Несколько вызовов из разных компонентов запрещены — централизуем в `shared/modules/charts/setup.ts` + флаг `isRegistered`.
- **Не использовать `chartjs-2` через свои собственные ref-манипуляции** — данные/опции через props, обновление через `data` prop (Chart.js сам diff’ит).
- **Дата/время** — только через `dayjs` с UTC-плагином. Все timestamps в API — UTC; пользователю показываем в локальной таймзоне.
- **Лимит точек на серию в графике — 500** (LTTB). Если сервер вернул больше — клиент дополнительно прорежает; сервер всё равно должен ограничивать (`limit ≤ 5000`).
- **Selected tags ≤ 6** — техническое ограничение (≤10 в API; UX-выбор — 6, чтобы легенда читалась).
- **Custom range** — валидация на клиенте: `from < to`, `to ≤ now + 1m` (защита от часов в будущем), `to - from ≤ 90d`. Сервер делает свою валидацию; клиент не дублирует, но превентивно блокирует submit.
- **Mock-режим** для разработки до готовности ms-viewer:
  - Если `import.meta.env.VITE_TRENDS_MOCK === "true"` — `trendsApi` возвращает синтетический сигнал (sin + noise) с правильным форматом.
  - Включается только в dev. В production-сборке игнорируется.
- **Не подключать pixi/konva** на этой странице.
- **Без прямых импортов `@mantine/core`** — только через `shared/ui/components` (см. memory: facade pattern).
- **Тексты/локализация** — русский (см. docs convention).
- Список тегов для `TrendTagPicker` — отдельный эндпоинт `GET /api/tags?search=...&limit=20` (контракт совпадает с ms-editor; в ms-viewer этот эндпоинт должен проксироваться или дублироваться). На время mock — отдавать стат. набор из 20 тегов.
- При смене темы (light↔dark) — график должен перестроить цвета без F5: `useEffect([colorScheme])` пересобирает `options`.

## Verify

- `npm run build` и `npm run lint` — без ошибок.
- На `/trends` без выбранных тегов — пустой холст с подсказкой «Выберите тег слева, чтобы построить график».
- Выбор одного тега + preset `1h` → улетает один `GET /api/trends/<id>?from=...&to=...&step=5s` (или `/api/trends?tag_ids=<id>` — в зависимости от реализации `refresh`); при mock — рисуется синусоида.
- Добавление 6-го тега работает; добавление 7-го — кнопка disabled, tooltip «Не более 6 тегов одновременно».
- Переключение пресета `1h → 7d` → новый запрос с `step≈5m`; в DevTools видно, что окно действительно изменилось.
- Custom range `from > to` — submit заблокирован, сообщение «Начало позже конца».
- Custom range `to - from > 90d` — submit заблокирован, сообщение «Период не может превышать 90 дней».
- На preset `5m` — авто-обновление каждые 15s (видно в Network); на `7d` — нет.
- Удаление тега из легенды → серия исчезает с графика, в store нет записи в `seriesByTag[tagId]`.
- Hover по линии → tooltip показывает время в локальной TZ, значение моноширинно, бейдж quality (например, OK / Comm Loss / Bad).
- Имитировать `q: "comm_loss"` с `v: null` — на графике разрыв; в tooltip подсвечен.
- Прогон сценария «401 на /trends → refresh → retry» — единый `refresh` из 0027, тренд не теряется.
- Переключение темы — линии и оси перекрашиваются мгновенно, без F5.
- При `VITE_TRENDS_MOCK=true npm run dev` — данные есть без бэкенда; при `VITE_TRENDS_MOCK=false` и недоступном ms-viewer — на странице показывается сообщение «Не удалось загрузить тренд» по каждому тегу, без бесконечного спиннера.
- Размер бандла страницы `/trends` (chunk) — `chart.js` выделен в отдельный chunk через динамический импорт `pages/TrendsPage/index.tsx`. Проверка через `vite build --report` или анализ `dist/assets`.
