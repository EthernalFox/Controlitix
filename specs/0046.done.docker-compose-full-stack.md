# Spec 0046 — Docker Compose full stack

**Status:** ready  
**Goal:** одной командой `docker compose up --build` поднять все бэкенд-сервисы и БД — ms-auth, ms-editor, ms-poll, ms-viewer + PostgreSQL/TimescaleDB, Redis, Kafka, Nginx-gateway.

## Context

Сейчас `docker-compose.yml` содержит только: postgres, kafka, ms-editor (+ migrate), editor-ui, gateway.

Отсутствуют:
- **redis** — нужен ms-viewer (кэш последних значений тегов, сессии WS)
- **ms-auth** (+ migrate) — авторизация; порт `:8083`; собственный бинарник `ms-auth-migrate` (не goose)
- **ms-poll** — поллер устройств; порт `:8081`; читает схему ms-editor, своих миграций нет
- **ms-viewer** (+ migrate) — realtime/тренды/аларм; порт `:8084`; использует goose-совместимый бинарник `ms-viewer-migrate`
- **viewer-ui** — React SPA оператора; сборка аналогична editor-ui
- **gateway** — не знает о ms-auth и ms-viewer

Все Go-сервисы уже имеют `Dockerfile` в своём каталоге. viewer-ui ещё не имеет Dockerfile — нужно создать по образцу editor-ui.

## Architecture decisions

### Один PostgreSQL для всех сервисов

Используем уже существующий контейнер `postgres` (TimescaleDB). Каждый сервис получает свою **схему** внутри одной БД `controlitix`. Миграции каждого сервиса создают свою схему: `editor`, `auth`, `viewer`. ms-poll читает схему `editor` (read-only), своих миграций не имеет.

Все сервисы используют одну и ту же строку подключения (одна БД, разные схемы разруливают сами миграции):

```
postgres://controlitix:controlitix@postgres:5432/controlitix?sslmode=disable
```

### JWT private key

`MS_AUTH_JWT_PRIVATE_KEY` — PEM RS256, закодированный в base64 (single-line). В `.env.example` — placeholder. При первом запуске разработчик генерирует ключ:

```bash
openssl genrsa 2048 | base64 -w 0
```

### ms-viewer JWKS URL

ms-viewer получает публичный ключ от ms-auth через JWKS:

```
MS_VIEWER_JWKS_URL=http://ms-auth:8083/jwks
```

ms-auth должен быть healthy перед стартом ms-viewer.

### Gateway routing (ADR-0006 prefix routing)

| External path | Upstream | Strip prefix |
|---|---|---|
| `/api/auth/` | `ms-auth:8083` | `/api/auth` → `/` |
| `/api/viewer/` | `ms-viewer:8084` | `/api/viewer` → `/` |
| `/api/viewer/ws` | `ms-viewer:8084` | WebSocket upgrade |
| `/api/` | `ms-editor:8080` | `/api` → `/` |
| `/viewer/` | `viewer-ui:80` | без strip, SPA |
| `/` | `editor-ui:80` | без strip, SPA |

Nginx обрабатывает более специфичные location первыми (длиннее path = раньше).

### New: `viewer-ui/Dockerfile`

По образцу `editor-ui/Dockerfile`. viewer-ui — Vite/React проект. Создать multi-stage build:

```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
ARG VITE_API_URL=/api/viewer
ARG VITE_WS_URL=/api/viewer/ws
RUN npm run build

FROM nginx:1.27-alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

Если в `viewer-ui/` уже нет `nginx.conf` — создать аналогичный editor-ui (SPA fallback: `try_files $uri /index.html`).

### Modified: `infra/nginx/gateway.conf`

Полностью заменить содержимое файла:

```nginx
upstream ms_editor_upstream {
    server ms-editor:8080;
}

upstream ms_auth_upstream {
    server ms-auth:8083;
}

upstream ms_viewer_upstream {
    server ms-viewer:8084;
}

upstream editor_ui_upstream {
    server editor-ui:80;
}

upstream viewer_ui_upstream {
    server viewer-ui:80;
}

server {
    listen 80;
    server_name _;

    client_max_body_size 10m;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ms-auth REST API
    location /api/auth/ {
        proxy_pass http://ms_auth_upstream/;
        proxy_read_timeout 30s;
    }

    # ms-viewer WebSocket (must be before /api/viewer/ to match first)
    location /api/viewer/ws {
        proxy_pass http://ms_viewer_upstream/ws;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }

    # ms-viewer REST API
    location /api/viewer/ {
        proxy_pass http://ms_viewer_upstream/;
        proxy_read_timeout 60s;
    }

    # ms-editor REST API (strip /api prefix)
    location /api/ {
        proxy_pass http://ms_editor_upstream/;
        proxy_read_timeout 60s;
    }

    # Viewer UI SPA
    location /viewer/ {
        proxy_pass http://viewer_ui_upstream/;
    }

    # Editor UI SPA (catch-all)
    location / {
        proxy_pass http://editor_ui_upstream;
    }
}
```

## Constraints

1. **ms-auth Dockerfile** уже содержит `/app/ms-auth-migrate`. Entrypoint для migrate-контейнера — `["/app/ms-auth-migrate"]`, command `["up"]`. Никакого goose.
2. **ms-viewer Dockerfile** уже содержит `/app/ms-viewer-migrate`. Entrypoint — `["/app/ms-viewer-migrate"]`, command `["up"]`.
3. **ms-poll** — нет migrations-бинарника. Никакого migrate-контейнера для ms-poll.
4. **viewer-ui/Dockerfile** — создать с нуля. Если в `viewer-ui/` уже есть `nginx.conf` — использовать его. Если нет — создать с `try_files $uri /index.html`.
5. **Один postgres** для всех сервисов. Переменная `POSTGRES_DB=controlitix`. Все сервисы подключаются к этой одной БД; схемы разруливают миграции.
6. **Nginx location order**: более длинные prefixes (`/api/viewer/`) должны стоять выше коротких (`/api/`) — иначе nginx не дойдёт до них. Порядок в spec выше — правильный.
7. **ms-auth healthcheck** использует `wget` (есть в alpine). Endpoint `/health` — существующий (см. `ms-auth/internal/api/http/health.go`).
8. **ms-viewer** зависит от `ms-auth: service_healthy` (нужен JWKS при старте). Поэтому у ms-auth обязателен healthcheck.
9. **TELEGRAM_BOT_TOKEN** — пустое значение (`""`) допустимо; ms-viewer логирует warn и запускается без уведомителя.
10. **viewer-ui build args**: `VITE_API_URL` и `VITE_WS_URL` передаются через ARG/ENV в Dockerfile — Vite embed их в бандл на этапе сборки.

## Verify

После `docker compose up --build`:

```bash
# Все сервисы running (не exited/restarting)
docker compose ps

# Postgres принимает подключения
docker compose exec postgres pg_isready -U controlitix

# ms-auth health
curl -f http://localhost/api/auth/health

# ms-editor health  
curl -f http://localhost/api/health

# ms-viewer WS handshake (401 без токена — OK, не 502)
curl -i -H "Upgrade: websocket" -H "Connection: Upgrade" \
     http://localhost/api/viewer/ws

# editor-ui SPA
curl -sf http://localhost/ | grep -q "<title>"

# viewer-ui SPA
curl -sf http://localhost/viewer/ | grep -q "<title>"
```

Migrate-контейнеры (`ms-editor-migrate`, `ms-auth-migrate`, `ms-viewer-migrate`) должны завершиться с кодом 0:

```bash
docker compose ps --filter "status=exited" | grep migrate
# ожидаем: все три exited (0)
```
