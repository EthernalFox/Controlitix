# 0020: ms-auth — domain, IdentityProvider, LocalProvider (Argon2id)

## Scope

`ms-auth`. Доменные типы, репозитории `auth.users/identity_sources/user_roles/role_mappings`, пакет хэширования паролей (Argon2id + pepper), интерфейс `IdentityProvider` и его единственная MVP-реализация `LocalProvider`.
После этого спека — можно проверить аутентификацию в юнит-тесте, но ещё нельзя логиниться по HTTP (это спек 0022).

## Context

- Предыдущие спеки: [`0018.ready.ms-auth-skeleton.md`](0018.ready.ms-auth-skeleton.md), [`0019.ready.ms-auth-migrations-seeds.md`](0019.ready.ms-auth-migrations-seeds.md).
- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md).
- Решения: [ADR-0012](../docs/08_ADR/ADR-0012-ms-auth-pluggable-identity.md).
- Ключевая идея: **весь код после `IdentityProvider.Authenticate` одинаков** — что для LocalProvider, что для будущих LDAP/AD/Kerberos/OIDC. Поэтому оркестрацию (lookup-or-JIT, разрешение ролей) мы пишем один раз в `AuthService` и НЕ в LocalProvider.
- Argon2id-параметры — из ADR-0012: `m=64 MiB (65536)`, `t=3`, `p=2`, salt 16 байт, hash 32 байта.
- Pepper — глобальный секрет из env, добавляется к паролю перед хэшированием. Формат хранения — стандартный Argon2 encoded `$argon2id$v=19$m=...,t=...,p=...$salt$hash` (без pepper — pepper применяется "на лету" при verify).

## Interface

### Domain

```go
package domain

import "time"

type IdentitySource struct {
    ID        int
    Type      string   // local | ldap | ad | kerberos | oidc
    Name      string
    Config    map[string]any
    IsEnabled bool
}

type User struct {
    ID            string    // uuid
    Subject       string    // "local:<uuid>", "ad:<guid>", ...
    SourceID      int
    Username      string
    DisplayName   string
    Email         string
    PasswordHash  string    // "" для внешних источников
    IsActive      bool
    LastLoginAt   *time.Time
    CreatedAt     time.Time
    UpdatedAt     time.Time
}

type Role struct {
    Code        string    // admin | engineer | operator
    Name        string
    Description string
}

// Credentials — универсальная структура на вход любого IdentityProvider.
// Для password-flow используются Username/Password.
// Для SPNEGO (будущее) — Extra["spnego_ticket"] = []byte.
// Для OIDC (будущее) — Extra["oidc_code"], Extra["pkce_verifier"].
type Credentials struct {
    Username string
    Password string
    Extra    map[string]any
}

// ExternalIdentity — то, что провайдер возвращает из Authenticate.
// Это "кто аутентифицировался" до того, как мы разрешили это в нашего User.
type ExternalIdentity struct {
    Subject     string   // уникально в рамках source: "local:<uuid>", "ad:<guid>"
    Username    string
    DisplayName string
    Email       string
    Groups      []string // внешние группы для RoleMapping
    Raw         map[string]any
}

// AuthenticatedUser — результат AuthService.Authenticate.
// Всё, что нужно для выпуска токена (spec 0021).
type AuthenticatedUser struct {
    User   User
    Source IdentitySource
    Roles  []string
}
```

### Ошибки

```go
package domain

import "errors"

var (
    ErrInvalidCredentials = errors.New("invalid credentials")
    ErrUserDisabled       = errors.New("user disabled")
    ErrSourceDisabled     = errors.New("identity source disabled")
    ErrUserNotFound       = errors.New("user not found")
    ErrSourceNotFound     = errors.New("identity source not found")
    ErrUnsupportedGrant   = errors.New("unsupported grant type")
)
```

**Важно:** AuthService возвращает `ErrInvalidCredentials` и для "нет такого пользователя", и для "неверный пароль". Разные причины различаются **только в audit_log**, но не в ответе клиенту (защита от username enumeration).

### Password hasher

```go
package password

type Hasher struct {
    pepper []byte
    // Параметры зафиксированы по ADR-0012:
    // memoryKiB = 65536 (64 MiB), time = 3, threads = 2, saltLen = 16, keyLen = 32
}

func NewHasher(pepper []byte) (*Hasher, error)

// Hash формирует encoded строку формата $argon2id$v=19$m=...,t=...,p=...$salt$hash.
// Salt генерируется crypto/rand.
func (h *Hasher) Hash(password string) (string, error)

// Verify парсит encoded-строку, вычисляет хэш с тем же salt и параметрами
// (из строки), сравнивает через subtle.ConstantTimeCompare.
// Возвращает (ok, error). error != nil только при повреждённом формате.
func (h *Hasher) Verify(password, encoded string) (bool, error)
```

Требования:

- `pepper` обязателен (min 32 байта). При пустом — `NewHasher` возвращает ошибку.
- Hash: конкатенирует `password + pepper`, затем `argon2.IDKey(...)`.
- Verify читает параметры из encoded-строки (а не из поля Hasher), чтобы работало при смене параметров в будущем.
- Внутри использовать `crypto/subtle.ConstantTimeCompare`.
- Никакого логирования пароля/пеппера/хэша.

### Repository — user_repository

```go
package repository

type UserRepository struct { /* *sql.DB */ }

func NewUserRepository(db *sql.DB) *UserRepository

func (r *UserRepository) FindBySourceAndUsername(ctx context.Context, sourceID int, username string) (*domain.User, error)
func (r *UserRepository) FindBySubject(ctx context.Context, subject string) (*domain.User, error)
func (r *UserRepository) FindByID(ctx context.Context, id string) (*domain.User, error)
func (r *UserRepository) Create(ctx context.Context, u *domain.User) (*domain.User, error)
func (r *UserRepository) UpdateLastLogin(ctx context.Context, id string, at time.Time) error
func (r *UserRepository) GetRoles(ctx context.Context, userID string) ([]string, error)
func (r *UserRepository) SetRoles(ctx context.Context, userID string, roles []string, grantedBy *string) error
```

SQL:

- `FindBySourceAndUsername`: `WHERE source_id = $1 AND lower(username) = lower($2)`.
- `FindBySubject`: `WHERE subject = $1`.
- Все `Find*` возвращают `(nil, nil)` если не найдено (НЕ `sql.ErrNoRows`). Доменная ошибка `ErrUserNotFound` — задача usecase-слоя.
- `Create` — INSERT с `RETURNING id, created_at, updated_at`.
- `SetRoles` — транзакция: `DELETE FROM auth.user_roles WHERE user_id = $1`, затем `INSERT` новых.

package repository

func (r *IdentitySourceRepository) FindByID(ctx context.Context, id int) (*domain.IdentitySource, error)

### IdentityProvider

```go
package identity

type Provider interface {
    // Type возвращает значение auth.identity_sources.type ("local"/"ldap"/...).
    Type() string

    // Authenticate проверяет credentials в контексте конкретного source
    // и возвращает ExternalIdentity, если успех.
    // При неверных кредах — domain.ErrInvalidCredentials.
    Authenticate(ctx context.Context, source domain.IdentitySource, creds domain.Credentials) (*domain.ExternalIdentity, error)
}

// Registry хранит провайдеры по типу. В MVP — только "local".
type Registry struct {
    byType map[string]Provider
}

func NewRegistry(providers ...Provider) *Registry
func (r *Registry) Get(sourceType string) (Provider, bool)
```

### LocalProvider

```go
package identity

type LocalProvider struct {
    users  *repository.UserRepository
    hasher *password.Hasher
    logger *slog.Logger
}

func NewLocalProvider(users *repository.UserRepository, hasher *password.Hasher, logger *slog.Logger) *LocalProvider

func (p *LocalProvider) Type() string { return "local" }

func (p *LocalProvider) Authenticate(ctx context.Context, source domain.IdentitySource, creds domain.Credentials) (*domain.ExternalIdentity, error) {
    // 1. FindBySourceAndUsername.
    // 2. Если nil или PasswordHash == "" — ErrInvalidCredentials.
    //    (важно: не раскрываем "unknown user" отдельно).
    //    Но для constant-time: всё равно вызываем hasher.Verify на dummy-хэше,
    //    чтобы время отклика не зависело от существования пользователя.
    // 3. hasher.Verify(creds.Password, user.PasswordHash).
    //    Если false — ErrInvalidCredentials.
    // 4. Если !user.IsActive — ErrUserDisabled.
    // 5. Возврат ExternalIdentity{Subject: user.Subject, Username: user.Username,
    //    DisplayName: user.DisplayName, Email: user.Email, Groups: nil}.
}
```

**Важно:** LocalProvider не разрешает роли, не обновляет `last_login_at`. Это задача `AuthService`.

Dummy-hash для constant-time: захардкоденная строка-пример валидного Argon2id encoded из pepper + любого "impossible-to-match" пароля, сгенерированная один раз при `NewLocalProvider` в памяти. Это делает время ответа в случае "нет пользователя" близким к случаю "пользователь есть, пароль неверен".

### AuthService

```go
package usecase

type AuthService struct {
    sources   *repository.IdentitySourceRepository
    users     *repository.UserRepository
    registry  *identity.Registry
    logger    *slog.Logger
    clock     func() time.Time // тестируемость
}

func NewAuthService(
    sources *repository.IdentitySourceRepository,
    users *repository.UserRepository,
    registry *identity.Registry,
    logger *slog.Logger,
) *AuthService

// Authenticate — универсальный вход.
// sourceType пока всегда "local" (MVP). В будущем UI/API может указывать провайдер явно или через login/options.
func (s *AuthService) Authenticate(ctx context.Context, sourceType string, creds domain.Credentials) (*domain.AuthenticatedUser, error)
```

Алгоритм:

1. `source := sources.FindByType(sourceType)` — берём первую `is_enabled=true`. Если нет — `ErrSourceNotFound`. Если отключена — `ErrSourceDisabled`.
2. `provider := registry.Get(source.Type)` — если нет — `ErrSourceNotFound`.
3. `ext, err := provider.Authenticate(ctx, *source, creds)` — прокидываем ошибки как есть.
4. **Lookup or JIT-create:**
   - `u := users.FindBySubject(ext.Subject)`.
   - Если `nil` — `u = users.Create(User{Subject: ext.Subject, SourceID: source.ID, Username: ext.Username, DisplayName: ext.DisplayName, Email: ext.Email, PasswordHash: "", IsActive: true})`.
   - Для LocalProvider этот JIT не сработает в обычном потоке (пользователь УЖЕ был в БД — провайдер его нашёл), но для будущих LDAP/AD сработает на первом логине. Поэтому обязателен сейчас.
5. Если `u.IsActive == false` → `ErrUserDisabled`.
6. **Разрешение ролей:**
   - `localRoles := users.GetRoles(u.ID)`.
   - `mappedRoles := sources.ResolveRoles(source.ID, ext.Groups)` (для LocalProvider — всегда пусто).
   - Итоговый набор — дедупликация объединения. Если пусто — возвращаем `[]string{}` (пустой срез, НЕ nil). Это значит user залогинился, но прав не имеет — решение о 403 принимают приёмники.
7. `users.UpdateLastLogin(u.ID, clock())`.
8. `return &AuthenticatedUser{User: *u, Source: *source, Roles: allRoles}, nil`.

## Constraints

- Единственная MVP-реализация `Provider` — `LocalProvider`. Файлов `ldap.go`/`ad.go`/`kerberos.go`/`oidc.go` создавать НЕ нужно — чтобы не было "мёртвых" заглушек, только интерфейс и `Registry`.
- Константное время в `LocalProvider.Authenticate`: dummy-verify для несуществующих пользователей.
- Никакого bcrypt. Только Argon2id через `golang.org/x/crypto/argon2`.
- Password и pepper никогда не попадают в логи и в ошибки.
- `FindBy*` возвращают `(nil, nil)` при отсутствии. Доменные ошибки — только из usecase/provider.
- Не добавлять кэш ролей в этом спеке — in-memory кэш добавим при необходимости позже.
- Не делать JWT / HTTP / Kafka / rate-limit в этом спеке.
- Не модифицировать миграции из спека 0019.
- `SetRoles` валидирует, что все role_code ∈ {admin, engineer, operator} — иначе возвращает ошибку. Список роли — константа в `domain.AllowedRoles`.

## Verify

- `cd ms-auth && go build ./... && go vet ./...` зелёное.
- Юнит-тесты:
  - `password/argon2_test.go`:
    - `Hash` → `Verify` → true.
    - Разные пароли с тем же pepper → Verify(other) == false.
    - Разные pepper → Verify == false (Hash под другим pepper'ом).
    - Искажённая encoded-строка → Verify возвращает error.
    - `NewHasher(empty pepper)` → error.
    - Hash дважды с одним паролем даёт разные строки (разный salt).
  - `identity/local_test.go` с мок-репозиторием `UserRepository`:
    - Валидные креды → `ExternalIdentity` с правильным subject.
    - Неверный пароль → `ErrInvalidCredentials`.
    - Несуществующий пользователь → `ErrInvalidCredentials`, и время ответа в пределах ±20% от случая "неверный пароль" (проверка константного времени — достаточно одного запуска с замером; не жёсткий assert).
    - `PasswordHash == ""` → `ErrInvalidCredentials` (не crash).
    - `IsActive == false` → `ErrUserDisabled`.
  - `usecase/auth_service_test.go` с моками:
    - Успешный логин local-пользователя → возвращает AuthenticatedUser с ролями из `GetRoles`.
    - Неактивный source → `ErrSourceDisabled`.
    - Неизвестный sourceType → `ErrSourceNotFound`.
    - Успех → `UpdateLastLogin` вызван.
    - Пользователь с внешним subject (имитация будущего LDAP): если `FindBySubject` возвращает nil — срабатывает JIT-create.
- Интеграционный тест (опционально, если Codex сочтёт нужным): с testcontainers-go поднять PG, применить миграции (из 0019), seed-ить admin'а с известным паролем, вызвать `AuthService.Authenticate("local", {username:admin, password:<test>})` → успех; с неверным паролем — `ErrInvalidCredentials`.
- Ручной прогон: `go test ./...` проходит без падений.
