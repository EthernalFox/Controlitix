# Потоки данных

Ниже — ключевые сценарии прохождения данных между сервисами и хранилищами. Диаграммы на уровне компонентов — в `../Controlitix.drawio`.

## 1) Опрос устройств → нормализация → значения тегов
1. ms-poll загружает конфигурацию из PostgreSQL (`devices.*`, `tags.*`) или кэша Redis.
2. Драйверы (Modbus TCP/RTU, SNMP) выполняют чтения по расписанию (scan rate), формируют сырые показания.
3. Нормализация в составе ms-poll: применяется `tag_params` (тип данных), `tag_scaling` (min/max/factor), вычисляется `quality` (good/bad/uncertain).
4. Публикация:
   - Kafka: `ms-poll` (tag_id, value, ts, quality[, meta]) — поток текущих значений; `raw.readings` — опционально.
   - Redis: локальный pub/sub для быстрых обновлений Viewer (опционально).
5. Историзация и кэш:
   - `ms-viewer` потребляет `ms-poll`, пишет архив значений в PostgreSQL.
   - `ms-viewer` обновляет Redis с «последними значениями» для быстрых чтений/Viewer.

## 2) Изменение конфигурации (devices/tags/objects)
1. Клиент вызывает REST API `ms-editor`.
2. Сервис вносит изменения в PostgreSQL (соответствующие схемы) и эмитит событие Kafka `config.changed`.
3. Потребители (`ms-poll`, `ms-viewer`, кэши) инвалидацируют/обновляют локальное состояние и графы зависимостей.

## 3) Realtime для Viewer
1. Viewer устанавливает WebSocket к `ms-viewer`.
2. Подписка по областям (object/mimic/tag), аутентификация/авторизация по ролям.
3. Источники обновлений:
   - Kafka `tags.values` → `ms-viewer` транслирует подписчикам (fan-out, debouncing).
   - Redis pub/sub (если используется локальная доставка внутри `ms-viewer`).
4. Фоллбек: периодический REST-пуллинг для участков без WS.

## 4) Тревоги и уведомления (LoLo/LoHi/HiLo/HiHi)
1. `ms-viewer` потребляет `tags.values`.
2. Внутренний модуль тревог сопоставляет значения с `tag_setpoints`, вычисляет состояния, подавление/гистерезис, дедупликацию.
3. `ms-viewer` публикует события Kafka `alarms.events` (alarm_id, tag_id, state, ts, payload).
4. Встроенный notifier `ms-viewer` вызывает Telegram (бот/вебхук), применяет ретраи/эскалации.

## 5) Тренды и отчёты
1. `ms-viewer` потребляет `ms-poll` и пишет историю в PostgreSQL (политика retention/downsampling — TBA).
2. Viewer/отчётный сервис выполняет запросы за период через API `ms-viewer`.
3. Экспорт в CSV/PDF и планировщик отчётов — последующие этапы.

## 6) Публикация мнемосхем
1. Инженер редактирует схему в Editor (черновик), затем вызывает «публикацию».
2. ms-editor фиксирует версию в `public.*` и эмитит `config.changed`.
3. Viewer инвалидирует локальный кэш схемы и подтягивает актуальную версию.

## Темы Kafka (использование)
- `raw.readings` — сырые показания драйверов (опционально).
- `tags.values` — нормализованные значения тегов.
- `alarms.events` — жизненный цикл тревог.
- `config.changed` — изменения конфигураций (objects/devices/tags/mimic).
- `audit.logs` — действия пользователей/сервисов (опционально).
