# ms-editor — конфиг объектов, устройств и мнемосхем (MVP)

## Назначение

Управление объектами мониторинга, устройствами, тегами, мнемосхемами и фигурами. Сервис является единой точкой изменения инженерной конфигурации: через него создаются объекты, настраиваются устройства и теги, а затем эти теги используются в мнемосхемах. В MVP отсутствуют полноценная версионность и экспорт, сохраняется только актуальное состояние.

## Стек

- Go
- PostgreSQL (схемы `public`, `devices`, `tags`)
- Redis (опционально для кэша)
- Kafka (опционально для события `config.changed`)

## Интеграции

- REST API — операции CRUD для объектов, устройств, тегов, схем и фигур.
- Используется `editor-ui` как единый backend для инженерного редактирования.
- Эмитит `config.changed` при изменении конфигурации, чтобы `ms-poll`, realtime и кэши перечитывали актуальное состояние.

## Текущий статус реализации

Фактический skeleton `ms-editor` пока покрывает только:

- объекты;
- мнемосхемы;
- фигуры;
- HTTP API и Swagger для этих сущностей.

Устройства, теги, справочники и событие `config.changed` пока описаны архитектурно, но не реализованы в текущем проекте.

## Модель данных (MVP)

- **objects**: описание объекта мониторинга (ЦОД, узел и т. д.).
- **devices**: устройства объекта мониторинга с привязкой к `object_id`.
- **device_type**: словарь типов устройств и схема сериализации настроек.
- **devices_params**: JSONB-параметры протоколов и настроек подключения устройства.
- **tags**: теги, привязанные к устройству.
- **tag_params**: адрес, тип данных, единица измерения и протокольные параметры тега.
- **data_types**, **units**: справочники типов данных и единиц измерения.
- **tag_scaling**, **tag_setpoints**: масштабирование и уставки тега.
- **mimic**: мнемосхема, связанная с объектом.
- **figures**: фигуры, размещённые на схеме; имеют привязку к тегу (один `tag_id`).
- **figure_params**: JSONB-поле со свойствами Konva-фигуры (координаты, размеры, цвет, стиль и др.).

Поддерживаемые типы фигур на текущий момент синхронизированы с `editor-ui`:

- `rect`
- `circle`
- `ellipse`
- `wedge`
- `line`
- `image`
- `text`
- `ring`
- `arc`
- `tag`
- `path`

### Особенности

- Все свойства фигур (позиция, геометрия, стиль) сохраняются в JSONB (`figure_params`).
- Настройки устройств хранятся в JSONB (`devices_params.settings`) и валидируются по типу устройства.
- Привязка к тегу — одна на фигуру (поле `tag_id`).
- Один тег соответствует одному адресу устройства; составные теги — вне MVP.
- Анимация и составные условия — **вне MVP**.

## Основные функции (входит в MVP)

1. **Работа с объектами**
   - Создание/редактирование/удаление объекта.
   - Привязка устройств и мнемосхем к объекту.
2. **Работа с устройствами и тегами**
   - Создание/редактирование/удаление устройства.
   - Настройка параметров протокола через JSONB (`devices_params`).
   - Создание/редактирование/удаление тегов у выбранного устройства.
   - Настройка адреса, типа данных, единицы измерения, масштабирования и уставок тега.
   - Выдача справочников `device_type`, `data_types`, `units` для `editor-ui`.
3. **Мнемосхемы**
   - Создание/редактирование/удаление мнемосхемы.
   - Онлайн-сохранение: изменения отправляются как UPSERT (одна версия).
   - Публикация = текущее состояние (разделение на «черновик» и «публикацию» вне MVP).
   - Отправка уведомления при изменении мнемосхемы в `viewer-ui`.
4. **Фигуры**
   - Добавление/редактирование/удаление фигур.
   - Привязка к тегу (один `tag_id`).
   - Хранение свойств фигуры в JSONB.
   - Динамика (смена цвета/видимости по значению тега) задаётся через параметры фигуры (простое условие).
5. **Удаление**
   - Мягкое удаление: объекты, схемы и фигуры помечаются флагом `deleted_at`.
   - Устройства и теги в MVP удаляются физически.

## Пользовательские потоки

- **Создать устройство:** `editor-ui` открывает карточку объекта → отправляет данные устройства и протокола → `ms-editor` сохраняет в `devices`/`devices_params` → возвращает `id`.
- **Добавить тег:** `editor-ui` отправляет имя, адрес, тип данных, unit и дополнительные параметры → `ms-editor` сохраняет в `tags`/`tag_params`/`tag_scaling`/`tag_setpoints`.
- **Создать объект и схему:** создать объект → добавить мнемосхему → перейти в редактор (`editor-ui`) → добавить фигуры → сохранить изменения.
- **Редактировать фигуру:** изменить свойства фигуры (позиция, цвет) → `editor-ui` отправляет изменения → `ms-editor` сохраняет через upsert → уведомление в response.
- **Удалить фигуру:** editor-ui помечает фигуру как удалённую → ms-editor проставляет `deleted_at` → фигура скрывается из UI.

## Нефункциональные требования

- **Скорость сохранения:** операции upsert < 100 мс при типовых размерах схемы.
- **Скорость CRUD конфигурации:** создание/редактирование устройств и тегов ≤ 100 мс при типовых данных.
- **Устойчивость:** мягкое удаление позволяет использовать undo/redo.
- **Уникальность:** `device.name` уникально в пределах объекта; `tag.name` уникально в пределах устройства.
- **Масштаб:** поддержка ≥ 500 фигур на одной мнемосхеме.

## Вне MVP

- Версионность схем (черновик/публикация).
- Экспорт/импорт конфигурации в JSON.
- Множественные условия/логические теги для фигур.
- Управление анимацией фигур.
- Проверка соединения с устройством перед сохранением.
