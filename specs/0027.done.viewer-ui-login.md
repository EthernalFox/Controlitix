# 0027: viewer-ui — LoginPage + auth-store + интеграция с ms-auth

## Scope

`viewer-ui/src/`:
- `pages/LoginPage/`
- `app/providers/AuthProvider/`
- `features/auth/`
- `shared/api/` — токен-инжекция и refresh-loop
- `shared/libs/router/` — `ProtectedRoute`

Бэкенд не трогаем. Используем готовые эндпоинты ms-auth из спеки 0022 (`POST /api/auth/login`, `POST /api/auth/refresh`, `POST /api/auth/logout`, `GET /api/auth/userinfo`).

## Context

Спека 0026 поставила каркас viewer-ui с placeholder LoginPage и пустым AuthProvider. Эта спека закрывает реальный логин-флоу: форма, store, обмен токенами, перехват 401 → refresh, redirect-после-логина, logout, восстановление сессии при перезагрузке.

Контракт ms-auth — [specs/0022.wip.ms-auth-http-auth.md](0022.wip.ms-auth-http-auth.md):

- `POST /api/auth/login` — body `{ "username", "password" }` → 200 `{ access_token, token_type:"Bearer", expires_in, refresh_token, user{...} }` + `Set-Cookie: refresh_token=...; HttpOnly; Secure; SameSite=Strict; Path=/api/auth`.
- `POST /api/auth/refresh` — без тела (refresh-cookie сам летит) → 200 `{ access_token, token_type, expires_in, refresh_token }` + новый Set-Cookie.
- `POST /api/auth/logout` → 204, очищает cookie.
- `GET /api/auth/userinfo` — нужен `Authorization: Bearer` → 200 `{ subject, username, email, roles[], ... }`.

Коды ошибок (RFC 7807, относительные URI):
- `401 /errors/auth/invalid-credentials` — неверные креды.
- `401 /errors/auth/invalid-refresh` — refresh невалиден / переиспользован.
- `401 /errors/auth/invalid-token` / `/errors/auth/token-expired` — access невалиден.
- `403 /errors/auth/user-disabled` — пользователь отключён.
- `429 /errors/auth/rate-limited` — c заголовком `Retry-After`.
- `503 /errors/auth/source-disabled`.

UX-референс — `editor-ui/src/pages/LoginPage` (если будет создан раньше). На текущий момент — только дизайн-бриф [Design-Brief-editor-ui.md](../docs/06_Дизайн/Design-Brief-editor-ui.md), § 5 экран 1.

## Interface

### `authStore` (Zustand)

```ts
type AuthUser = {
  subject: string;
  username: string;
  email: string | null;
  roles: string[];
  // плюс что вернёт /userinfo
};

type AuthStatus =
  | "idle"            // первичное состояние до bootstrap
  | "authenticating"  // /login или /refresh в процессе
  | "authenticated"
  | "unauthenticated";

interface AuthState {
  status: AuthStatus;
  accessToken: string | null;
  expiresAt: number | null;     // unix ms
  user: AuthUser | null;
  lastError: string | null;     // RFC 7807 type, например "/errors/auth/invalid-credentials"

  login(username: string, password: string): Promise<void>;
  refresh(): Promise<void>;
  logout(): Promise<void>;
  bootstrap(): Promise<void>;   // вызвать на старте приложения
}
```

`accessToken` хранится **только в памяти** (не в localStorage / sessionStorage). Refresh-токен живёт в HttpOnly cookie — клиент его не читает.

### `LoginForm`

Поля:
- `username` — текст, autofocus, required.
- `password` — пароль, required.
- Кнопка «Войти» (primary).

Состояния:
- default;
- submitting (Loader в кнопке, поля disabled);
- error: показать сообщение по `lastError`:
  - `/errors/auth/invalid-credentials` → «Неверный логин или пароль».
  - `/errors/auth/user-disabled` → «Учётная запись отключена. Обратитесь к администратору».
  - `/errors/auth/rate-limited` → «Слишком много попыток. Повторите через N секунд» (показать Retry-After).
  - `/errors/auth/source-disabled` → «Сервис аутентификации недоступен. Попробуйте позже».
  - прочее → «Не удалось выполнить вход. Попробуйте ещё раз».

После успешного `login()` — `navigate(state.from ?? "/")`, заменяя историю (`replace: true`).

### Bootstrap flow (на mount AuthProvider)

```
1. status = "authenticating"
2. Попытка userinfo() с текущим accessToken (он null после холодной загрузки).
   - 200 → user, status = "authenticated".
   - 401 → перейти к refresh.
3. refresh() — без явного refresh_token, cookie летит сама.
   - 200 → setAccessToken, expiresAt; затем userinfo() снова.
   - 401/403 → status = "unauthenticated".
   - сеть упала → status = "unauthenticated", lastError = network.
```

`ProtectedRoute` ждёт переход из `idle/authenticating` в терминальное состояние (`authenticated` или `unauthenticated`). Пока ждём — рендерим полноэкранный `<Loader />` (без редиректа).

### Refresh-loop

- **Реактивный**: при 401 в API-клиенте — один параллельный `refresh()`; все одновременные запросы ждут одного и того же in-flight `refresh()` (мьютекс через одиночный promise в `tokenScheduler`).
- **Проактивный**: после `setAccessToken` запускается `setTimeout` на `expiresAt - now - 60s`. По истечении — `refresh()`. Сбрасывается на новый `setAccessToken` или `logout`.

Если `refresh()` упал — `logout()` локально (без вызова сервера, т.к. нечем), редирект `/session-expired`.

### `/session-expired`

Минимальный экран: «Сессия истекла. [Войти ещё раз]». Кнопка → `/login`. Без AppShell.

### Logout

`logout()`:
1. `POST /api/auth/logout` — игнорировать ошибку (всегда 204).
2. `clearAccessToken()`, обнулить store.
3. `navigate("/login", { replace: true })`.

### TypeScript-контракты DTO

```ts
// shared/modules/auth/types.ts
export interface LoginRequest { username: string; password: string; }

export interface LoginResponse {
  accessToken: string;
  tokenType: "Bearer";

}
```

Имена в TS — camelCase; клиент `shared/api/client.ts` уже делает snake→camel.

## Constraints

- Access-токен **только в памяти**. Не писать в localStorage/sessionStorage/IndexedDB. (Безопасность — XSS-устойчивость по политике Cookie + Memory-Token, см. 0022.)
- Refresh-токен — **никогда** не доступен JS. Только HttpOnly cookie. Если ms-auth прислал `refreshToken` в теле — игнорировать.
- При 401 не делать больше **одного** retry с refresh. Цикл `401→refresh→401→refresh…` запрещён.
- В `LoginForm` не сохранять пароль в Redux/Zustand/store. Только локальный `useState`, очищать после submit.
- Не использовать `axios` или другую HTTP-обёртку. Только `fetch` через `shared/api/client.ts`.
- `ProtectedRoute` **не мигает** контентом — пока bootstrap идёт, показывает Loader. После — редирект или контент. Никаких «увидел контент → редиректнуло».
- `AuthProvider` должен быть выше `RouterProvider` в дереве, чтобы навигация была доступна изнутри auth-логики через `useNavigate`. Альтернатива: использовать `router.navigate(...)` из `react-router` императивно, без хука.
- `redirect after login` — только на роут из `state.from` (если есть) или `/`. Не редиректить на `/login` (бесконечный цикл) или внешние URL (open-redirect).
- Не показывать в UI техническое поле `lastError` со значениями типа `/errors/auth/...` — только локализованные сообщения.
- Тексты — русский (см. язык docs).
- Запросы `/api/auth/*` — через тот же `shared/api/client.ts`, но с явным `credentials: "include"`. БЕЗ обхода refresh-loop’а: `/login` сам по себе не должен триггерить refresh при 401 (это валидный отказ, не «истёк токен»).

## Verify

- `npm run build` и `npm run lint` — без ошибок.
- Открыть `/` без сессии → редирект на `/login` после показа короткого Loader (bootstrap → unauthenticated).
- Ввести неверные креды → форма показывает «Неверный логин или пароль», без перезагрузки, без перехода.
- Ввести верные креды → редирект на `/`, в Header виден `username`, в DevTools Application → Cookies есть `refresh_token` HttpOnly Secure SameSite=Strict.
- В DevTools Application → Local/Session Storage **пусто** — токен не утекает на диск.
- F5 на `/alarms` → коротко Loader → bootstrap проходит через refresh → попадаем обратно на `/alarms`.
- Удалить cookie вручную, F5 → редирект на `/login`.
- Имитировать `accessToken` истёкший (например, через DevTools заменить значение): следующий API-запрос вызывает один `/api/auth/refresh`, обновляет токен, исходный запрос ретраится и завершается успехом. В Network видно ровно один retry.
- Принудительно отвергать `/api/auth/refresh` на бэкенде → клиент уходит на `/session-expired`, нет бесконечного цикла.
- Logout → cookie очищена, accessToken null, редирект `/login`.
- Rate-limit (429 + Retry-After: 30) → форма блокируется на 30s с сообщением «Повторите через 30 секунд», по истечении — снова можно отправить.
- Нет ни одного импорта `@mantine/core` из `pages/LoginPage` или `widgets/UserMenu` напрямую — только через `shared/ui/components`.
