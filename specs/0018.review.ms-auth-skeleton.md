# 0018: ms-auth — скелет сервиса (config, PG, slog, health, Dockerfile)

## Scope

`ms-auth` — новый Go-микросервис аутентификации и авторизации. Этот спек создаёт каркас сервиса **без какой-либо бизнес-логики**: Go-модуль, конфиг, подключение к PostgreSQL, structured logging, health endpoints, Docker Compose.
Доменные типы, JWT, репозитории, HTTP-эндпоинты, миграции — в следующих спеках (0019–0023).

## Context

- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md).
- ADR: [`ADR-0007`](../docs/08_ADR/ADR-0007-service-accounts-env-secrets.md), [`ADR-0012`](../docs/08_ADR/ADR-0012-ms-auth-pluggable-identity.md).
- Каркас копирует `ms-editor` и `ms-poll` (см. `ms-editor/cmd/ms-editor/main.go`, `ms-editor/internal/config/`, `ms-editor/internal/infrastructure/database`).
- В этом спеке **нет** Kafka, нет таблиц, нет доменных типов — только стартует пустое приложение, подключается к PG, отдаёт health-эндпоинты, корректно завершается по сигналу. Cделано ровно как `ms-poll` в спеке 0012, но без Kafka-компонент.
- Сервис НЕ должен иметь зависимости от модулей `ms-editor` / `ms-poll`.

## Files

Создать с нуля:

- `ms-auth/go.mod` — модуль `github.com/EthernalFox/Controlitix/ms-auth`, Go 1.24.4. Зависимости минимальные: `github.com/jackc/pgx/v5`, `github.com/joho/godotenv`.
- `ms-auth/go.sum` — после `go mod tidy`.
- `ms-auth/cmd/ms-auth/main.go` — entrypoint: загрузка конфига, slog, открытие БД, HTTP-сервер health-эндпоинтов, graceful shutdown по SIGINT/SIGTERM с таймаутом 10 сек.
- `ms-auth/internal/config/config.go` — структура `Config` и `LoadConfig()` (см. Interface).
- `ms-auth/internal/infrastructure/database/postgres.go` — `OpenPostgres(ctx, url)` по образцу ms-editor (через `database/sql` + pgx stdlib, `SELECT 1` при инициализации).
- `ms-auth/internal/api/http/health.go` — handler с двумя эндпоинтами: `/healthz` (liveness, всегда 200) и `/readyz` (readiness — проверяет `PingContext` БД с таймаутом 1с).
- `ms-auth/Dockerfile` — multi-stage по образцу `ms-editor/Dockerfile`. `EXPOSE 8083` (отличается от ms-editor:8080 и ms-poll:8081).
- `ms-auth/docker-compose.yml` — как у ms-poll: сервис `ms-auth`, порт `8083:8083`. Postgres определяется только для локальной разработки (если уже есть корневой compose — просто ссылаться на external network, но для самостоятельного запуска сервис должен работать).
- `ms-auth/.env.example` — список всех переменных окружения с примерами значений (см. Interface).
- `ms-auth/README.md` — описание сервиса, схема запуска `go run ./cmd/ms-auth`, переменные окружения (ссылка на `.env.example`), эндпоинты health, ссылки на архитектуру и ADR.

## Interface

### Config

```go
package config

type Config struct {
    HTTPAddress        string // :8083
    DatabaseURL        string // postgres://...
    LogLevel           string // debug|info|warn|error
    ShutdownTimeoutSec int    // default: 10
}

func LoadConfig() (Config, error)
```

Переменные окружения (префикс `MS_AUTH_`):

| Env                              | Default  | Required |
|----------------------------------|----------|----------|
| `MS_AUTH_HTTP_ADDRESS`           | `:8083`  | no       |
| `MS_AUTH_DATABASE_URL`           | —        | yes      |
| `MS_AUTH_LOG_LEVEL`              | `info`   | no       |
| `MS_AUTH_SHUTDOWN_TIMEOUT_SEC`   | `10`     | no       |

`LoadConfig` возвращает ошибку, если `DatabaseURL` пустая.

**Зарезервированные env-переменные** — в этом спеке НЕ читаются, но перечислены в `.env.example` с пометкой «используется в спеке NNNN», чтобы Codex не добавлял их случайно раньше времени:

```
# Спек 0021 — JWT
# MS_AUTH_JWT_PRIVATE_KEY_PATH=/run/secrets/ms-auth-jwt.pem
# MS_AUTH_JWT_KEY_ID=2026-04-20
# MS_AUTH_JWT_ISSUER=controlitix-auth
# MS_AUTH_JWT_ACCESS_TTL_SEC=900
# MS_AUTH_JWT_REFRESH_TTL_SEC=1209600

# Спек 0020 — пароли
# MS_AUTH_PASSWORD_PEPPER=<base64 от минимум 32 случайных байт>

# Спек 0022 — rate limit (опционально Redis, иначе in-memory)
# MS_AUTH_REDIS_URL=
# MS_AUTH_LOGIN_RATE_LIMIT=10
# MS_AUTH_LOGIN_RATE_WINDOW_SEC=60

# Спек 0023 — Kafka audit.logs
# MS_AUTH_KAFKA_BROKERS=localhost:9092
# MS_AUTH_KAFKA_AUDIT_TOPIC=audit.logs
```

### HTTP health

- `GET /healthz` → 200 `{"status":"ok"}` всегда.
- `GET /readyz` → 200 при доступности БД (`PingContext`, таймаут 1с); 503 + `{"status":"degraded","reason":"database unreachable"}` иначе.

### main.go (последовательность)

1. `config.LoadConfig()`.
2. Инициализация slog (уровень из конфига, JSON handler).
3. `database.OpenPostgres(ctx, cfg.DatabaseURL)`.
4. Создание health-хэндлера с зависимостью на `*sql.DB`.
5. Запуск HTTP-сервера health в goroutine.
6. Ожидание SIGINT/SIGTERM, отмена контекста, корректное закрытие HTTP (Shutdown) и БД в течение `ShutdownTimeoutSec`.

В логах должны быть записи: `starting ms-auth`, `database connected`, `http server started address=:8083`, `shutdown signal received`, `http server shutting down`, `database closed`, `ms-auth stopped`.

## Constraints

- Структура каталогов и стиль кода копируют `ms-editor`/`ms-poll` (Clean Architecture, `fmt.Errorf("...: %w", err)` для ошибок).
- НЕ заводить зависимость на модули `ms-editor` / `ms-poll`.
- Ни одной таблицы — миграции в спеке 0019. Ни одного доменного типа — в спеке 0020. Ни одного эндпоинта, кроме health, — в спеках 0022/0023.
- Не добавлять Kafka в этом спеке.
- Не добавлять JWT-библиотеки в этом спеке (спек 0021).
- Не добавлять `argon2` (спек 0020).
- Один `go.mod` на сервис.
- `.env.example` должен быть в репозитории; реальный `.env` — в `.gitignore` (уже есть у других сервисов, проверить).

## Verify

- `cd ms-auth && go mod tidy && go build ./...` проходит.
- `go vet ./...` чистый.
- `docker build -f ms-auth/Dockerfile ms-auth` собирается.
- Запуск с минимальным `.env`:
  ```
  MS_AUTH_DATABASE_URL=postgres://controlitix:controlitix@localhost:5432/controlitix?sslmode=disable
  ```
  - сервис стартует, в логе видно `http server started address=:8083`.
  - `curl http://localhost:8083/healthz` → 200.
  - `curl http://localhost:8083/readyz` → 200 при поднятом Postgres, 503 при остановленном.
- Остановка по `Ctrl+C` завершает процесс без panic, в логе видны ожидаемые сообщения shutdown.
- Git-diff: появляется только новый каталог `ms-auth/`, никаких изменений в других сервисах.
