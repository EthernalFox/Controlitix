# ADR-0011: Konva в редакторе, Pixi в просмотрщике

- Статус: accepted
- Дата: 2026-04-15
- Авторы: команда Controlitix

## Контекст

Платформе нужно рендерить мнемосхемы в двух режимах с разными требованиями:

- **editor-ui** — интерактивный редактор: выделение, трансформации, привязка к сетке, undo/redo, формы свойств. Сложность операций важнее предельной производительности.
- **viewer-ui** — просмотр в realtime: много фигур обновляются одновременно (цвет, видимость, текст), высокая частота обновлений. Плавный рендер при 2 000+ значений в секунду важнее удобства API.

## Рассмотренные варианты

1. **Konva везде** — объектная модель, удобная для редактирования, но дороже по производительности при большом количестве объектов и высокой частоте обновлений.
2. **Pixi везде** — быстрее рендер (WebGL), но нет готовых абстракций для редактора (selection, transformers, drag handles, history).
3. **Konva в editor, Pixi в viewer** — каждый инструмент применяется по сильной стороне. Нужен общий формат описания фигур, чтобы обе стороны рендерили одну и ту же схему.
4. **SVG** — простой, но не тянет динамику при большом количестве обновлений.
5. **Canvas 2D без библиотек** — максимум контроля, максимум кода.

## Решение

- **editor-ui** использует **Konva** — богатый API для редактора, прямая поддержка Transformer, drag-handles, undo/redo через Zustand.
- **viewer-ui** использует **Pixi** — WebGL-рендеринг, лучшая производительность при realtime-обновлениях.
- **Общий формат фигур** — JSONB `figure_params`, описывающий тип, геометрию, стиль и правила динамики. Обе стороны читают один формат и маппят его на свои объекты рендеринга.

## Последствия

**Позитивно:**

- Каждый инструмент применяется по сильной стороне.
- Производительность Viewer выше, чем если бы использовали Konva.
- UX редактора богаче, чем если бы использовали Pixi.

**Негативно:**

- Два рендерера = два набора маппинга «JSONB → объекты рендера». Требуется согласованность стилей.
- При изменении доступных типов фигур нужно обновлять маппинг в обоих местах.
- Команде нужно знать обе библиотеки.

**Риск и митигация:**

- Риск расхождения визуализации (одна и та же схема выглядит в editor и viewer по-разному).
- Митигация: общий набор примеров в `06_Дизайн/` с регрессионным визуальным сравнением; тесты на маппинг параметров.
