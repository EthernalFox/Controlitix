# 0019: ms-auth — миграции схемы `auth.*` и справочники

## Scope

`ms-auth`. Создаёт схему `auth` и все её таблицы через Goose-миграции + seed ролей, источника идентичности `local` и начального `admin`-пользователя.
Этот спек — только DDL + seed. Никакого Go-кода, кроме одношотовой job-обёртки для применения миграций (по образцу `ms-editor-migrate`).

## Context

- Каркас сервиса: спек [`0018.ready.ms-auth-skeleton.md`](0018.ready.ms-auth-skeleton.md).
- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md).
- Решения: [ADR-0012](../docs/08_ADR/ADR-0012-ms-auth-pluggable-identity.md), [ADR-0007](../docs/08_ADR/ADR-0007-service-accounts-env-secrets.md).
- Схема `auth` упомянута в корневой архитектуре ([`docs/02_Архитектура/README.md`](../docs/02_Архитектура/README.md)) как одна из 6 схем единой БД. **На данный момент она не создана** — миграции ms-editor (`000001`, `000002`, `000003`) её не заводят. Создаём здесь.
- Goose применяется по образцу ms-editor: отдельный binary `cmd/ms-auth-migrate/main.go` и сервис-шот `ms-auth-migrate` в docker-compose.
- Все `subject` — строки (`local:<uuid>`), PK `users.id` — отдельный UUID для внутренних FK. Это ключевое архитектурное решение (см. ADR-0012).

## Interface

### Схема `auth.*` — миграция 000001

```sql
-- +goose Up
CREATE SCHEMA IF NOT EXISTS auth;

-- Справочник источников идентичности.
-- В MVP — одна строка 'local'. LDAP/AD/Kerberos/OIDC — добавятся позже.
CREATE TABLE auth.identity_sources (
    id          serial PRIMARY KEY,
    type        text NOT NULL,    -- local | ldap | ad | kerberos | oidc
    name        text NOT NULL,    -- человекочитаемое имя ("Local database", "Corporate AD", ...)
    config      jsonb NOT NULL DEFAULT '{}'::jsonb,
    is_enabled  boolean NOT NULL DEFAULT true,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT identity_sources_type_check
        CHECK (type IN ('local', 'ldap', 'ad', 'kerberos', 'oidc'))
);

CREATE UNIQUE INDEX identity_sources_name_uq ON auth.identity_sources (name);

-- Роли. В MVP — фиксированный набор (admin/engineer/operator).
CREATE TABLE auth.roles (
    code        text PRIMARY KEY,    -- admin | engineer | operator
    name        text NOT NULL,       -- "Администратор", "Инженер", "Оператор"
    description text NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);

-- Пользователи.
-- subject — стабильный внешний идентификатор вида "local:<uuid>", "ad:<guid>", ...
-- Используется как JWT "sub". PK id — отдельный uuid для FK-связей.
CREATE TABLE auth.users (
    id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    subject        text NOT NULL,
    source_id      integer NOT NULL REFERENCES auth.identity_sources (id),
    username       text NOT NULL,
    display_name   text NULL,
    email          text NULL,
    password_hash  text NULL,  -- NULL для внешних источников (AD/LDAP/Kerberos/OIDC)
    is_active      boolean NOT NULL DEFAULT true,
    last_login_at  timestamptz NULL,
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX users_subject_uq ON auth.users (subject);
CREATE UNIQUE INDEX users_username_source_uq ON auth.users (source_id, lower(username));
CREATE INDEX users_email_lower_idx ON auth.users (lower(email)) WHERE email IS NOT NULL;

-- Назначения ролей.
CREATE TABLE auth.user_roles (
    user_id   uuid NOT NULL REFERENCES auth.users (id) ON DELETE CASCADE,
    role_code text NOT NULL REFERENCES auth.roles (code),
    granted_at timestamptz NOT NULL DEFAULT now(),
    granted_by uuid NULL REFERENCES auth.users (id),
    PRIMARY KEY (user_id, role_code)
);

CREATE INDEX user_roles_role_idx ON auth.user_roles (role_code);

-- Маппинг внешних групп (из AD/LDAP/OIDC) в наши роли.
-- В MVP таблица пустая, LocalProvider её не использует.
CREATE TABLE auth.role_mappings (
    id              bigserial PRIMARY KEY,
    source_id       integer NOT NULL REFERENCES auth.identity_sources (id) ON DELETE CASCADE,
    external_group  text NOT NULL,      -- CN группы в AD, claim-значение в OIDC, ...
    role_code       text NOT NULL REFERENCES auth.roles (code),
    created_at      timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX role_mappings_source_group_role_uq
    ON auth.role_mappings (source_id, lower(external_group), role_code);

-- Технологические учётные записи (ТУЗ).
-- client_secret_hash — Argon2id (см. спек 0020).
CREATE TABLE auth.service_accounts (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    client_id           text NOT NULL,
    client_secret_hash  text NOT NULL,
    display_name        text NOT NULL,
    scopes              text[] NOT NULL DEFAULT '{}',
    is_active           boolean NOT NULL DEFAULT true,
    created_at          timestamptz NOT NULL DEFAULT now(),
    updated_at          timestamptz NOT NULL DEFAULT now(),
    last_used_at        timestamptz NULL
);

CREATE UNIQUE INDEX service_accounts_client_id_uq ON auth.service_accounts (client_id);

-- Refresh-токены (opaque + hash).
-- family_id объединяет все токены цепочки ротации для reuse-detection.
CREATE TABLE auth.refresh_tokens (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     uuid NOT NULL REFERENCES auth.users (id) ON DELETE CASCADE,
    family_id   uuid NOT NULL,
    token_hash  text NOT NULL,           -- SHA-256 hex от opaque-строки
    parent_id   uuid NULL REFERENCES auth.refresh_tokens (id) ON DELETE SET NULL,
    user_agent  text NULL,
    ip          inet NULL,
    issued_at   timestamptz NOT NULL DEFAULT now(),
    expires_at  timestamptz NOT NULL,
    used_at     timestamptz NULL,
    revoked_at  timestamptz NULL,
    revoke_reason text NULL
);

CREATE UNIQUE INDEX refresh_tokens_hash_uq ON auth.refresh_tokens (token_hash);
CREATE INDEX refresh_tokens_user_idx ON auth.refresh_tokens (user_id);
CREATE INDEX refresh_tokens_family_idx ON auth.refresh_tokens (family_id);
CREATE INDEX refresh_tokens_expires_idx ON auth.refresh_tokens (expires_at)
    WHERE revoked_at IS NULL AND used_at IS NULL;

-- Аудит.
CREATE TABLE auth.audit_log (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    occurred_at     timestamptz NOT NULL DEFAULT now(),
    actor_subject   text NULL,          -- JWT sub совершавшего, NULL для анонимных попыток
    action          text NOT NULL,      -- login.success, login.failure, token.refresh, admin.user.create, ...
    target          text NULL,          -- кого/что затронуло (user_id, client_id, ...)
    result          text NOT NULL,      -- success | failure
    reason          text NULL,          -- короткая машинно-читаемая причина (invalid_credentials, rate_limited, ...)
    ip              inet NULL,
    user_agent      text NULL,
    metadata        jsonb NOT NULL DEFAULT '{}'::jsonb
);

CREATE INDEX audit_log_occurred_idx ON auth.audit_log (occurred_at DESC);
CREATE INDEX audit_log_actor_idx ON auth.audit_log (actor_subject);
CREATE INDEX audit_log_action_idx ON auth.audit_log (action);

-- +goose Down
DROP TABLE IF EXISTS auth.audit_log;
DROP TABLE IF EXISTS auth.refresh_tokens;
DROP TABLE IF EXISTS auth.service_accounts;
DROP TABLE IF EXISTS auth.role_mappings;
DROP TABLE IF EXISTS auth.user_roles;
DROP TABLE IF EXISTS auth.users;
DROP TABLE IF EXISTS auth.roles;
DROP TABLE IF EXISTS auth.identity_sources;
DROP SCHEMA IF EXISTS auth;
```

### Seeds — миграция 000002

```sql
-- +goose Up
INSERT INTO auth.identity_sources (id, type, name, config, is_enabled)
VALUES (1, 'local', 'Local database', '{}'::jsonb, true)
ON CONFLICT (id) DO NOTHING;

-- Для совместимости будущих INSERT с serial'ом
SELECT setval('auth.identity_sources_id_seq',
              GREATEST((SELECT MAX(id) FROM auth.identity_sources), 1));

INSERT INTO auth.roles (code, name, description) VALUES
    ('admin',    'Администратор', 'Полный доступ, управление пользователями и ТУЗ'),
    ('engineer', 'Инженер',       'CRUD инженерной конфигурации (objects, devices, tags, diagrams)'),
    ('operator', 'Оператор',      'Просмотр мнемосхем, трендов, квитирование тревог')
ON CONFLICT (code) DO NOTHING;

-- +goose Down
DELETE FROM auth.roles WHERE code IN ('admin','engineer','operator');
DELETE FROM auth.identity_sources WHERE id = 1;
```

### Initial admin — миграция 000003

**Подход:** миграция управляется переменными окружения. Если `MS_AUTH_INITIAL_ADMIN_USERNAME` и `MS_AUTH_INITIAL_ADMIN_PASSWORD_HASH` заданы — создаётся пользователь. Если пусто — миграция no-op. Хэш считается Argon2id **снаружи** (например, `ms-auth-migrate --hash-password`), чтобы не встраивать в миграцию криптокод.

```sql
-- +goose Up
-- +goose StatementBegin
DO $$
DECLARE
    v_username text := current_setting('ms_auth.initial_admin_username', true);
    v_hash     text := current_setting('ms_auth.initial_admin_password_hash', true);
    v_email    text := current_setting('ms_auth.initial_admin_email', true);
    v_user_id  uuid;
BEGIN
    IF v_username IS NULL OR v_username = '' OR v_hash IS NULL OR v_hash = '' THEN
        RAISE NOTICE 'ms_auth: initial admin vars not set, skipping';
        RETURN;
    END IF;

    INSERT INTO auth.users (subject, source_id, username, display_name, email, password_hash, is_active)
    VALUES (
        'local:' || gen_random_uuid()::text,
        1,
        v_username,
        'Administrator',
        NULLIF(v_email, ''),
        v_hash,
        true
    )
    ON CONFLICT (source_id, lower(username)) DO NOTHING
    RETURNING id INTO v_user_id;

    IF v_user_id IS NULL THEN
        SELECT id INTO v_user_id FROM auth.users
         WHERE source_id = 1 AND lower(username) = lower(v_username);
    END IF;

    INSERT INTO auth.user_roles (user_id, role_code)
    VALUES (v_user_id, 'admin')
    ON CONFLICT DO NOTHING;
END $$;
-- +goose StatementEnd

-- +goose Down
-- +goose StatementBegin
DO $$
DECLARE
    v_username text := current_setting('ms_auth.initial_admin_username', true);
BEGIN
    IF v_username IS NULL OR v_username = '' THEN
        RETURN;
    END IF;
    DELETE FROM auth.users WHERE source_id = 1 AND lower(username) = lower(v_username);
END $$;
-- +goose StatementEnd
```

`current_setting('ms_auth.initial_admin_*', true)` читает session-level GUC. `ms-auth-migrate` выставляет их перед запуском Goose:

```sql
SET ms_auth.initial_admin_username = '...';
SET ms_auth.initial_admin_password_hash = '$argon2id$...';
SET ms_auth.initial_admin_email = '...';
```

### `ms-auth-migrate`

По образцу `ms-editor-migrate`:

```go
package main

// Основной режим — goose up/down/status.
// Плюс команда `hash-password` — читает пароль из stdin, печатает Argon2id-хэш в stdout.
// Это нужно, чтобы сгенерировать MS_AUTH_INITIAL_ADMIN_PASSWORD_HASH снаружи.
// Параметры Argon2id согласно ADR-0012: m=64 MiB, t=3, p=2; pepper = env MS_AUTH_PASSWORD_PEPPER.

func main() {
    // subcommands:
    //   ms-auth-migrate up
    //   ms-auth-migrate down
    //   ms-auth-migrate status
    //   ms-auth-migrate hash-password  (stdin -> stdout)
}
```

`up` перед вызовом Goose должен выставить GUC из env:

```go
_, _ = db.Exec("SET ms_auth.initial_admin_username = $1", os.Getenv("MS_AUTH_INITIAL_ADMIN_USERNAME"))
_, _ = db.Exec("SET ms_auth.initial_admin_password_hash = $1", os.Getenv("MS_AUTH_INITIAL_ADMIN_PASSWORD_HASH"))
_, _ = db.Exec("SET ms_auth.initial_admin_email = $1", os.Getenv("MS_AUTH_INITIAL_ADMIN_EMAIL"))
```

Argon2id-параметры — **в этом спеке** реализовать через `golang.org/x/crypto/argon2`. В спеке 0020 появится полноценный пакет `internal/infrastructure/password`; здесь минимальная реализация в `cmd/ms-auth-migrate/hash.go` (повторно не используется — утилита одноразовая).

### .env.example — добавить

```
# Applied only on first `up` migration. If either is empty — no admin created.
MS_AUTH_INITIAL_ADMIN_USERNAME=admin
MS_AUTH_INITIAL_ADMIN_EMAIL=admin@example.local
# Generate via: echo -n 'your-password' | docker run ... ms-auth-migrate hash-password
MS_AUTH_INITIAL_ADMIN_PASSWORD_HASH=
# Required for hashing. Base64-encoded random >= 32 bytes.
MS_AUTH_PASSWORD_PEPPER=
```

## Constraints

- Все DDL-объекты в схеме `auth`. Ничего в `public` / `devices` / `tags` / `history` / `alarms`.
- Никаких FK из / в другие схемы. Пользователи и роли живут исключительно внутри `auth`.
- `CHECK`-констрейнт на `identity_sources.type` строго со списком 5 значений даже при том, что в MVP используется только `local`. Это документирует намерение.
- Seed ролей использует фиксированный набор (`admin|engineer|operator`), нигде в коде и миграциях не добавлять другие.
- Пароли хранятся строго как Argon2id encoded-строки (`$argon2id$...`). Никакого bcrypt, никакого plaintext.
- Миграция `000003` должна быть идемпотентной (`ON CONFLICT DO NOTHING`): повторный `goose up` не должен падать, даже если admin уже создан вручную.
- `hash-password` subcommand требует `MS_AUTH_PASSWORD_PEPPER` в env; при отсутствии — выход с ошибкой.
- Не трогать миграции `ms-editor/`. Каждый сервис владеет своими миграциями.
- Не добавлять `soft delete` (`deleted_at`) на `auth.users` — исп. флаг `is_active`. Hard-delete доступен только каскадно через ON DELETE CASCADE.

## Verify

- `cd ms-auth && go mod tidy && go build ./...` проходит (включая `cmd/ms-auth-migrate`).
- `docker build -f ms-auth/Dockerfile ms-auth` собирается.
- Против чистого PG:
  ```
  MS_AUTH_DATABASE_URL=... ./ms-auth-migrate up
  ```
  - Применяются 3 миграции.
  - `\dt auth.*` показывает: `audit_log`, `identity_sources`, `refresh_tokens`, `role_mappings`, `roles`, `service_accounts`, `user_roles`, `users`.
  - `SELECT code FROM auth.roles` → три строки.
  - `SELECT type, name FROM auth.identity_sources` → `(local, Local database)`.
- `goose down` — откатывает до пустой БД (все 3 миграции).
- Цикл `up → down → up` стабилен.
- Команда генерации хэша:
  ```
  MS_AUTH_PASSWORD_PEPPER=... echo -n 'secret' | ./ms-auth-migrate hash-password
  ```
  печатает строку формата `$argon2id$v=19$m=65536,t=3,p=2$<salt>$<hash>`.
- С переменными окружения:
  ```
  MS_AUTH_INITIAL_ADMIN_USERNAME=admin
  MS_AUTH_INITIAL_ADMIN_PASSWORD_HASH=$argon2id$...
  MS_AUTH_INITIAL_ADMIN_EMAIL=admin@example.local
  ```
  после `goose up` в `auth.users` есть ровно одна строка с `username='admin'`, а в `auth.user_roles` — связка с `role_code='admin'`.
- Повторный `goose up` при уже созданном admin'е не падает и не дублирует строки.
- Без переменных: `RAISE NOTICE 'ms_auth: initial admin vars not set, skipping'` в логе, записи не создаются.
