# 0022: ms-auth — HTTP /login, /refresh, /logout, /userinfo + rate limit + audit

## Scope

`ms-auth`. Пользовательские HTTP-эндпоинты аутентификации, rate-limit, аудит событий безопасности (в БД + Kafka).
После этого спека — `editor-ui` может залогиниться через `POST /api/auth/login` и получить JWT. Admin CRUD и service-token — в спеке 0023.

## Context

- Предыдущие спеки: [0018](0018.ready.ms-auth-skeleton.md), [0019](0019.ready.ms-auth-migrations-seeds.md), [0020](0020.ready.ms-auth-identity-provider.md), [0021](0021.ready.ms-auth-jwt-jwks.md).
- Контракт: [`docs/04_API/ms-auth.md`](../docs/04_API/ms-auth.md), разделы 1 и 5.
- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-auth.md`](../docs/02_Архитектура/Микросервисы/ms-auth.md).
- Формат ошибок — RFC 7807 (`application/problem+json`), как в ms-editor (см. `ms-editor/internal/api/http/handler.go` + `internal/api/http/problems.go` как референс стиля).
- Аудит — таблица `auth.audit_log` (из 0019) + Kafka-топик `audit.logs` ([ADR-0010](../docs/08_ADR/ADR-0010-kafka-event-bus.md)). Если Kafka недоступна — пишем в БД и логируем warning, не падаем.
- Rate limit: счётчик N неудач за окно M по ключу `ip + username`. MVP-реализация — in-memory с sync.Map + expiry; Redis — опционально (если `MS_AUTH_REDIS_URL` задан). В этом спеке делаем **только in-memory**, Redis — в отдельном спеке при необходимости.

### Rate limiter

```go
package ratelimit

type Limiter struct { /* sync.Map + clock + cfg */ }

func New(maxFailures int, window time.Duration, clock func() time.Time) *Limiter

// Allow возвращает true, если текущая попытка разрешена.
// Ключ — произвольная строка (в auth.go — "ip:username").
// Не инкрементирует счётчик — это задача OnFailure/OnSuccess.
func (l *Limiter) Allow(key string) (allowed bool, retryAfter time.Duration)

// OnFailure инкрементирует счётчик и при превышении возвращает retryAfter>0 в следующем Allow.
func (l *Limiter) OnFailure(key string)

// OnSuccess сбрасывает счётчик (успешный логин).
func (l *Limiter) OnSuccess(key string)
```

Реализация:

- Хранилище: `sync.Map[key]struct{count int; firstFailAt time.Time}`.
- При первом `OnFailure` — `count=1, firstFailAt=now`.
- Дальше `count++`. Если `now - firstFailAt > window` — сбросить в `count=1, firstFailAt=now`.
- `Allow`: если `count >= maxFailures` и `now - firstFailAt <= window` — запрет, `retryAfter = window - (now - firstFailAt)`.
- GC: фоновая goroutine раз в `window` чистит устаревшие записи.
- `OnSuccess` удаляет ключ.

### Handlers — auth.go

```go
type AuthHandler struct {
    auth     *usecase.AuthService
    tokens   *usecase.TokenService
    users    *repository.UserRepository     // для /userinfo
    audit    *usecase.AuditService
    limiter  *ratelimit.Limiter
    cfg      AuthHandlerConfig
    logger   *slog.Logger
}

type AuthHandlerConfig struct {
    RefreshCookieName string // default = "refresh_token"
    RefreshCookiePath string // default = "/api/auth"
    RefreshCookieSecure bool // default = true; false только для локальной разработки
    RefreshCookieTTL  time.Duration
}

func (h *AuthHandler) Register(r chi.Router) {
    r.Post("/login",    h.login)
    r.Post("/refresh",  h.refresh)
    r.Post("/logout",   h.logout)
    r.With(RequireAuth(ks, cfg.JWTAudienceUser)).Get("/userinfo", h.userinfo)
}
```

**POST /api/auth/login** — см. контракт (04_API/ms-auth.md, 1.1):

```
1. Декодировать body { username, password }. Пустое → 400 /errors/validation.
2. key := fmt.Sprintf("%s|%s", clientIP, strings.ToLower(username)).
3. if !limiter.Allow(key) → 429 /errors/auth/rate-limited, Retry-After = retryAfter.
     + audit.Record(AuditRateLimited, Result=failure, Reason="too_many_attempts", IP, UserAgent).
4. authUser, err := authService.Authenticate(ctx, "local", Credentials{Username, Password}).
5. if err:
      - ErrInvalidCredentials → 401 /errors/auth/invalid-credentials.
      - ErrUserDisabled       → 403 /errors/auth/user-disabled.
      - ErrSourceDisabled     → 503 /errors/auth/source-disabled.
      - default               → 500.
     limiter.OnFailure(key).
     audit.Record(AuditLoginFailure, actor="", target=username, result=failure,
                  reason=<stable machine code>, IP, UserAgent).
     return.
6. tokens, err := tokenService.IssueForUser(ctx, &authUser.User, authUser.Source.Type, authUser.Roles, meta).
   При ошибке → 500.
7. limiter.OnSuccess(key).
8. Ответ:
   - тело { access_token, token_type:"Bearer", expires_in, refresh_token, user{...} }.
   - Set-Cookie: refresh_token=<raw>; HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=<refresh ttl>.
9. audit.Record(AuditLoginSuccess, actor=user.Subject, target=user.ID, result=success, IP, UserAgent).
```

**POST /api/auth/refresh**:

```
1. Взять refresh: из тела либо из cookie. Если нет → 400 /errors/validation.
2. tokens, user, err := tokenService.Rotate(ctx, refresh, meta).
3. if err:
     - ErrRefreshReused → 401 /errors/auth/invalid-refresh.
         audit.Record(AuditTokenReuseDetected, actor=user.Subject (если есть), result=failure, reason="reuse_detected").
     - ErrInvalidRefresh → 401 /errors/auth/invalid-refresh.
         audit.Record(AuditLoginFailure (или отдельный code?)..., result=failure, reason="invalid_refresh").
     - ErrUserDisabled → 403 /errors/auth/user-disabled.
4. Успех:
     - Тело { access_token, token_type, expires_in, refresh_token }.
     - Обновить cookie refresh_token новым значением.
     - audit.Record(AuditTokenRefresh, actor=user.Subject, result=success).
```

**POST /api/auth/logout**:

```
1. Взять refresh. Если нет — ответ 204 всё равно.
2. tokenService.Revoke(ctx, refresh, "logout").
3. Очистить cookie (Set-Cookie с Max-Age=0).
4. audit.Record(AuditLogout, actor=Principal.Subject если есть либо "", result=success).
5. 204 No Content.
```

**GET /api/auth/userinfo** (за RequireAuth):

```
1. Principal из контекста.
2. user := userRepo.FindBySubject(Principal.Subject) → если nil (удалён, но JWT ещё валиден) → 401 /errors/auth/invalid-token.
3. roles := userRepo.GetRoles(user.ID).
4. source := sourceRepo.FindByID(user.SourceID).
5. Ответ по контракту (см. 04_API/ms-auth.md, 1.4).
```

## Constraints

- Только формат RFC 7807 для ошибок, никакого произвольного JSON.
- Ответ `/login` при неверных кредах одинаков для "нет такого пользователя" и "неправильный пароль" (401, `/errors/auth/invalid-credentials`). Различие — только в `audit_log.reason`.
- Ответ `/login` при rate-limit — 429 с заголовком `Retry-After` в секундах.
- Rate limiter ключуется на `clientIP + username`. `clientIP` — из `X-Forwarded-For` (первый) если есть, иначе `RemoteAddr`. Документировать в README, что это безопасно только за доверенным gateway (nginx), что справедливо для нашей архитектуры.
- Cookie refresh-токена: `HttpOnly`, `Secure`, `SameSite=Strict`, Path=`/api/auth`. Допускать `Secure=false` только при `MS_AUTH_DEV_MODE=true` (dev).
- `/logout` всегда 204, независимо от валидности токена.
- Audit-failure (запись в БД упала) никогда не должна ронять успешный логин — логируем warn и возвращаем 200. Kafka-ошибки — тем более.
- Не обрабатывать admin-ручки и `/service-token` — они в 0023.
- Не добавлять CSRF-token — refresh живёт в cookie с SameSite=Strict, это MVP-достаточно.
- Не добавлять `/logout-all` (global logout) — возможно в 0023.
- Никаких логов пароля, refresh, access-token в явном виде.
- `RequireAuth` валидирует подпись JWT строго по keystore (локальный), проверяет `iss`, `aud`, `exp`, `nbf`.
