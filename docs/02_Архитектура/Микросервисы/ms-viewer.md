# ms-viewer — просмотр, realtime, тревоги и история

## Назначение

Единый backend для операторского контура. `ms-viewer` обслуживает `viewer-ui`, принимает поток текущих значений от `ms-poll`, хранит последние значения и историю, рассчитывает тревоги, выдаёт тренды и отправляет уведомления в Telegram.

## Стек

- Go
- PostgreSQL
- Redis
- Kafka

## Интеграции

- Kafka: вход `tags.values`, `config.changed`; выход `alarms.events` и служебные события при необходимости.
- Redis: кэш последних значений, pub/sub для realtime-доставки.
- REST/WebSocket для `viewer-ui`.
- Telegram Bot API / webhook для уведомлений.

## Границы ответственности

1. **Просмотр и realtime**
   - Выдача опубликованных мнемосхем и последних значений.
   - WebSocket-подписки по объектам, схемам и тегам.
   - Деградация до polling при необходимости.
2. **Кэш и история**
   - Обновление Redis актуальными значениями тегов.
   - Сохранение исторических рядов в PostgreSQL.
   - Выдача трендов, диапазонов и агрегатов для графиков.
3. **Тревоги**
   - Сопоставление входящих значений с `tag_setpoints`.
   - Вычисление состояний тревог, подавление, гистерезис, квитирование.
   - Публикация `alarms.events` для UI и аудита.
4. **Уведомления**
   - Формирование сообщений для Telegram по тревогам и сервисным событиям.
   - Повторы, дедупликация и эскалации по политике доставки.

## Источники данных

- Конфигурация объектов, схем, устройств и тегов приходит из PostgreSQL и обновляется по событию `config.changed` от `ms-editor`.
- Текущие значения поступают из `ms-poll`.
- Уставки и правила тревог читаются из `tags.tag_setpoints`.

## Нефункциональные требования

- Низкая задержка доставки realtime-обновлений.
- Идемпотентная запись истории и событий тревог.
- Контроль ретеншна и downsampling для исторических рядов.
- Устойчивость к кратковременным потерям Kafka/Redis с восстановлением состояния из PostgreSQL.
