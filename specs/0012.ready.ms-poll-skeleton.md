# 0012: ms-poll — скелет сервиса (config, DB read-only, Kafka, health)

## Scope

`ms-poll` — новый Go-микросервис опроса устройств. Этот спек создаёт каркас сервиса без какой-либо реальной логики опроса.
Задача — поднять Go-модуль, конфиг, подключения к PostgreSQL (read-only) и Kafka (consumer + producer), structured logging, health endpoints и Docker Compose.

## Context

- Архитектура: [`docs/02_Архитектура/Микросервисы/ms-poll.md`](../docs/02_Архитектура/Микросервисы/ms-poll.md)
- Roadmap Phase 4.1: [`docs/09_План-работ/README.md`](../docs/09_План-работ/README.md)
- Каркас как у `ms-editor` (см. `ms-editor/cmd/ms-editor/main.go`, `internal/config/`, `internal/infrastructure/database`, `internal/infrastructure/kafka`).
- `ms-poll` НЕ изменяет конфигурацию. Доступ к схемам `devices.*`, `tags.*`, `public.objects` — только на чтение.
- Kafka:
  - **subscribes** топик `config.changed` (publisher — `ms-editor`, формат — `domain.ConfigChangedEvent` из `ms-editor/internal/domain/event.go`).
  - **publishes** топик `tags.values` (формат и наполнение появляются в спеке 0016, здесь — только инициализация writer'а).
- Никакой реальной обработки событий и опроса в этом спеке. Цель — собрать каркас, который запускается, подключается ко всем зависимостям и корректно завершается по SIGTERM.

## Files

Создать с нуля:

- `ms-poll/go.mod` — модуль `github.com/EthernalFox/Controlitix/ms-poll`, Go 1.24.4. Зависимости: `github.com/jackc/pgx/v5`, `github.com/joho/godotenv`, `github.com/segmentio/kafka-go`.
- `ms-poll/go.sum` — после `go mod tidy`.
- `ms-poll/cmd/ms-poll/main.go` — entrypoint: загрузка конфига, slog, открытие БД, инициализация Kafka consumer + producer, HTTP-сервер health-эндпоинтов, graceful shutdown по SIGINT/SIGTERM с таймаутом 10 сек.
- `ms-poll/internal/config/config.go` — структура `Config` и `LoadConfig()` (см. Interface).
- `ms-poll/internal/infrastructure/database/postgres.go` — `OpenPostgres(ctx, url)` по образцу `ms-editor` (через `database/sql` + pgx stdlib).
- `ms-poll/internal/infrastructure/kafka/consumer.go` — обёртка `ConfigChangedConsumer` над `kafka.Reader`. На этом этапе — только `New`, `Run(ctx, handler)` и `Close`. Обработчик принимает `domain.ConfigChangedEvent`. В этом спеке handler — заглушка, которая логирует событие и коммитит offset.
- `ms-poll/internal/infrastructure/kafka/producer.go` — `TagValuesProducer` поверх `kafka.Writer` для топика `tags.values`. Только конструктор + `Close()`. Метод `Publish` появится в спеке 0016.
- `ms-poll/internal/domain/event.go` — копия `ConfigChangedEvent` структуры из `ms-editor/internal/domain/event.go` (ms-poll не должен зависеть от модуля ms-editor).
- `ms-poll/internal/api/http/health.go` — handler с двумя эндпоинтами: `/healthz` (liveness, всегда 200) и `/readyz` (readiness — проверяет ping БД и наличие живых подключений Kafka).
- `ms-poll/Dockerfile` — multi-stage по образцу `ms-editor/Dockerfile`. EXPOSE 8081 (отличается от ms-editor).
- `ms-poll/docker-compose.yml` — как и у `ms-editor`, но имя сервиса `ms-poll`, порт `8081:8081`. БЛОК `postgres` НЕ дублировать, использовать external network. Допустимо описать сервис без зависимостей и не запускать БД здесь — реальная Compose-сборка живёт в корне репо (если её нет, оставить локальный compose, как у ms-editor; postgres определять в этом же файле для разработки).
- `ms-poll/.env.example` — список всех переменных окружения с примерами значений (см. Interface).
- `ms-poll/README.md` — обновить: описание сервиса, схема запуска `go run ./cmd/ms-poll`, переменные окружения (ссылка на `.env.example`), эндпоинты health.

## Interface

### Config

```go
package config

type Config struct {
    HTTPAddress           string   // :8081
    DatabaseURL           string   // postgres://... — read-only role recommended
    LogLevel              string   // debug|info|warn|error
    KafkaBrokers          []string // comma-separated
    KafkaConfigTopic      string   // default: config.changed
    KafkaConfigGroupID    string   // default: ms-poll
    KafkaTagValuesTopic   string   // default: tags.values
    ShutdownTimeoutSec    int      // default: 10
}

func LoadConfig() (Config, error)
```

Переменные окружения (префикс `MS_POLL_`):

| Env                              | Default            | Required |
|----------------------------------|--------------------|----------|
| `MS_POLL_HTTP_ADDRESS`           | `:8081`            | no       |
| `MS_POLL_DATABASE_URL`           | —                  | yes      |
| `MS_POLL_LOG_LEVEL`              | `info`             | no       |
| `MS_POLL_KAFKA_BROKERS`          | —                  | yes      |
| `MS_POLL_KAFKA_CONFIG_TOPIC`     | `config.changed`   | no       |
| `MS_POLL_KAFKA_CONFIG_GROUP_ID`  | `ms-poll`          | no       |
| `MS_POLL_KAFKA_TAG_VALUES_TOPIC` | `tags.values`      | no       |
| `MS_POLL_SHUTDOWN_TIMEOUT_SEC`   | `10`               | no       |

`LoadConfig` возвращает ошибку, если `DatabaseURL` или `KafkaBrokers` пустые.

### Domain

```go
package domain

type ConfigChangedEvent struct {
    EntityType string          `json:"entity_type"`
    EntityID   string          `json:"entity_id"`
    Operation  string          `json:"operation"`
    Timestamp  time.Time       `json:"timestamp"`
    ActorID    *string         `json:"actor_id"`
    Payload    json.RawMessage `json:"payload"`
}
```

Структура должна побайтово совпадать с `ms-editor/internal/domain/event.go`.

### Kafka consumer

```go
package kafka

type ConfigChangedHandler func(ctx context.Context, event domain.ConfigChangedEvent) error

type ConfigChangedConsumer struct { /* ... */ }

func NewConfigChangedConsumer(brokers []string, topic, groupID string, logger *slog.Logger) *ConfigChangedConsumer
func (c *ConfigChangedConsumer) Run(ctx context.Context, handler ConfigChangedHandler) error
func (c *ConfigChangedConsumer) Close() error
```

`Run` блокирующий, читает сообщения через `FetchMessage` → `handler` → `CommitMessages`. Завершается по `ctx.Done()`. Если handler вернул ошибку — лог `error`, offset НЕ коммитится, переход к следующему сообщению (поведение усложнится в спеке 0013, здесь — простое).

### Kafka producer

```go
package kafka

type TagValuesProducer struct { /* writer + topic + logger */ }

func NewTagValuesProducer(brokers []string, topic string, logger *slog.Logger) *TagValuesProducer
func (p *TagValuesProducer) Close() error
// Publish(...) добавим в спеке 0016
```

### HTTP health

- `GET /healthz` → 200 `{"status":"ok"}` всегда.
- `GET /readyz` → 200 при доступности БД (`PingContext`, таймаут 1с) и наличии broker'ов в конфиге; 503 + `{"status":"degraded","reason":"..."}` иначе.

### main.go (последовательность)

1. `config.LoadConfig()`.
2. Инициализация slog.
3. `database.OpenPostgres()`.
4. `NewConfigChangedConsumer(...)`, `NewTagValuesProducer(...)`.
5. Запуск HTTP-сервера health в goroutine.
6. Запуск consumer.Run в goroutine с handler-заглушкой:

```go
handler := func(ctx context.Context, event domain.ConfigChangedEvent) error {
    logger.Info("config event received",
        "entity_type", event.EntityType,
        "entity_id", event.EntityID,
        "operation", event.Operation,
    )
    return nil
}
```

7. Ожидание SIGINT/SIGTERM, отмена контекста, корректное закрытие consumer/producer/HTTP/DB в течение `ShutdownTimeoutSec`.

## Constraints

- Структура каталогов и стиль кода копируют `ms-editor` (Clean Architecture, длинные понятные имена переменных, error-handling через `fmt.Errorf("...: %w", err)`).
- НЕ заводить зависимость на модуль `ms-editor`. `ConfigChangedEvent` дублируется по контракту.
- БД-доступ исключительно read-only — не использовать `INSERT/UPDATE/DELETE` ни в одном файле этого спека (даже если позже понадобится — это отдельный спек).
- Никаких драйверов опроса, никакого парсинга `address` JSONB, никакой нормализации значений — всё это будет в спеках 0014–0016.
- Никакой бизнес-логики обработки `config.changed` — только лог и commit. Cache + reload — спек 0013.
- Не добавлять `Publish` метод у `TagValuesProducer` — он появится в спеке 0016.
- Один модуль `go.mod` на сервис, не вкладывать в `ms-editor`.
- Не делать миграций — у `ms-poll` нет своих таблиц.

## Verify

- `cd ms-poll && go mod tidy && go build ./...` проходит.
- `go vet ./...` чистый.
- `docker build -f ms-poll/Dockerfile ms-poll` собирается.
- Запуск с минимальным `.env`:
  ```
  MS_POLL_DATABASE_URL=postgres://controlitix:controlitix@localhost:5432/controlitix?sslmode=disable
  MS_POLL_KAFKA_BROKERS=localhost:9092
  ```
  - сервис стартует, в логе видно `http server started address=:8081`, `kafka consumer started topic=config.changed group=ms-poll`.
  - `curl http://localhost:8081/healthz` → 200.
  - `curl http://localhost:8081/readyz` → 200 при поднятых Postgres+Kafka.
- Остановка по `Ctrl+C` завершает процесс без panic, в логе видно `http server shutting down`, `kafka consumer stopped`, `kafka producer closed`, `database closed`.
- При публикации в `config.changed` валидного JSON `ConfigChangedEvent` (например, через ms-editor CRUD или `kafkacat`) в логе ms-poll появляется строка `config event received entity_type=device entity_id=... operation=create`.
