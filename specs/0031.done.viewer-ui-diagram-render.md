# 0031: viewer-ui — Просмотр опубликованных мнемосхем (PixiJS) + ms-viewer endpoints

## Scope

Цельный поток «оператор открывает мнемосхему и видит реальное состояние»:

1. Backend (`ms-viewer/internal/`): три read-only REST-эндпоинта над `public.mimic` / `public.figures` / `public.figure_params` + Redis last-value cache.
2. Frontend (`viewer-ui/src/`): `pages/DiagramPage`, PixiJS-рендер всех 11 типов фигур, viewport (pan/zoom/fit), привязка значений тегов к визуальному состоянию, live-обновление через WS (0030).
3. Контракт «правил динамики» в `figure_params.dynamics` — обязательный к фиксации в [docs/04_API/ms-viewer.md](../docs/04_API/ms-viewer.md) и [docs/06_Дизайн/Figure-Types.md](../docs/06_Дизайн/Figure-Types.md).

Out of scope: правка фигур (это `editor-ui`), alarms-стрим на схеме (отдельная спека после `alarms.events`-канала), история по клику на фигуру (вытаскивает в TrendsPage — отдельная задача интеграции).

## Interface

### Backend REST — добавления в ms-viewer

#### `GET /api/objects/{objectId}/diagrams`

Список **опубликованных** мнемосхем объекта (без figures). Параметры: `limit` (default 50), `offset`.

Ответ 200:
```json
{
  "items": [
    { "id": "uuid", "object_id": "uuid", "name": "Котёл №1",
      "description": "...", "published_at": "2026-04-25T08:00:00Z",
      "figure_count": 42, "bound_tag_count": 18 }
  ],
  "total": 1, "offset": 0, "limit": 50
}
```

Фильтр в SQL: `WHERE object_id = $1 AND published_at IS NOT NULL AND deleted_at IS NULL ORDER BY name ASC`.

`figure_count`/`bound_tag_count` — из подзапросов на `public.figures` (`count(*) FILTER (WHERE deleted_at IS NULL)`, `count(DISTINCT tag_id) FILTER (WHERE tag_id IS NOT NULL AND deleted_at IS NULL)`).

#### `GET /api/diagrams/{diagramId}`

Полная мнемосхема со всеми фигурами и параметрами. Только если `published_at IS NOT NULL`.

Ответ 200:
```json
{
  "id": "uuid",
  "object_id": "uuid",
  "object_name": "Котельная №3",
  "name": "Котёл №1",
  "description": "...",
  "published_at": "2026-04-25T08:00:00Z",
  "canvas": { "width": 1920, "height": 1080, "background": "#F5F5F5" },
  "figures": [
    {
      "id": "uuid",
      "type": "rect",
      "tag_id": "uuid|null",
      "params": { /* JSONB как есть, без преобразований */ },
      "tag": {
        "id": "uuid",
        "name": "boiler_1.t_out",
        "device_id": "uuid",
        "device_name": "Boiler-1",
        "unit": { "id": 7, "symbol": "°C", "name": "°C" },
        "data_type": { "id": 2, "name": "float32" }
      } /* nullable */
    }
  ]
}
```

Если `published_at IS NULL` — 404 `/errors/diagrams/not-published`. Soft-deleted — 404 `/errors/diagrams/not-found`.

`canvas` — извлекается из `mimic` (нужны новые колонки `width`, `height`, `background`) **либо** из `description` JSON. Решение: добавить отдельную миграцию в ms-editor под колонки `canvas_width int`, `canvas_height int`, `canvas_background text` — **out of scope** этой спеки. На время — клиент использует фолбэк `1920×1080, background=#F5F5F5` если поля отсутствуют. В этой спеке: ответ ms-viewer всегда заполняет `canvas`, читая из миграции если она есть, иначе — фолбэк-значения.

#### `GET /api/diagrams/{diagramId}/snapshot`

Снапшот текущих значений всех тегов, привязанных к фигурам этой мнемосхемы. Используется на initial load до того, как поедут WS-сообщения.

Ответ 200:
```json
{
  "diagram_id": "uuid",
  "ts": "2026-04-25T10:00:00.123Z",
  "values": [
    { "tag_id": "uuid", "ts": "2026-04-25T10:00:00.000Z", "v": 75.2, "q": "ok" }
  ],
  "missing_tag_ids": ["uuid", "uuid"]
}
```

Реализация:
1. Получить distinct `tag_id` из figures (одним запросом).
2. `MGET ms-viewer:last:<tag1> ms-viewer:last:<tag2> ...` в Redis.
3. Распарсить, теги без значения → `missing_tag_ids`.

Без обращения к PostgreSQL (только Redis cache). Если Redis недоступен — 503 `/errors/realtime/cache-unavailable`.

#### Errors (RFC 7807)

| Type | Status |
|---|---|
| `/errors/diagrams/not-found` | 404 |
| `/errors/diagrams/not-published` | 404 |
| `/errors/realtime/cache-unavailable` | 503 |
| `/errors/auth/invalid-token` | 401 |

### Контракт `figure_params`

Базовая часть (как сейчас в editor):
```jsonc
{
  "x": 100, "y": 200,
  "width": 80, "height": 40,             // для rect/image/text/tag
  "radius": 30,                          // circle/ring/arc
  "radiusX": 40, "radiusY": 20,          // ellipse
  "innerRadius": 18, "outerRadius": 30,  // ring/arc/wedge
  "angle": 270, "rotation": 0,           // wedge/arc/rotate-all
  "points": [{"x":0,"y":0},{"x":50,"y":50}], // line/path
  "src": "...",                          // image
  "text": "...", "fontSize": 14, "fontFamily": "Inter", // text/tag
  "fill": "#FFFFFF", "stroke": "#000000", "strokeWidth": 1, "opacity": 1,
  "visible": true
}
```

Расширение для динамики (новое, фиксируется в этой спеке):

```jsonc
"dynamics": {
  "fillByQuality": {
    "ok":           "#4CAF50",
    "hi":           "#FFA726",
    "hihi":         "#EF5350",
    "uncertain":    "#42A5F5",
    "bad":          "#78909C",
    "comm_loss":    "#546E7A",
    "offline":      "#37474F",
    "acknowledged": "#7E57C2"
  },                                    // если присутствует — fill вычисляется по q
  "textFromValue": {
    "format": "%.1f",                   // sprintf для числа; null → "—"
    "appendUnit": true                  // добавить unit.symbol через пробел
  },                                    // только для type ∈ {text, tag}
  "visibilityByQuality": ["ok", "hi", "hihi"], // показывать только при этих q
  "blinkOnAlarm": true                  // мигать при q ∈ {hihi, hi} и !acknowledged
}
```

Все поля `dynamics.*` — опциональные. При их отсутствии фигура — статичная (рендерится один раз).

`blinkOnAlarm` — единственное мигание в системе (см. Design-System.md § «Правила HMI»: «Мигание — только для активных неквитированных тревог LoLo/HiHi»).

### Frontend — `DiagramPage` flow

1. Mount → распарсить `:objectId`, `:diagramId`.
2. Параллельно: `fetchDiagram(diagramId)` + `fetchDiagramSnapshot(diagramId)`.
3. После прихода `diagram` — `computeBoundTags(diagram.figures)` → массив уникальных `tag_id`.
4. `useTagSubscription(boundTags, onValue)` — подписка из 0030.
5. На initial snapshot и каждый `value` → `diagramStore.setValue(tag_id, point)`.
6. Рендер: `DiagramScene` подписан на `valuesByTag`; `FigureRenderer` для каждой фигуры применяет `applyDynamics(params, valuesByTag[fig.tag_id])` → resolved props → PIXI.

### `applyDynamics` — pure-функция

```ts
type ResolvedFigureProps = {
  fill: number;            // PIXI ожидает hex как number
  stroke: number;
  strokeWidth: number;
  opacity: number;
  visible: boolean;
  text?: string;
  blink: boolean;          // флаг для shader/alpha tween
  // ... + геометрия из params
};

function applyDynamics(
  params: FigureParams,
  value: TagPoint | undefined,    // undefined = нет данных (тег не привязан или snapshot не пришёл)
  unitSymbol: string | undefined,
): ResolvedFigureProps;
```

Поведение:
- Нет `dynamics` → возврат базовых полей as-is.
- `value === undefined` → quality считается `"bad"` для целей `fillByQuality`/`visibilityByQuality`; text → `"—"`.
- `value.v === null` → quality берётся из `value.q`, text → `"—"`.
- `dynamics.fillByQuality[q]` отсутствует → fallback на `params.fill`.
- `dynamics.visibilityByQuality` есть, текущий q не в списке → `visible: false`.

### Viewport (pan/zoom)

Реализуем без сторонней библиотеки `pixi-viewport` (она не обновлялась под Pixi 8 на момент написания):

- Pan: drag правой кнопкой / средней кнопкой / пробел+drag.
- Zoom: wheel (cursor-anchored), `Ctrl++`/`Ctrl+-`, кнопки в `DiagramHeader`.
- Fit: `Ctrl+0` / кнопка «Вписать» — рассчитывает scale по `canvas.width/height` и размеру контейнера.
- 100%: `Ctrl+1` — scale = 1.
- Border-clamp: pan не позволяет утащить canvas полностью за границы экрана (минимум 64px внутри viewport).

Состояние viewport — в `diagramStore.viewport: { x, y, scale }`.

### `widgets/FigureRenderer/shapes/*`

Каждая фигура — функциональный React-компонент, использующий `@pixi/react` примитивы (`<Container>`, `<Graphics>`, `<Sprite>`, `<Text>`). Подписан на updates через стандартный React-flow.

Спецификация рендера для каждого типа:

| Type | PIXI primitives | Min params |
|---|---|---|
| `rect`     | `<Graphics>` drawRoundedRect | `x, y, width, height, fill, stroke, strokeWidth` |
| `circle`   | `<Graphics>` drawCircle | `x, y, radius, fill, stroke, strokeWidth` |
| `ellipse`  | `<Graphics>` drawEllipse | `x, y, radiusX, radiusY` |
| `wedge`    | `<Graphics>` arc + lineTo | `x, y, outerRadius, angle, rotation` |
| `line`     | `<Graphics>` moveTo/lineTo | `points[], stroke, strokeWidth` |
| `image`    | `<Sprite>` через `Assets.load(src)` | `x, y, width, height, src` |
| `text`     | `<Text>` Pixi text | `x, y, text, fontSize, fontFamily, fill` |
| `ring`     | `<Graphics>` arc(0..2π) с `innerRadius` | `x, y, innerRadius, outerRadius` |
| `arc`      | `<Graphics>` arc | `x, y, radius, angle, rotation` |
| `tag`      | `<Container>` = rect + text | `x, y, width, height, text` |
| `path`     | `<Graphics>` moveTo + lineTo по `points[]` (или `points` как SVG-path string → парсер; в MVP — массив точек) | `points[]` |

Ошибки в params одного фигуры (например, `image.src` 404) — лог в console, фигура не рендерится, остальные не страдают.

### Blinking

Реализуется на стороне PIXI: `useTick` с периодом 800ms; для фигур с `blink === true` toggle `alpha 1.0 ↔ 0.4`. Только для активных неквитированных hi/hihi.

## Constraints

### Backend

- Никаких write-операций на `public.mimic`/`public.figures`/`public.figure_params`. Только SELECT.
- Никаких новых FK / migrations на эти таблицы.
- DB-роль `ms_viewer` уже имеет `SELECT` на `public.*` (см. 0029); проверить фактически и при необходимости поправить миграцию ролей.
- Не возвращать `figures` для не-опубликованной мнемосхемы — это контрактно operator’ский UI, черновики ему не показываются.
- Фигуры с `deleted_at IS NOT NULL` исключаются на уровне SQL.
- Snapshot строится **только** из Redis. Если ключа нет в кэше — тег попадает в `missing_tag_ids`, БД не дёргаем (это горячий путь, ходить в `tag_values_raw` тут — анти-паттерн). Заполнение кэша — задача 0029 (ingest); если его нет, оператор увидит «нет данных» по тегу до прихода первого WS-сообщения.
- HTTP-кэш на `GET /api/diagrams/{id}`: `Cache-Control: private, max-age=10` — конфигурация меняется редко, повторные обращения экономят БД.
- Все эндпоинты под `RequireAuth` (audience user).

### Frontend

- **PIXI.Application — один на страницу**, не глобальный singleton приложения. Создаётся в `DiagramCanvas`, освобождается на unmount.
- **Текстуры** через `PIXI.Assets.load` с кэшем по URL. На unmount страницы — `Assets.unload` для использованных URL, иначе утечка памяти при частых переходах.
- Никаких прямых импортов `@mantine/core` в `pages/DiagramPage` или `widgets/FigureRenderer` — только через фасад `shared/ui/components`.
- React 19 + `@pixi/react` 8.1: запрещено использовать legacy class-API из @pixi/react 7. Только `<Application>` + новые хуки.
- Размер сцены: фигуры рендерятся на полном `canvas.width × canvas.height`; viewport масштабирует через `Container.scale`. Не пересчитывать координаты фигур руками.
- Производительность: при ≥ 200 фигур — `Graphics` кэшируется через `cacheAsBitmap` для статических (без `dynamics`) фигур. Для динамических — нельзя (иначе live-update не виден).
- WS-подписка ограничена тегами текущей открытой мнемосхемы. На unmount — отписка по всем (`useTagSubscription` сам через refcount).
- `applyDynamics` — pure, без побочных эффектов; легко тестируется юнит-тестами (`features/diagram/lib/applyDynamics.test.ts`).
- При смене темы (light/dark) — фон canvas (`canvas.background`) **не** меняется автоматически: это конфигурация мнемосхемы из editor’а. Тема влияет только на Header, контролы, легенду — не на «холст инженера».
- При потере WS (`RealtimeStatus` ≠ `open`) — рисуется баннер сверху холста «Соединение потеряно. Данные могут быть неактуальны». Snapshot/полученные значения остаются на сцене.
- Запрещено пересоздавать `<Application>` при смене viewport state (zoom/pan) — обновляются только props контейнера.

### Контракт `dynamics`

- Поле `dynamics` — опциональное и аддитивное; отсутствие = статичная фигура.
- Все ключи `*ByQuality` принимают строки enum’а, неизвестные ключи игнорируются (forward-compatibility).
- Фигуры без `tag_id`, но с `dynamics`, → `dynamics` игнорируется (нет источника значения).
- Цвета в `dynamics.fillByQuality` — рекомендация, не обязательство. Если editor сохранил кастомные — viewer им следует. Если не сохранил — viewer может проставить дефолты из Design-System.md (логика — в `applyDynamics`).
- Валидацию `dynamics` на write делает `ms-editor` (отдельная задача расширения 0007 — здесь только чтение).
- Документировать в [docs/06_Дизайн/Figure-Types.md](../docs/06_Дизайн/Figure-Types.md) § «Минимальный контракт для figure_params» (раскрыть «правила динамики»).
- Документировать в [docs/04_API/ms-viewer.md](../docs/04_API/ms-viewer.md) полную схему ответа `/api/diagrams/{id}` с примером `dynamics`.

- Viewport нельзя утащить полностью за пределы экрана (min 64px внутри).
- При живом WS: смена значения тега в `tags.values` (через kafkacat) → фигура с этим `tag_id` меняет fill согласно `dynamics.fillByQuality`, текст-фигура показывает новое значение, единица добавлена.
- При `q: "comm_loss"` и `dynamics.visibilityByQuality: ["ok","hi","hihi"]` → фигура исчезает; вернулось `ok` → появляется.
- При `q: "hihi"` и `blinkOnAlarm: true` → фигура мигает с периодом 800ms.
- Потеря WS → баннер сверху, последние значения остались; восстановление WS → баннер уходит, значения догоняют (через `snapshot { reason: "subscribe" }` после реконнекта подписки).
- Размонтаж страницы (переход на `/alarms`) — нет утечки PIXI-приложения (DevTools Memory snapshot до/после показывает примерное равенство; нет растущих PIXI.Texture в куче).
- Переход с одной мнемосхемы на другую — старая отписана, новая подписана; `valuesByTag` сброшен.
- 200 фигур, из них 50 с `dynamics` → 60 fps на референс-машине; статичные 150 закэшированы как bitmap (видно в Pixi devtools).
- `applyDynamics` юнит-тесты покрывают: нет dynamics, нет value, value.v=null, fallback fill при отсутствии q-key, visibility filter, text форматирование с unit.
