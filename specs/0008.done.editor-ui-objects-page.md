# 0008: editor-ui — Страница объектов мониторинга

## Scope

`editor-ui` — `pages/`, `widgets/`, `entities/`, `shared/`. Затрагивает маршрутизацию, API-слой, Layout, Navbar, новые фасадные компоненты.

## Context

Страница объектов — точка входа в `editor-ui` после логина. Это первая полноценная страница list mode, поэтому спецификация также устанавливает:
- Вложенную маршрутизацию (замена текущей плоской).
- API-клиент (`shared/api/`).
- Паттерн Zustand-стора для entities.
- Обновлённый Navbar (дерево объектов вместо плоских ссылок).
- Новые фасадные компоненты в `shared/ui/components/`.

Связанные документы:
- `specs/0001.ready.editor-ui-layout-design-system.md` — лейаут, токены, компонентная модель.
- `docs/06_Дизайн/Information-Architecture.md` — sitemap, навигационная модель.
- `docs/04_API/ms-editor.md` — API-контракт.
- `docs/03_Модель-данных/public/Objects.md` — модель данных.

## 1. User Flow

### 1.1 Просмотр списка объектов

```
Пользователь → /objects
  → Layout: list mode (Header + Navbar + Main)
  → Navbar: дерево объектов (загружается из API)
  → Main: заголовок «Объекты мониторинга» + кнопка «Создать» + список объектов (карточки)
  → Каждая карточка: имя, описание, дата обновления
  → Поиск: TextInput в верхней части контента фильтрует список по имени
```

### 1.2 Создание объекта

```
Пользователь нажимает «Создать объект»
  → Открывается Modal
  → Поля: Название (обязательное), Описание (опциональное)
  → Валидация: название не пустое, уникальное (серверная)
  → Submit → POST /objects → Modal закрывается
  → Объект появляется в списке и в Navbar
  → При ошибке: сообщение в Modal (Notification не нужен)
```

### 1.3 Выбор объекта → переход к деталям

```
Пользователь кликает на объект в списке ИЛИ в Navbar
  → Навигация на /objects/:objectId (по умолчанию → вкладка «Устройства»)
  → Navbar: выбранный объект подсвечен
  → Main: шапка объекта (имя + кнопки Edit/Delete) + Tabs (Устройства | Теги | Мнемосхемы)
  → Под Tabs: контент активной вкладки (Outlet)
```

### 1.4 Редактирование объекта

```
Пользователь нажимает кнопку Edit (иконка карандаша) в шапке объекта
  → Открывается Modal с предзаполненными полями
  → Изменяет название и/или описание
  → Submit → PATCH /objects/:id → Modal закрывается
  → Обновлённые данные отражаются в шапке и в Navbar
```

### 1.5 Удаление объекта

```
Пользователь нажимает кнопку Delete (иконка корзины) в шапке объекта
  → Открывается Modal подтверждения: «Удалить объект "Цех №1"? Все устройства, теги и мнемосхемы будут удалены.»
  → Кнопки: «Удалить» (danger) / «Отмена» (secondary)
  → Submit → DELETE /objects/:id → Навигация на /objects
  → Объект исчезает из списка и Navbar
```

### 1.6 Навигация по вкладкам объекта

```
Пользователь на /objects/:id/devices
  → Кликает вкладку «Мнемосхемы»
  → Навигация на /objects/:id/diagrams
  → Контент вкладки обновляется (Outlet)
  → URL обновляется
  → Активная вкладка подсвечена
```

## 2. Маршрутизация

### 2.1 Текущая (плоская) → Целевая (вложенная)

Текущие маршруты `/mimics`, `/devices`, `/draw` удаляются. Вся навигация строится вокруг объектов.

```ts
// shared/libs/router/routes.ts

export const routePaths = {
  objects: "/objects",
  objectDetail: "/objects/:objectId",
  objectDevices: "/objects/:objectId/devices",
  objectTags: "/objects/:objectId/tags",
  objectDiagrams: "/objects/:objectId/diagrams",
  diagramEditor: "/objects/:objectId/diagrams/:diagramId/edit",
} as const;
```

### 2.3 ListLayout — общий каркас list mode

```tsx
// widgets/ListLayout/ListLayout.tsx
```

## 5. API-слой

### 5.1 HTTP-клиент

```ts
// shared/api/client.ts

const BASE_URL = import.meta.env.VITE_API_URL ?? "/api";

interface RequestOptions extends RequestInit {
  params?: Record<string, string | number>;
}

async function request<T>(path: string, options?: RequestOptions): Promise<T>;

export const api = {
  get: <T>(path: string, params?: Record<string, string | number>) => request<T>(path, { params }),
  post: <T>(path: string, body: unknown) => request<T>(path, { method: "POST", body: JSON.stringify(body) }),
  patch: <T>(path: string, body: unknown) => request<T>(path, { method: "PATCH", body: JSON.stringify(body) }),
  delete: (path: string) => request(path, { method: "DELETE" }),
};
```

### 5.2 Общие типы

```ts
// shared/api/types.ts

export interface PaginatedResponse<T> {
  items: T[];
  total: number;
  offset: number;
  limit: number;
}

export interface ApiError {
  type: string;
  title: string;
  status: number;
  detail: string;
  errors?: { field: string; message: string }[];
}
```

### 5.3 API объектов

```ts
// entities/objects/api.ts

import { api } from "@shared/api";
import type { PaginatedResponse } from "@shared/api";
import type { MonitoringObject, CreateObjectPayload, UpdateObjectPayload } from "./types";

export const objectsApi = {
  list: (params?: { offset?: number; limit?: number; name?: string }) =>
    api.get<PaginatedResponse<MonitoringObject>>("/objects", params),

  get: (id: string) =>
    api.get<MonitoringObject>(`/objects/${id}`),

  create: (payload: CreateObjectPayload) =>
    api.post<MonitoringObject>("/objects", payload),

  update: (id: string, payload: UpdateObjectPayload) =>
    api.patch<MonitoringObject>(`/objects/${id}`, payload),

  delete: (id: string) =>
    api.delete(`/objects/${id}`),
};
```

## Constraints

- **Фасадный паттерн**: Mantine-компоненты НЕ импортируются напрямую за пределами `shared/ui/components/`. Каждый новый фасадный компонент: обёртка Mantine → кастомные types → реэкспорт.
- **Layout один раз**: Страницы list mode **не оборачиваются в Layout** — это делает `ListLayout` через `<Outlet />`.
- **FSD**: pages → widgets → entities → shared. Нарушение зависимостей запрещено.
- **Реэкспорт**: все сущности экспортируются через `index.ts` на уровне модуля.
- **API camelCase**: бэкенд отдаёт `snake_case`, клиент трансформирует в `camelCase` (в `shared/api/client.ts`).
- **Не добавлять**: теги, устройства, мнемосхемы — это отдельные спецификации.
- **Env-переменная**: `VITE_API_URL` для базового URL API.
