# 0009: editor-ui — Страница мнемосхем объекта

## Scope

`editor-ui` — `pages/DiagramsPage`, `entities/diagrams`, `widgets/`. Вкладка «Мнемосхемы» внутри `ObjectDetailPage`.

## Context

Страница мнемосхем — вкладка в карточке объекта (`/objects/:objectId/diagrams`). Инженер видит список мнемосхем текущего объекта, создаёт новые, удаляет, и переходит в редактор.

Зависимости:
- **0008** (Objects page) — маршрутизация, ListLayout, ObjectDetailPage с Outlet, фасадные компоненты, API-клиент.
- `specs/0001.ready.editor-ui-layout-design-system.md` — лейаут, режим editor mode (для перехода в редактор).
- `docs/04_API/ms-editor.md` — API мнемосхем.
- `docs/03_Модель-данных/public/Mimic.md` — модель данных.

### Терминология

Бэкенд и БД используют термин `mimic`. Фронтенд и пользовательский интерфейс используют термин **«мнемосхема»** (diagram). В коде entity называется `diagrams` (не `mimics`), API-пути — `/diagrams`. Существующий `entities/mimics/` переименовывается в `entities/diagrams/`.

## 1. User Flow

### 1.1 Просмотр списка мнемосхем

```
Пользователь на /objects/:objectId → кликает вкладку «Мнемосхемы»
  → Навигация на /objects/:objectId/diagrams
  → Контент вкладки: заголовок «Мнемосхемы» + кнопка «Создать» + сетка карточек
  → Каждая карточка:
    ┌─────────────────────────────┐
    │  [Превью-заглушка / иконка] │
    │  Главная схема               │
    │  Опубликована: 15.03.2026    │  ← или «Черновик»
    │                  [✏️] [🗑]   │
    └─────────────────────────────┘
  → Клик на карточку → переход в редактор
```

### 1.2 Создание мнемосхемы

```
Пользователь нажимает «Создать мнемосхему»
  → Открывается Modal
  → Поля: Название (опциональное, placeholder «Без названия»), Описание (опциональное)
  → Submit → POST /objects/:objectId/diagrams
  → Modal закрывается
  → Новая карточка появляется в списке со статусом «Черновик»
  → Автоматический переход в редактор НЕ происходит (инженер может создать несколько схем подряд)
```

### 1.3 Переход в редактор

```
Пользователь кликает на карточку мнемосхемы ИЛИ нажимает кнопку ✏️
  → Навигация на /objects/:objectId/diagrams/:diagramId/edit
  → Смена layout: list mode → editor mode (Header с toolbar, Panel, Aside, Footer)
  → Загружается Canvas + фигуры мнемосхемы из API
```

**Важно:** Переход в редактор — это смена маршрута на `diagramEditor`, который рендерится **вне** ListLayout (у него свой layout — editor mode из спеки 0001).

### 1.4 Удаление мнемосхемы

```
Пользователь нажимает 🗑 на карточке
  → Открывается Modal подтверждения: «Удалить мнемосхему "Главная схема"? Все фигуры будут удалены.»
  → Кнопки: «Удалить» (danger) / «Отмена» (secondary)
  → Submit → DELETE /diagrams/:id
  → Карточка исчезает из списка
```

### 1.5 Empty state

```
Нет мнемосхем для объекта
  → Иллюстрация + текст «У этого объекта нет мнемосхем»
  → Кнопка «Создать первую мнемосхему»
```

## 5. API-интеграция

### 5.1 Типы

```ts
// entities/diagrams/types.ts

export interface Diagram {
  id: string;
  objectId: string;
  name: string | null;
  description: string | null;
  publishedAt: string | null;
  createdAt: string;
  updatedAt: string;
}

export interface CreateDiagramPayload {
  name?: string;
  description?: string;
}
```

### 5.2 API-функции

```ts
// entities/diagrams/api.ts

import { api } from "@shared/api";
import type { PaginatedResponse } from "@shared/api";
import type { Diagram, CreateDiagramPayload } from "./types";

export const diagramsApi = {
  listByObject: (objectId: string, params?: { offset?: number; limit?: number }) =>
    api.get<PaginatedResponse<Diagram>>(`/objects/${objectId}/diagrams`, params),

  get: (id: string) =>
    api.get<Diagram>(`/diagrams/${id}`),

  create: (objectId: string, payload: CreateDiagramPayload) =>
    api.post<Diagram>(`/objects/${objectId}/diagrams`, payload),

  delete: (id: string) =>
    api.delete(`/diagrams/${id}`),
};
```

### 5.3 Zustand Store

```ts
// entities/diagrams/store.ts

import { create } from "zustand";
import { diagramsApi } from "./api";
import type { Diagram } from "./types";

interface DiagramsState {
  diagrams: Diagram[];
  isLoading: boolean;
  error: string | null;

  fetchDiagrams: (objectId: string) => Promise<void>;
  createDiagram: (objectId: string, payload: { name?: string; description?: string }) => Promise<Diagram>;
  deleteDiagram: (id: string) => Promise<void>;
  reset: () => void;
}

export const useDiagramsStore = create<DiagramsState>((set) => ({
  diagrams: [],
  isLoading: false,
  error: null,

  fetchDiagrams: async (objectId) => { /* set isLoading, call diagramsApi.listByObject, set diagrams */ },
  createDiagram: async (objectId, payload) => { /* call diagramsApi.create, append to diagrams, return */ },
  deleteDiagram: async (id) => { /* call diagramsApi.delete, remove from diagrams */ },
  reset: () => set({ diagrams: [], isLoading: false, error: null }),
}));
```

`reset()` вызывается при смене объекта (в `useEffect` внутри `DiagramsPage`).

### 6.2 DiagramCard

```ts
interface DiagramCardProps {
  diagram: Diagram;
  onEdit: (id: string) => void;   // навигация в редактор

```

- Карточка (`Card`) с:
  - Верхняя часть: заглушка-иконка (placeholder для будущего превью).
  - Имя: `Text fw={600}`, fallback «Без названия» если `name === null`.
  - Статус: `Badge` — зелёный «Опубликована» если `publishedAt !== null`, серый «Черновик» если null.
  - Дата публикации (если есть) или дата создания.
  - ActionIcon: Edit (✏️ → навигация в редактор) и Delete (🗑 → confirm).
- Клик по карточке (вне ActionIcon) → навигация в редактор.

## 8. Навигация в редактор — граница спеки

Переход на `/objects/:objectId/diagrams/:diagramId/edit` рендерит `DrawPage` в **editor mode** layout. Реализация editor mode — это scope спеки 0001 и будущей спеки по редактору. В данной спеке:

- `DiagramCard` формирует URL через `buildDiagramEditorPath(objectId, diagramId)` (helper из 0008).
- Навигация выполняется через `useNavigate()`.
- Что происходит в `DrawPage` — вне scope данной спеки.

## Constraints

- **Фасадный паттерн**: SimpleGrid и Textarea оборачиваются через `shared/ui/components/`. Не импортировать `@mantine/core` напрямую.
- **FSD**: DiagramCard — widget (содержит UI + бизнес-логику отображения). DiagramFormModal — widget.
- **Store reset**: при смене objectId store должен сбрасываться и перезагружаться.
- **Не реализовывать**: редактор мнемосхемы, публикацию, превью — вне scope.
- **Имена**: в коде entity = `diagrams` (не `mimics`). В UI = «Мнемосхемы».
