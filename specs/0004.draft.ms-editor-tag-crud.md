# 0004: ms-editor — Tag CRUD

## Scope

`ms-editor/internal/` — domain, usecase, api/http, infrastructure/repository.

## Context

Tags are the third-level entity (Object → Device → Tag). A tag represents a single measurement or state read from a device. Each tag has technical parameters (address, data type, unit), optional setpoints (alarm thresholds), and optional scaling (interpolation and/or factor+offset).

Prerequisite: spec 0002 (migration), spec 0003 (device CRUD + Kafka infrastructure).

Related: `docs/03_Модель-данных/tags/`, `docs/04_API/ms-editor.md`.

### UseCase

```go
type TagUseCase struct {
    tagRepo       domain.TagRepository
    tagParamsRepo domain.TagParamsRepository
    setpointsRepo domain.TagSetpointsRepository
    scalingRepo   domain.TagScalingRepository
    referenceRepo domain.ReferenceRepository
    eventPublisher domain.EventPublisher
    logger        *slog.Logger
}
```

Methods:
- `CreateTag(ctx, deviceID, name, description, params, setpoints, scaling) (TagFull, error)` — creates tag + params + optional setpoints/scaling in transaction, publishes `config.changed`.
- `GetTag(ctx, tagID) (TagFull, error)` — returns tag with all nested data.
- `UpdateTag(ctx, tagID, update) (Tag, error)` — updates tag name/description, publishes event.
- `DeleteTag(ctx, tagID) error` — soft delete, publishes event.
- `ListTagsByDevice(ctx, deviceID) ([]Tag, error)`
- `UpdateTagParams(ctx, tagID, paramsUpdate) (TagParams, error)` — upserts tag_params, publishes event.
- `UpdateTagSetpoints(ctx, paramID, setpoints) (TagSetpoints, error)` — upserts, publishes event.
- `DeleteTagSetpoints(ctx, paramID) error` — removes setpoints row.
- `UpdateTagScaling(ctx, paramID, scaling) (TagScaling, error)` — upserts, publishes event.
- `DeleteTagScaling(ctx, paramID) error` — removes scaling row.
- `ListDataTypes(ctx) ([]DataType, error)`
- `ListUnits(ctx) ([]Unit, error)`
- `ListUnitsByCategory(ctx, category) ([]Unit, error)`

## Tag address JSONB reference

Structure depends on the device type of the parent device. Validation is deferred to spec 0007 — here we only store.

**Modbus (modbus_rtu, modbus_tcp):**
```json
{
  "register_type": "holding",
  "address": 40001
}
```
`register_type` values: `"holding"`, `"input"`, `"coil"`, `"discrete"`.

**SNMP (snmp_v1, snmp_v2c, snmp_v3):**
```json
{
  "oid": "1.3.6.1.2.1.1.1.0"
}
```

## Constraints

- Follow existing code patterns exactly.
- `CreateTag` must validate that `deviceID` exists and is not soft-deleted.
- `UpdateTagSetpoints` / `UpdateTagScaling` require that `tag_params` exists for the tag (return 400 if not).
- Setpoints and scaling are 1:1 with tag_params (keyed by `param_id`).
- All repository reads exclude soft-deleted tags (`WHERE deleted_at IS NULL`).
- The `GET /tags/{id}` response includes nested `params`, `setpoints`, `scaling` (all nullable).
- `GET /units?category=electrical` filters by category.
- Event publishing: reuse `EventPublisher` from spec 0003. `entity_type` = `"tag"`.
- On create/update events, include full `TagFull` as payload. On delete, payload is `null`.
- Structured logging: include `"method"`, `"tag_id"`, `"device_id"`.

## Verify

- `go build ./...` passes.
- `POST /devices/{deviceID}/tags` with body `{"name":"Temp_Room1","params":{"data_type_id":9,"unit_id":16,"address":{"oid":"1.3.6.1.2.1.1.1.0"}}}` creates tag with params.
- `GET /tags/{id}` returns tag with nested params, null setpoints, null scaling.
- `PUT /tags/{id}/setpoints` with `{"lolo":-10,"lo":0,"hi":35,"hihi":45}` upserts setpoints.
- `PUT /tags/{id}/scaling` with `{"raw_min":0,"raw_max":4095,"eng_min":-50,"eng_max":150}` upserts scaling.
- Subsequent `GET /tags/{id}` returns tag with all nested data.
- `DELETE /tags/{id}/setpoints` removes setpoints; `GET` shows `"setpoints": null`.
- `DELETE /tags/{id}` soft-deletes; subsequent `GET` returns 404.
- `GET /data-types` returns 10 types.
- `GET /units` returns 30 units.
- `GET /units?category=electrical` returns only electrical units.
- Kafka `config.changed` events are emitted for tag create/update/delete.
