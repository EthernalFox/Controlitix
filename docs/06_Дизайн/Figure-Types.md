# Figure Types — editor-ui

## Назначение

Документ фиксирует набор типов фигур, которые на текущий момент заявлены и поддерживаются в `editor-ui`. Это нужно, чтобы:

- `editor-ui`, `ms-editor` и документация говорили на одном языке;
- `figure_params` не превращался в бесконтрольный JSONB без контракта;
- команда проектировала wireframes и API вокруг реального набора фигур, а не абстрактного "и др.".

## Поддерживаемые типы фигур

| Type | UI label | Назначение |
|---|---|---|
| `rect` | Rectangle | Прямоугольник, базовые панели, рамки, зоны оборудования |
| `circle` | Circle | Круговые индикаторы, точки состояния |
| `ellipse` | Ellipse | Эллиптические зоны и индикаторы |
| `wedge` | Wedge | Сектора, условные пиктограммы, угловые индикаторы |
| `line` | Line | Линии трасс, соединения, контуры |
| `image` | Image | Растровые изображения и подложки |
| `text` | Text | Текстовые подписи, значения, единицы измерения |
| `ring` | Ring | Кольцевые индикаторы и обводки |
| `arc` | Arc | Дуги и частичные круговые индикаторы |
| `tag` | Tag | Группированная метка/лейбл |
| `path` | Path | Произвольные SVG-подобные контуры |

## Практический статус для MVP

Для MVP имеет смысл разделять фигуры на два слоя:

- **Базовые для первого релиза редактора:** `rect`, `circle`, `line`, `text`, `image`
- **Расширенные, но уже заведённые в коде:** `ellipse`, `wedge`, `ring`, `arc`, `tag`, `path`

Причина такого разделения: редактор может раньше выйти на production readiness по базовым фигурам, но публичный контракт `ms-editor` уже должен знать полный текущий набор, который объявлен в `editor-ui`.

## Минимальный контракт для figure_params

Все фигуры обязаны иметь:

- `id`
- `type`
- координатные и/или геометрические параметры, соответствующие типу Konva-узла

Дополнительно, в зависимости от сценария, в `figure_params` могут храниться:

- визуальные стили: `fill`, `stroke`, `strokeWidth`, `opacity`
- текстовые свойства: `text`, `fontSize`, `fontFamily`
- поведение на схеме: `visible`, `draggable`, `rotation`
- правила динамики: изменение цвета, текста или видимости по значению/quality тега

## Ограничения

- `figure_params` должен оставаться рендеро-нейтральным на уровне бизнес-смысла, даже если `editor-ui` использует Konva.
- Если фигура завязана на сугубо Konva-специфичный параметр, нужно проверить, сможет ли `viewer-ui` на Pixi отрисовать тот же смысловой результат.
- Для проектирования HMI нельзя рассчитывать на то, что сложные фигуры заменят понятную семантику состояния. Цвет, форма и подпись должны оставаться читаемыми.
