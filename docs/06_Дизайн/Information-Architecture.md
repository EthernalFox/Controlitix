## Scope

Этот документ покрывает только `editor-ui` инженерного контура. `viewer-ui` должен быть описан отдельно, чтобы не смешивать сценарии инженера и оператора.

## Навигационная модель

- **Primary navigation:** список объектов.
- **Secondary navigation:** вкладки внутри выбранного объекта.
- **Tertiary navigation:** действия в шапке страницы, toolbar редактора, контекстные панели и модалки.

Главная идея: инженер почти всегда работает в контексте конкретного объекта. Поэтому верхний уровень IA строится не вокруг абстрактных разделов, а вокруг потока `объект -> устройство/тег/схема`.

## Перечень страниц

### 1. Логин

- Точка входа в `editor-ui`.
- Содержит форму входа и состояния ошибки сессии.
- Отдельный flow: редирект после `401`, экран истечения сессии, запрет доступа по `403`.

### 2. Список объектов

- Стартовый экран после логина.
- Показывает объекты мониторинга, поиск и основные действия.
- Ключевые действия: выбрать объект, создать объект.

### 3. Создание объекта

- Отдельный экран или modal поверх списка объектов.
- В MVP можно реализовать как отдельную страницу, если форма заметно расширится.
- Результат действия: переход в карточку созданного объекта.

### 4. Карточка объекта

- Контейнерный экран объекта.
- Показывает шапку объекта, хлебные крошки, статусные сообщения и secondary navigation.
- Отсюда инженер попадает во вкладки `Устройства`, `Теги`, `Мнемосхемы`.

### 5. Устройства объекта

- Список устройств текущего объекта.
- Ключевые действия: создать устройство, открыть форму редактирования, удалить устройство.
- Для MVP это самостоятельная вкладка внутри карточки объекта.

### 6. Форма устройства

- Открывается из вкладки `Устройства`.
- Содержит имя, тип устройства, протокол и конфигурацию подключения.
- Рекомендуемый паттерн: drawer или modal, если не требуется длинный мастер.

### 7. Теги объекта

- Экран управления тегами в контексте объекта.
- Должен позволять фильтровать теги по устройству, типу данных и unit.
- Это лучше, чем прятать теги только внутрь формы устройства: инженеру нужен плоский обзор.

### 8. Форма тега

- Создание и редактирование тега.
- Содержит адрес/OID, тип данных, единицу, scaling, setpoints.
- Может открываться как drawer или отдельная подстраница.

### 9. Список мнемосхем объекта

- Список схем выбранного объекта.
- Ключевые действия: создать схему, открыть редактор, удалить схему, посмотреть статус публикации.

### 10. Карточка мнемосхемы

- Лёгкий промежуточный экран метаданных схемы.
- Нужен, если хотим отдельно показывать название, описание, `published_at`, служебные действия.
- Если команда хочет минимизировать глубину маршрутов, этот экран можно схлопнуть в список схем.

### 11. Редактор мнемосхемы

- Ключевой экран `editor-ui`.
- Содержит:
  - левую панель со списком объектов/схем и поиском;
  - центральный холст Konva;
  - toolbar с undo/redo, zoom, snap to grid, publish;
  - правые панели `Свойства`, `Данные`, `Устройства и теги`.
- Именно этот экран должен быть главным фокусом wireframes и hi-fi mockups.

### 12. Подтверждение публикации

- Не отдельная страница, а обязательный modal flow из редактора.
- Подтверждает публикацию текущего состояния схемы.
- Должен показывать статус: `saving`, `published`, `error`.

### 13. Поиск

- Необязательная отдельная страница на MVP.
- Можно реализовать как глобальный command/search overlay для перехода к объекту, устройству, тегу или схеме.
- В sitemap оставлен как опциональная точка роста.

### 14. Системные экраны и состояния

- `403 / Нет прав`
- `404 / Не найдено`
- `500 / Ошибка backend`
- `Session expired`
- Empty states для пустых списков объектов, устройств, тегов, схем
- Loading/skeleton states для списков и редактора

Ниже не догма, а базовое предложение для фронтенда:

## Приоритет для wireframes

В первую очередь имеет смысл рисовать и согласовывать:

1. `Логин`
2. `Список объектов`
3. `Карточка объекта -> Устройства`
4. `Карточка объекта -> Теги`
5. `Список мнемосхем объекта`
6. `Редактор мнемосхемы`
7. `Модалка подтверждения публикации`
8. Системные состояния: `403`, `404`, `500`, empty state

## Открытые вопросы

- Нужен ли отдельный экран `Карточка мнемосхемы`, или достаточно списка + перехода сразу в редактор.
- Должны ли формы устройства и тега быть отдельными маршрутами или overlay-формами.
- Нужен ли в MVP глобальный поиск как самостоятельный экран.
- Нужен ли отдельный экран `settings` в `editor-ui`, если админский контур будет выделен отдельно.
