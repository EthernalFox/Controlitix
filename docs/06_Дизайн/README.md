## Ограничения и решения по стеку

- **Библиотека UI:** [Mantine UI 8](https://mantine.dev). Кастомный дизайн — настройка темы Mantine + кастомные компоненты поверх примитивов.
- **Canvas-библиотеки:** Konva в `editor-ui`, Pixi в `viewer-ui` — [ADR-0011](../08_ADR/ADR-0011-konva-pixi-split.md). Дизайн фигур должен быть **рендеро-нейтральным**: одно и то же описание `figure_params` должно одинаково выглядеть в обоих инструментах.
- **Темы:** тёмная — основная для оператора (диспетчерская), светлая — основная для инженера. Обе темы обязательны в MVP.
- **Язык:** русский (см. [project docs conventions](../../CLAUDE.md) при появлении, пока — память команды).
- **Инструмент проектирования:** Figma. В репозитории хранятся snapshot-изображения и ссылки на frame-ы, но источник правды — Figma-файл.

## Критерии важные для SCADA-продукта

Отдельно фиксируем то, что отличает HMI-дизайн от обычного web-UI и на что нужно обращать внимание при каждом решении:

1. **Читаемость при быстром взгляде.** Оператор смотрит на экран секундами, должен мгновенно понять состояние.
2. **Стабильность цифр.** Численные значения не должны «прыгать» по ширине. Моноширинный шрифт обязателен для значений тегов.
3. **Цвет — не единственный носитель информации.** Обязательно дублируем иконкой или паттерном (штриховка, форма) для accessibility.
4. **Мигание — редкий ресурс.** Мигает только активная тревога, ничего другого. Иначе оператор перестаёт воспринимать сигнал.
5. **Тёмная тема по умолчанию.** Диспетчерские обычно в полутени, глаза работают часами.
6. **Чёткая иерархия тревог.** LoLo/HiHi визуально отличаются от Lo/Hi. Communication loss и offline — визуально отличаются от OK и от тревог.
7. **Quality всегда рядом со значением.** Оператор должен видеть, можно ли верить числу.
8. **Плотность информации.** SCADA исторически плотно заполнена — это норма. Нельзя «раздувать» экраны современным web-стилем с большими отступами.
