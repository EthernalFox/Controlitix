# 0016: ms-poll — драйвер SNMP, нормализация значений, публикация в Kafka

## Scope

`ms-poll`. Завершающий спек первой волны:
- Драйвер `domain.Driver` для SNMP v1/v2c/v3 поверх `github.com/gosnmp/gosnmp`.
- Нормализация значений на пути `Reading → published value`: `data_type` cast → `scaling` (interpolation **затем** factor+offset).
- `TagValuesPublisher` имплементация поверх `kafka.Writer` для топика `tags.values`.
- Опциональная публикация сырых значений в `raw.readings` (toggle через env).

После этого спека ms-poll способен опрашивать реальные устройства Modbus/SNMP и кормить ms-viewer.

## Context

- Драйвер фреймворк: спек [`0014.ready.ms-poll-scheduler-driver-framework.md`](0014.ready.ms-poll-scheduler-driver-framework.md).
- Modbus драйверы: спек [`0015.ready.ms-poll-modbus-drivers.md`](0015.ready.ms-poll-modbus-drivers.md).
- Roadmap Phase 4.4 (SNMP), 4.5 (нормализация), 4.6 (публикация).
- Формат `tag.address` для SNMP: `{"oid":"1.3.6.1.2.1.1.3.0"}`.
- Формат `device.settings`:
  - `snmp_v1`/`snmp_v2c`: `{"host":"192.168.1.20","port":161,"community":"public","timeout_ms":2000,"retries":1}`.
  - `snmp_v3`: `{"host":"...","port":161,"username":"u","auth_protocol":"SHA","auth_passphrase":"...","priv_protocol":"AES","priv_passphrase":"...","security_level":"authPriv","timeout_ms":2000,"retries":1}`.
- Kafka топик `tags.values` потребляет `ms-viewer` для realtime + history. Контракт фиксируется этим спеком.
- Партиционирование: `key = tag_id`. Это даёт стабильный порядок per-tag.

Структура цепочки публикаторов в main:

```
scheduler.Publish([]Reading)
  → normalizingPublisher (Reading + Tag → нормализованный Reading)
    → compositePublisher (если raw enabled)
      ├── tagValuesPublisher (обязательный, Kafka tags.values)
      └── rawReadingsPublisher (best-effort, Kafka raw.readings)
    → иначе сразу tagValuesPublisher
```

Все обёртки реализуют `usecase.TagValuesPublisher`.

## Interface

### SNMP Driver

```go
package snmp

type SNMPDriverFactory struct{}

func NewSNMPDriverFactory() *SNMPDriverFactory
func (f *SNMPDriverFactory) SupportedType() string { return "snmp_v2c" } // и "snmp_v1", "snmp_v3" — см. ниже
func (f *SNMPDriverFactory) Build(device *domain.DeviceSnapshot) (domain.Driver, error)
```

Поддержка трёх версий через ОДНУ фабрику с тремя `SupportedType` будет некрасива — поэтому в `DriverRegistry.Register` мы регистрируем три обёртки:

```go
registry.Register(snmp.NewVersionedFactory(gosnmp.Version1))   // SupportedType "snmp_v1"
registry.Register(snmp.NewVersionedFactory(gosnmp.Version2c))  // SupportedType "snmp_v2c"
registry.Register(snmp.NewVersionedFactory(gosnmp.Version3))   // SupportedType "snmp_v3"
```

`Build` парсит `device.Settings` под нужную версию (community для v1/v2c, USM для v3), создаёт `*gosnmp.GoSNMP`, делает `Connect()`. Драйвер хранит `*gosnmp.GoSNMP`.

`Read`:
1. Сгруппировать теги по `oid`. Если в одном устройстве больше одного тега — использовать `Get(oids...)` или `GetBulk` (оптимизация: при ≤25 OIDs — один `Get`; иначе разбить).
2. Сопоставить ответ ASN.1 → `decode(value, tag.DataType)`.
3. Сформировать `[]Reading` в исходном порядке `tags`.
4. Любая ошибка GET → все теги бэтча получают `Reading{Quality: bad, Error: ...}`.

`HealthCheck`: `Get` по `1.3.6.1.2.1.1.3.0` (sysUpTime). Любой ответ → nil.

`Close`: `gosnmp.Conn.Close()`.

### SNMP decode

```go
package snmp

func DecodePDU(pdu gosnmp.SnmpPDU, dataType string) (any, error)
```

Маппинг:

| gosnmp ASN.1 type        | float64 / int64 / string / bool                              |
|--------------------------|--------------------------------------------------------------|
| Integer                  | int64; cast по data_type (boolean → value!=0)                |
| Counter32, Gauge32, TimeTicks | uint64                                                  |
| Counter64                | uint64                                                       |
| OctetString              | string (если data_type=string) или попытка распарсить в число|
| ObjectIdentifier         | string                                                       |
| OpaqueFloat / OpaqueDouble | float64                                                    |
| NoSuchObject / NoSuchInstance / EndOfMibView | error («no such object»)                  |
| Null                     | error («null pdu»)                                           |

Final cast по `data_type` (например, ответ Integer → tag.DataType=`float32` → конвертация через float64).

### Normalize

```go
package usecase

// Normalize выполняет: cast (по data_type) → scaling. Не трогает Reading с Quality != good.
// Возвращает НОВЫЙ Reading; не мутирует входной.
func Normalize(reading domain.Reading, tag *domain.TagSnapshot) domain.Reading
```

Алгоритм при `Quality == good`:

1. **Cast**: `reading.RawValue := reading.Value`. Привести `reading.Value` к каноническому типу:
   - `bool` → `bool`.
   - `int8|int16|int32` → `int64`.
   - `uint8|uint16|uint32` → `uint64`.
   - `float32|float64` → `float64`.
   - `string` → `string`.
   Для числовых конверсий используем reflect/type switch. Если value не приводится — `Quality=bad, Error="cast: ..."`.
2. **Scaling**, только если `tag.Scaling != nil` и значение числовое:
   - Если все четыре `RawMin/RawMax/EngMin/EngMax` непустые: линейная интерполяция
     `v = (raw - RawMin) * (EngMax - EngMin) / (RawMax - RawMin) + EngMin`.
   - Затем, если `Factor != nil`: `v = v * Factor`.
   - Затем, если `Offset != nil`: `v = v + Offset`.
   - Результат всегда `float64`.
3. Если scaling применён — `reading.Value` становится `float64`. Если scaling не применим — `reading.Value` остаётся типа после cast.

`Reading.RawValue` ВСЕГДА содержит значение до cast и scaling (то, что пришло от драйвера). Если была применена нормализация — это полезно для отладки и `raw.readings`.

Setpoints в нормализации НЕ применяем — они нужны только для алармов (которые делает ms-viewer).

### Publisher contracts

```go
package kafka

// Расширение TagValuesProducer из спека 0012:
func (p *TagValuesProducer) Publish(ctx context.Context, readings []domain.Reading) error
```

Сериализация одного Reading в JSON:

```json
{
  "tag_id": "uuid",
  "device_id": "uuid",
  "value": 23.45,         // тип определяется data_type: number, bool, string
  "quality": "good",
  "error": "",            // непусто только при quality != good
  "ts": "2026-04-18T10:23:45.123Z"
}
```

Один Kafka message на один Reading. Key = `tag_id` (стабильное партиционирование per-tag). Топик из конфига `KafkaTagValuesTopic`.

`raw.readings` сообщение:

```json
{
  "tag_id": "uuid",
  "device_id": "uuid",
  "raw_value": "0x4048F5C3",    // string-представление сырого значения для отладки
  "value_type": "float32",
  "quality": "good",
  "ts": "2026-04-18T10:23:45.123Z"
}
```

`raw_value` сериализуется как строка (для unfiable JSON формата отладки): `fmt.Sprintf("%v", reading.RawValue)`.

### Composite publisher

```go
package kafka

type compositePublisher struct {
    primary  usecase.TagValuesPublisher
    bestEffort usecase.TagValuesPublisher
    logger *slog.Logger
}

func NewCompositePublisher(primary, bestEffort usecase.TagValuesPublisher, logger *slog.Logger) usecase.TagValuesPublisher
```

`Publish`:
1. `err := primary.Publish(ctx, readings)` — если ошибка, возвращаем её (это критичный путь, scheduler не блокируется, но ошибка попадает в лог).
2. `if err := bestEffort.Publish(ctx, readings); err != nil { logger.Warn("...") }` — игнорируем ошибку.

### Normalizing publisher

```go
package usecase

type NormalizingPublisher struct {
    next  TagValuesPublisher
    store *SnapshotStore
    logger *slog.Logger
}

func NewNormalizingPublisher(next TagValuesPublisher, store *SnapshotStore, logger *slog.Logger) *NormalizingPublisher
func (p *NormalizingPublisher) Publish(ctx context.Context, readings []domain.Reading) error
```

`Publish` для каждого reading достаёт `tag := store.Get().Tags[reading.TagID]`. Если тег уже удалён — пропускаем reading (это редкая гонка между удалением тега и текущим Read устройства). Если тег есть — `Normalize(reading, tag)` → собрать новый слайс → передать дальше.

## Constraints

- Для SNMP v3 используем USM. Engine ID auto-discovery через `gosnmp` (`Connect` сам сделает).
- `gosnmp.Version1` поддерживается, но без TRAP'ов и без community-string в строгой проверке — для MVP «good enough».
- Нормализация всегда применяется ОДИН раз и в фиксированном порядке: cast → interpolation → factor → offset. Поменять порядок нельзя — это инженерный контракт.
- Если `RawMin == RawMax` (zero-divide) — пропустить interpolation, продолжить с factor/offset, лог `warn` один раз per tag (через sampler — не на каждое Read).
- `raw.readings` — best-effort. Падение этого топика **никогда** не должно блокировать `tags.values`.
- `tags.values` — критичный. Если Kafka недоступна — Reading теряются (приемлемо для MVP). НЕ городить локальную очередь/диск-буфер в этом спеке.
- Паpтиционирование `tags.values` строго `key = tag_id`. Это контракт с ms-viewer.
- Все timestamps — UTC, RFC3339Nano (`time.Format(time.RFC3339Nano)`).
- НЕ публиковать пустые батчи: если `len(readings) == 0` — `return nil` сразу.
- Один Kafka writer (topic) на сервис. `kafka.Writer` thread-safe, `Publish` можно звать из разных goroutine.
- Никаких метрик/Prometheus в этом спеке — Phase 4.8.
- Не трогать ms-viewer. Контракт топика `tags.values` фиксируется этим спеком; consumer пишет ms-viewer отдельно.

## Verify

- `cd ms-poll && go mod tidy && go build ./... && go vet ./...` зелёное.
- Юнит-тесты `snmp/snmp_test.go`:
  - `DecodePDU` для каждого ASN.1 типа из таблицы.
  - `NoSuchObject` → error.
  - Integer + data_type=`bool` → false для 0, true для 1.
- Юнит-тесты `usecase/normalize_test.go`:
  - cast int16 → int64 (data_type=int16): value=42 → int64(42).
  - cast float32 → float64 (data_type=float32, scaling=nil): value=float32(1.5) → float64(1.5), RawValue=float32(1.5).
  - scaling interpolation: raw_min=0, raw_max=4095, eng_min=0, eng_max=100, value=2048 → ≈50.0 ±0.05.
  - scaling factor+offset: factor=0.1, offset=-40, value=850 → 45.
  - cast bad → Quality=bad, Error содержит "cast".
  - Quality=bad на входе → reading возвращается без изменений.
  - tag.Scaling=nil → значение проходит только через cast.
- Юнит-тест `kafka/serialize_test.go`:
  - Reading с float64 + good → JSON содержит `"value": 50` (число), `"quality":"good"`.
  - Reading с bool + good → `"value": true`.
  - Reading с bad + Error="timeout" → `"value": null, "quality":"bad", "error":"timeout"`.
- E2E: запустить все три сервиса (ms-editor, ms-poll, Kafka). Создать SNMP-устройство и тег:
  - В логе ms-poll: `device started type=snmp_v2c`.
  - `kafkacat -b localhost:9092 -t tags.values -C` показывает раз в секунду JSON с `tag_id`, `value`, `quality=good`.
  - При остановке SNMP-агента — сообщения с `quality=bad, error="..."`.
- Включить `MS_POLL_PUBLISH_RAW_READINGS=true`:
  - В `raw.readings` появляются параллельные сообщения с `raw_value` и `value_type`.
  - Падение `raw.readings` (например, неверный topic) не останавливает `tags.values`.
- Сценарий с scaling:
  - Тег с raw_min/max=0..4095, eng_min/max=0..100, factor=1, offset=0.
  - Modbus устройство возвращает 2048 → в Kafka летит `"value": 50.012...`.
  - Удалить scaling → следующее значение `"value": 2048`.
