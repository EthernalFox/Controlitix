# Controlitix — Основные бизнес‑сущности (MVP)

Этот раздел фиксирует ключевые сущности домена и их минимальные атрибуты/связи в **MVP**. Формулировки даны на бизнес‑уровне; физическая модель БД и API‑контракты описываются отдельно.

## Объект мониторинга (`MonitoringObject`)

**Назначение:** Логическая «площадка» наблюдения (ЦОД, узел, помещение).  
**Ключевые атрибуты:** `id`, `name`, `description`.  
**Связи:**

- 1 → N **Мнемосхема** (`MimicDiagram`)
- 1 → N **Устройство** (`Device`)

## Мнемосхема (`MimicDiagram`)

**Назначение:** Графическое представление объекта для операторов/инженеров.  
**Ключевые атрибуты:** `id`, `object_id`, `name`, `description`, `published_at` (в MVP хранится текущее состояние без версий).  
**Связи:**

- N → 1 **Объект мониторинга**
- 1 → N **Фигура** (`Figure`)

## Фигура (`Figure`)

**Назначение:** Элемент мнемосхемы (примитив или виджет).  
**Ключевые атрибуты:** `id`, `mimic_id`, `type`, `params` (JSONB — геометрия/стиль и пр.).  
**Связи:**

- N → 1 **Мнемосхема**
- 0..1 → 1 **Тег** (`Tag`) — привязка данных для динамики (цвет/видимость в MVP).

## Устройство (`Device`)

**Назначение:** Источник данных (Modbus TCP/RTU, SNMP). Принадлежит одному объекту, может использоваться на нескольких схемах этого объекта.  
**Ключевые атрибуты:** `id`, `object_id`, `name`, `device_type`, `settings` (JSONB с параметрами протокола), `created_at`, `updated_at`.  
**Связи:**

- N → 1 **Объект мониторинга**
- 1 → N **Тег** (`Tag`)

## Тип устройства (`DeviceType`)

**Назначение:** Категоризация устройства и схема сериализации его настроек (`settings`).  
**Ключевые атрибуты:** `id`, `code`, `name`, `schema_ref` (описание структуры JSONB).  
**Связи:**

- 1 → N **Устройство**

## Тег (`Tag`)

**Назначение:** Измеряемый/дискретный параметр, считываемый с устройства.  
**Ключевые атрибуты:** `id`, `device_id`, `name`, `description`, `created_at`, `updated_at`.  
**Связи:**

- N → 1 **Устройство**
- 1 → 1 **Параметры тега** (`TagParams`)
- 0..1 → 1 **Масштабирование** (`TagScaling`)
- 0..1 → 1 **Уставки** (`TagSetpoints`)
- 0..N ← **Фигура** (фигура может ссылаться на тег)

## Параметры тега (`TagParams`)

**Назначение:** Адресация и тип данных тега.  
**Ключевые атрибуты:**

- Общие: `tag_id`, `data_type`, `unit`
- **Modbus:** `address` (hex, нулевой базис), `registerType` (coil/discrete/holding/input)
- **SNMP:** `oid` (строка)  
  **Связи:**
- 1 → 1 **Тег**
- N → 1 **Единица измерения** (`Unit`) — по необходимости через справочник
- N → 1 **Тип данных** (`DataType`) — через справочник

## Масштабирование (`TagScaling`)

**Назначение:** Преобразование «сырых» значений в инженерные.  
**Ключевые атрибуты:** `tag_id`, `min_value`, `max_value`, `factor` (или `scale/offset` по принятой модели).  
**Связи:**

- 1 → 1 **Тег**

## Уставки (`TagSetpoints`)

**Назначение:** Пороговые уровни для трактовки значения.  
**Ключевые атрибуты:** `tag_id`, `lolo`, `lo`, `hi`, `hihi` (набор в MVP).  
**Связи:**

- 1 → 1 **Тег**

## Тип данных (`DataType`)

**Назначение:** Нормализованный список типов значений.  
**Значения MVP:** `bool, int16, int32, uint16, uint32, float, double, string`.  
**Связи:**

- 1 → N **Параметры тега**

## Единица измерения (`Unit`)

**Назначение:** Отображение и интерпретация инженерных величин.  
**Примеры:** `°C, V, A, kW, MW, %` и др.  
**Связи:**

- 1 → N **Параметры тега**

## Пользователь (минимально, для контекста MVP)

**Назначение:** Аутентификация и базовые права доступа (тонкий RBAC отложен).  
**Ключевые атрибуты:** `id`, `email`, `name`, `role` (admin/integrator/operator — упрощённо).  
**Связи:**

- Используется `editor-ui`/`ms-editor` для разграничения режимов редактирования.

---

### Кардинальности (сводно)

- **MonitoringObject 1 → N MimicDiagram**
- **MimicDiagram 1 → N Figure**
- **MonitoringObject 1 → N Device**
- **Device 1 → N Tag**
- **Tag 1 → 1 TagParams**
- **Tag 0..1 → 1 TagScaling**
- **Tag 0..1 → 1 TagSetpoints**
- **Figure 0..1 → 1 Tag**

> Примечание: Export/Import, версии схем и расширенные роли — вне MVP и описываются отдельно.
