# 0013: ms-poll — загрузка и кэш конфигурации опроса

## Scope

`ms-poll`. Этот спек добавляет источник конфигурации: чтение графа `device → tag → params → scaling/setpoints` из PostgreSQL, in-memory snapshot и обработчик `config.changed`, который обновляет snapshot.
Никакого опроса всё ещё нет — здесь только структуры данных и их жизненный цикл. Планировщик и драйверы появятся в спеке 0014.

## Context

- Базовый каркас: спек [`0012.ready.ms-poll-skeleton.md`](0012.ready.ms-poll-skeleton.md).
- Источник правды: схемы `devices.*`, `tags.*` (см. `ms-editor/migrations/000002_devices_tags_schemas.sql`).
- Формат `address` (JSONB) и `settings` (JSONB) определяются типом устройства (`devices.device_type.name`):
  - `modbus_tcp`, `modbus_rtu` → tag.address: `{"register_type":"holding|input|coil|discrete","address":40001}`. Для `modbus_rtu` device.settings содержит `unit_id`, для `modbus_tcp` — host/port.
  - `snmp_v1`, `snmp_v2c`, `snmp_v3` → tag.address: `{"oid":"1.3.6.1.2.1.1.1.0"}`.
  - В этом спеке мы парсим address/settings в `json.RawMessage` и **не валидируем содержимое** — детальный парсинг будет в драйверах (0015, 0016). Snapshot хранит JSON «как есть».
- ConfigChangedEvent: `entity_type ∈ {device, tag, monitoring_object, diagram, figure, ...}`, `operation ∈ {create, update, delete}`. Для cache интересны только `device` и `tag`.

## Interface

### Snapshot

```go
package domain

type DeviceSnapshot struct {
    ID         string          // uuid
    ObjectID   *string
    TypeID     int
    TypeName   string          // modbus_tcp | modbus_rtu | snmp_v1 | snmp_v2c | snmp_v3
    Name       string
    Settings   json.RawMessage // raw JSONB; драйверы парсят сами
    UpdatedAt  time.Time
}

type TagSnapshot struct {
    ID         string          // uuid
    DeviceID   string
    Name       string
    DataType   string          // bool|int8|...|float64|string
    UnitSymbol *string
    Address    json.RawMessage // raw JSONB
    Scaling    *TagScaling     // nil, если строки в tags.tag_scaling нет
    Setpoints  *TagSetpoints   // аналогично
    UpdatedAt  time.Time
}

type TagScaling struct {
    RawMin, RawMax, EngMin, EngMax *float64
    Factor, Offset                 *float64
}

type TagSetpoints struct {
    LoLo, Lo, Hi, HiHi *float64
}

type Snapshot struct {
    Devices map[string]*DeviceSnapshot       // device_id -> device
    Tags    map[string]*TagSnapshot          // tag_id -> tag
    TagsByDevice map[string][]*TagSnapshot   // device_id -> [...tags]
    LoadedAt time.Time
}
```

Snapshot **immutable после возврата из store**: store при изменениях создаёт новый объект Snapshot с обновлёнными map'ами (copy-on-write). Это упростит планировщик в 0014.

### Repository

```go
package repository

type ConfigRepository struct { /* *sql.DB */ }

func NewConfigRepository(db *sql.DB) *ConfigRepository

func (r *ConfigRepository) LoadAll(ctx context.Context) (*domain.Snapshot, error)
func (r *ConfigRepository) LoadDevice(ctx context.Context, id string) (*domain.DeviceSnapshot, error)
func (r *ConfigRepository) LoadTag(ctx context.Context, id string) (*domain.TagSnapshot, error)
```

SQL-запросы:

- `LoadAll`:
  ```sql
  SELECT d.id, d.object_id, d.type_id, dt.name, d.name,
         COALESCE(p.settings, '{}'::jsonb) AS settings,
         d.updated_at
    FROM devices.devices d
    JOIN devices.device_type dt ON dt.id = d.type_id
    LEFT JOIN devices.devices_params p ON p.device_id = d.id
   WHERE d.deleted_at IS NULL;
  ```
  ```sql
  SELECT t.id, t.device_id, t.name,
         dty.name AS data_type, u.symbol AS unit_symbol,
         tp.address,
         sc.raw_min, sc.raw_max, sc.eng_min, sc.eng_max, sc.factor, sc."offset",
         sp.lolo, sp.lo, sp.hi, sp.hihi,
         t.updated_at
    FROM tags.tags t
    JOIN tags.tag_params tp ON tp.tag_id = t.id
    JOIN tags.data_types dty ON dty.id = tp.data_type_id
    LEFT JOIN tags.units u ON u.id = tp.unit_id
    LEFT JOIN tags.tag_scaling sc ON sc.param_id = tp.id
    LEFT JOIN tags.tag_setpoints sp ON sp.param_id = tp.id
   WHERE t.device_id = ANY($1) AND t.deleted_at IS NULL;
  ```
  Сначала тянем устройства, затем теги одним запросом по списку device IDs.
- `LoadDevice` / `LoadTag` — по одной сущности, фильтр по id и `deleted_at IS NULL`.
- Если `LoadDevice`/`LoadTag` не находит запись — возвращать `(nil, nil)` (это может быть soft-delete).

### Snapshot store

```go
package usecase

type SnapshotStore struct { /* sync.RWMutex + *domain.Snapshot */ }

func NewSnapshotStore() *SnapshotStore
func (s *SnapshotStore) Get() *domain.Snapshot
func (s *SnapshotStore) Replace(next *domain.Snapshot)

// Целевые мутации (атомарные copy-on-write):
func (s *SnapshotStore) UpsertDevice(d *domain.DeviceSnapshot)
func (s *SnapshotStore) RemoveDevice(deviceID string)        // также удаляет все теги устройства
func (s *SnapshotStore) UpsertTag(t *domain.TagSnapshot)
func (s *SnapshotStore) RemoveTag(tagID string)
```

Мутации перестраивают `TagsByDevice` для затронутых device_id.

### Config loader

```go
package usecase

type ConfigLoader struct { /* repo + store + logger */ }

func NewConfigLoader(repo *repository.ConfigRepository, store *SnapshotStore, logger *slog.Logger) *ConfigLoader
func (l *ConfigLoader) Load(ctx context.Context) error
```

`Load` делает `repo.LoadAll`, замеряет длительность, логирует `info` с `devices_count` и `tags_count`, кладёт в store через `Replace`.

### Config event handler

```go
package usecase

type ConfigEventHandler struct { /* repo + store + logger */ }

func NewConfigEventHandler(repo *repository.ConfigRepository, store *SnapshotStore, logger *slog.Logger) *ConfigEventHandler
func (h *ConfigEventHandler) Handle(ctx context.Context, event domain.ConfigChangedEvent) error
```

Логика `Handle`:

| entity_type | operation        | действие                                                                                  |
|-------------|------------------|-------------------------------------------------------------------------------------------|
| `device`    | `create/update`  | `repo.LoadDevice(id)` → `store.UpsertDevice(...)`. Если `nil` — `store.RemoveDevice(id)`. |
| `device`    | `delete`         | `store.RemoveDevice(id)` (каскадно убирает теги).                                         |
| `tag`       | `create/update`  | `repo.LoadTag(id)` → `store.UpsertTag(...)`. Если `nil` — `store.RemoveTag(id)`.          |
| `tag`       | `delete`         | `store.RemoveTag(id)`.                                                                    |
| иное        | любое            | лог `debug` («ignored entity_type»), возврат `nil`.                                       |

Ошибка от репозитория → возврат `error` (consumer не закоммитит offset → перечитает на следующей итерации). Это ОК, потому что обработчик идемпотентен.

### Health update

`/readyz` отвечает 200, только если `store.Get()` ≠ nil **и** загружен (`LoadedAt != zero`). Иначе — 503 `{"status":"degraded","reason":"snapshot not loaded"}`.

## Constraints

- Только SELECT — никаких INSERT/UPDATE/DELETE в `repository` пакете.
- Snapshot мутации — atomic swap через `sync.RWMutex`. Никакого in-place мутирования возвращённого snapshot'а вне store.
- Не парсить `address` JSONB и `settings` JSONB здесь — оставляем `json.RawMessage`. Парсинг — задача драйверов в 0015/0016.
- Не лочить consumer на время `LoadAll` — `Load` вызывается ОДИН раз на старте; обработчик событий работает по одной сущности.
- Если `repo.LoadAll` упал на старте — `os.Exit(1)`. Если упал при обработке события — возвращаем error из handler, не паникуем.
- Не вводить Redis в этом спеке — он не нужен, snapshot целиком помещается в RAM (см. НФТ: <100k тегов).
- Не вводить дебаунс/батчинг событий — реакция на изменения должна быть мгновенной (≤2 сек p95 — общий бюджет латентности).
- Не трогать существующие файлы спека 0012 кроме `cmd/ms-poll/main.go` и `internal/api/http/health.go`.
