# 0023: ms-auth — service-token + admin CRUD users/roles/ТУЗ

## Scope

`ms-auth`. Завершающий спек серии. Добавляет:

- `POST /api/auth/service-token` — client_credentials grant для межсервисной аутентификации.
- `GET /api/auth/admin/*` — CRUD пользователей, назначение ролей, CRUD ТУЗ, чтение audit, список ролей/источников.
- Админ-действия пишутся в `auth.audit_log` и Kafka `audit.logs`.

После этого спека `ms-auth` функционально полон для MVP.

## Interface

### Middleware RequireRole

```go
// RequireRole отклоняет запросы с Principal, в чьём Roles нет хотя бы одной из requiredRoles.
// В случае отсутствия роли — 403 /errors/auth/forbidden.
func RequireRole(requiredRoles ...string) func(http.Handler) http.Handler
```

Используется ПОСЛЕ `RequireAuth` — Principal уже в контексте.

### Service-token handler

```go
// POST /api/auth/service-token
// Body: grant_type, client_id, client_secret, scope?
type serviceTokenRequest struct {
    GrantType    string `json:"grant_type"`
    ClientID     string `json:"client_id"`
    ClientSecret string `json:"client_secret"`
    Scope        string `json:"scope,omitempty"` // space-separated
}
```

Алгоритм:

```
1. Декод body. Если grant_type != "client_credentials" → 400 /errors/auth/unsupported-grant.
2. acc := serviceAccountRepo.FindByClientID(ClientID).
   Если nil → 401 /errors/auth/invalid-client.
   audit(service_token.failure, reason="unknown_client", target=ClientID).
3. hasher.Verify(ClientSecret, acc.ClientSecretHash) → false → 401 /errors/auth/invalid-client.
   audit(service_token.failure, reason="invalid_secret", target=ClientID).
4. Если !acc.IsActive → 403 /errors/auth/client-disabled.
5. Разрешение scope:
     requested := strings.Fields(Scope)
     if len(requested) == 0: granted = acc.Scopes (все разрешённые)
     else:
        for each s in requested: должен быть в acc.Scopes, иначе 400 invalid-scope.
        granted = requested.
6. tokens := tokenService.IssueForService(ctx, ClientID, granted, meta).
7. serviceAccountRepo.UpdateLastUsed(acc.ID, now()).
8. audit(service_token.success, actor="svc:"+ClientID, target=ClientID).
9. Тело ответа: {access_token, token_type, expires_in, scope: strings.Join(granted, " ")}.
```

### AdminService

Одна точка с валидацией и audit-записью. Пример:

```go

    users    *repository.UserRepository
    services *repository.ServiceAccountRepository
    sources  *repository.IdentitySourceRepository
    audit    *usecase.AuditService
    refresh  *repository.RefreshTokenRepository
    hasher   *password.Hasher
    logger   *slog.Logger
    clock    func() time.Time
    rand     io.Reader
}

func (s *AdminService) CreateUser(ctx, actorSubject string, req CreateUserInput) (*domain.User, error)
func (s *AdminService) UpdateUser(ctx, actor, userID string, req UpdateUserInput) (*domain.User, error)
func (s *AdminService) DeactivateUser(ctx, actor, userID string) error      // is_active=false + revoke all refresh
func (s *AdminService) SetUserRoles(ctx, actor, userID string, roles []string) error
func (s *AdminService) RemoveUserRole(ctx, actor, userID, role string) error
func (s *AdminService) RevokeUserSessions(ctx, actor, userID string) error

func (s *AdminService) CreateServiceAccount(ctx, actor string, req CreateServiceAccountInput) (*domain.ServiceAccount, plaintextSecret string, err error)
func (s *AdminService) RotateServiceAccountSecret(ctx, actor, id string) (newSecret string, err error)
func (s *AdminService) UpdateServiceAccount(ctx, actor, id string, req UpdateServiceAccountInput) error
func (s *AdminService) DeleteServiceAccount(ctx, actor, id string) error
```

Валидация ролей при `SetUserRoles` / `CreateUser`: все в `domain.AllowedRoles`. Иначе — 422 validation.

Создание ТУЗ:

- `ClientID` — `^[a-z][a-z0-9-]{2,63}$` (kebab-case, строчные).
- `Scopes` — список строк без пробелов, уникальные. В MVP не проверяем содержимое scope против whitelist (каждый сервис сам решает, какие scope понимает). Но документируем рекомендуемые значения в API-doc: `config.read`, `tags.values.write`, `alarms.events.write`.
- Секрет генерируется сервисом: 32 случайных байта → base64url. В ответе отдаётся ровно один раз.

### Паджинейшн / фильтры

- `?offset=<>&limit=<>`; limit 1..200 (default 50).
- Для `GET /admin/users` — фильтр `q` по `username`/`email` через `ILIKE '%q%'`, фильтр `source_id`, `is_active`.
- Для `GET /admin/audit` — `action` (точное совпадение), `actor` (точное по `actor_subject`), `from`/`to` (RFC3339).
- Ответ — `{data:[...], total, offset, limit}` (в стиле ms-editor).

## Constraints

- Все admin-ручки обязательно за `RequireAuth(keystore, AudienceUser)` + `RequireRole("admin")`.
- Service-token handler требует только валидный body — НЕ за RequireAuth (это сам get-token).
- Service-token — `aud=controlitix-internal`, никогда не `controlitix-api`. (Уже в TokenService, проверить.)
- Admin НЕ может менять свои роли (`SetUserRoles` для self с исключением роли `admin` → 409 `/errors/auth/forbidden-self-demote`). Это чтобы случайно не оставить систему без админов.
- **Минимум один активный admin:** при `DeactivateUser` и при `RemoveUserRole admin` проверять, что останется хотя бы один другой активный admin. Иначе 409 `/errors/auth/last-admin`.
- Удалить admin-пользователя полностью (hard delete) нельзя в MVP — только `DeactivateUser` (is_active=false + revoke all refresh). Это безопаснее для аудита.
- `client_secret` никогда не хранится в plain — только Argon2id-хэш через тот же `password.Hasher`.
- `ClientID` уникален (констрейнт из миграции 0019), попытка создать дубликат → 409 `/errors/conflict/client-id-exists`.
- `RotateServiceAccountSecret` не инвалидирует ранее выпущенные service-JWT (у них TTL 15 мин) — это MVP-допуск. При компрометации — `DeleteServiceAccount` + срок жизни ≤ 15 мин.
- Никаких полей `password` в ответах. Никаких `client_secret` кроме моментов create/rotate.
- Identity-sources CRUD — возвращает 501 `/errors/not-implemented` для POST/PATCH/DELETE; GET работает (пользуется существующим репозиторием).
- Role-mappings — аналогично, GET всегда возвращает `{data:[]}`.
- Не трогать `/login`, `/refresh`, `/logout`, `/userinfo` — они уже в 0022.
- Не добавлять MFA, password reset.
- Не добавлять soft-delete для service-accounts — `Delete` = hard delete (ТУЗ меньше и проще пересоздать).
