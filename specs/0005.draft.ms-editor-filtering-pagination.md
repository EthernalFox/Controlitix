# 0005: ms-editor — Filtering, pagination, search

## Scope

`ms-editor/internal/` — domain, usecase, api/http, infrastructure/repository.

## Context

Current list endpoints return all rows without filtering or pagination. At scale (250 devices, 2500 tags, 50 diagrams) this is inefficient. This task adds offset/limit pagination and filters (by id, name, type) to all list endpoints.

Prerequisite: specs 0003, 0004 (device and tag CRUD).

## Interface

### Query structs

```go
// domain/query.go

type Pagination struct {
    Offset int  // default 0
    Limit  int  // default 50, max 200
}

type ListResult[T any] struct {
    Items  []T `json:"items"`
    Total  int `json:"total"`   // total count matching filters (before pagination)
    Offset int `json:"offset"`
    Limit  int `json:"limit"`
}

type ObjectListQuery struct {
    Pagination
    Search string  // ILIKE on name
}

type DeviceListQuery struct {
    Pagination
    ObjectID *string // filter by object_id (exact)
    TypeID   *int    // filter by type_id (exact)
    Search   string  // ILIKE on name
}

type TagListQuery struct {
    Pagination
    DeviceID   *string // filter by device_id (exact)
    DataTypeID *int    // filter by data_type_id (exact)
    Search     string  // ILIKE on name
}

type DiagramListQuery struct {
    Pagination
    ObjectID *string // filter by object_id (exact)
    Search   string  // ILIKE on name
}

type FigureListQuery struct {
    Pagination
    DiagramID string  // required — figures always filtered by diagram
    TypeFilter *string // filter by figure type
}
```

### HTTP query parameters

All list endpoints accept these common params:

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `offset` | int | 0 | Skip N records |
| `limit` | int | 50 | Return max N records (capped at 200) |
| `search` | string | "" | Case-insensitive substring match on `name` |

Entity-specific filters:

| Endpoint | Extra params |
|----------|-------------|
| `GET /objects` | — |
| `GET /objects/{id}/devices` | `type_id` (pre-filled object_id from path) |
| `GET /devices` | `object_id`, `type_id` |
| `GET /devices/{id}/tags` | `data_type_id` (pre-filled device_id from path) |
| `GET /tags` | `device_id`, `data_type_id` |
| `GET /objects/{id}/diagrams` | (pre-filled object_id from path) |
| `GET /diagrams/{id}/figures` | `type` (pre-filled diagram_id from path) |

**New top-level endpoints** (needed for cross-object search):
- `GET /devices` — list all devices with filters (object_id, type_id, search).
- `GET /tags` — list all tags with filters (device_id, data_type_id, search).

### Response wrapper

All list endpoints change their response from `[]entity` to:

```json
{
  "items": [...],
  "total": 127,
  "offset": 0,
  "limit": 50
}
```

### HTTP model

```go
type listResponse[T any] struct {
    Items  []T `json:"items"`
    Total  int `json:"total"`
    Offset int `json:"offset"`
    Limit  int `json:"limit"`
}
```

Note: since Go generics cannot be used directly in JSON serialization with the existing pattern, implement `listResponse` as a concrete struct or use `any` for Items:

```go
type listResponse struct {
    Items  any `json:"items"`
    Total  int `json:"total"`
    Offset int `json:"offset"`
    Limit  int `json:"limit"`
}
```

## Constraints

- Pagination defaults: offset=0, limit=50, max limit=200. If limit > 200, clamp to 200.
- Negative offset or limit → 400 Bad Request.
- `search` uses `WHERE name ILIKE '%' || $1 || '%'`. Escape `%` and `_` in the search term to prevent SQL pattern injection.
- `total` is the count of rows matching all filters, **before** offset/limit. Use `COUNT(*) OVER()` or a separate count query.
- All list endpoints must exclude soft-deleted records.
- `GET /objects/{id}/devices` and `GET /devices` share the same handler logic — the path-based version pre-fills `object_id`.
- Similarly for tags and diagrams.
- Preserve backwards compatibility for `GET /diagrams/{id}/figures` (still requires diagram_id).
- Sorting: `ORDER BY created_at DESC` as default. No custom sort in this spec.

## Verify

- `go build ./...` passes.
- `GET /objects?offset=0&limit=10` returns `{"items":[...],"total":N,"offset":0,"limit":10}`.
- `GET /objects?search=ЦОД` returns only objects with "ЦОД" in name.
- `GET /devices?object_id={id}&type_id=1` returns only modbus_rtu devices of that object.
- `GET /tags?search=Temp&limit=5` returns max 5 tags matching "Temp".
- `GET /devices?limit=999` returns with `"limit":200` (clamped).
- `GET /tags?offset=-1` returns 400.
- `total` reflects full count, not just the page size.
- All existing tests/clients that called list endpoints must be updated to expect the new wrapper format.
