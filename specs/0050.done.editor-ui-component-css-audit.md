# 0050: editor-ui — Component & Pages CSS Audit (токен-driven)

## Scope

`editor-ui/src/shared/ui/components/`  
`editor-ui/src/pages/`  
`editor-ui/src/features/`  
`editor-ui/src/widgets/`

## Context

После спек 0047–0049 токен-система переведена на Mantine 8 `cssVariablesResolver`. Все компонентные `.module.css` и inline-стили до сих пор ссылаются на устаревшее пространство имён (`--bg-*`, `--text-*`, `--border-*`, `--accent-*`, `--alarm-*` без `mantine-` или `ctrx-` префикса). Цель — вычистить старые ссылки и перевести на две правильные группы:

- `var(--mantine-color-*)` / `var(--mantine-spacing-*)` / `var(--mantine-radius-*)` — стандартная Mantine механика.
- `var(--ctrx-*)` — только то, чего Mantine не покрывает: alarm, glass, canvas, orbs.

Зависимости: **выполнять после** спек 0047, 0048, 0049.

### Паттерн использования

**Приоритет при выборе токена:**

1. Если это Mantine-компонент — не стилизуй его CSS vars вручную, используй `classNames`, `styles` props или `components` override в `createTheme()`.
2. `var(--mantine-*)` — для кастомных CSS-модулей, где нужны стандартные значения (spacing, radius, border, text, body bg).
3. `var(--ctrx-*)` — только для alarm, glass, canvas, orbs.
4. Никаких hex / rgba() напрямую.

**Корректные примеры:**
```css
/* spacing и радиус */
.panel   { padding: var(--mantine-spacing-md); border-radius: var(--mantine-radius-sm); }
.item    { gap: var(--mantine-spacing-xs); }

/* поверхности */
.card    { background: var(--mantine-color-default); border: 1px solid var(--mantine-color-default-border); }
.page    { background: var(--mantine-color-body); }

/* текст */
.label   { color: var(--mantine-color-dimmed); }
.value   { font-family: var(--mantine-font-family-monospace); }

/* проект-специфика */
.canvas  { background: var(--ctrx-canvas-bg); }
.grid    { stroke: var(--ctrx-canvas-grid); }
.glass   { background: var(--ctrx-glass-bg); backdrop-filter: var(--ctrx-glass-blur); }
.alarm   { color: var(--ctrx-alarm-crit); }
```

## Constraints

- Не вносить изменений в логику `.tsx`-файлов — только CSS-модули.
- Один коммит на компонентный слой (`shared/ui/`), отдельный на страницы (`pages/`, `features/`).
- Не добавлять новые CSS-классы — только замена значений переменных.
- Если в Layout-файлах встречается старый `var(--glass-*)` (до spec 0049) — заменить на `var(--ctrx-glass-*)`.
- Mantine-компоненты (TextInput, Button, etc.) управляют своими hover/focus/disabled состояниями сами — не дублировать через CSS vars.
