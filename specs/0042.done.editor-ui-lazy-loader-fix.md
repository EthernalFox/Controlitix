# 0042: editor-ui — Fix lazyLoader: статический динамический импорт через importer-фабрику

## Scope

`editor-ui/src/shared/libs/router/`:
- `LazyLoader.ts` — переписать, принимать importer-фабрику вместо строки.
- `routes.ts` — обновить все call-sites под новый API.

Out of scope: миграция на `import.meta.glob`, изменение route-структуры, ленивая загрузка чего-либо за пределами роутера.

## Context

Текущая реализация:

```ts
// editor-ui/src/shared/libs/router/LazyLoader.ts
export const lazyLoader =
  (importPath: string): LazyRouteFunction<RouteObject> =>
  async () => {
    const module = await import(importPath);
    return { Component: module.default };
  };
```

Использование:

```ts
// editor-ui/src/shared/libs/router/routes.ts
{ path: routePaths.objects, lazy: lazyLoader("../../../pages/ObjectsPage") }
```

### Почему это не работает

1. **Vite/Rollup не статически анализирует `import(<runtime-string>)`.** Документация: <https://vite.dev/guide/features.html#dynamic-import>. Bundler видит `import(importPath)` где `importPath` — параметр функции, и не может на этапе сборки создать отдельный chunk для целевого модуля. В рантайме браузер вызывает нативный `import()` с строкой, которая указывает на путь, отсутствующий в манифесте.
2. **Относительные пути `"../../../pages/..."` резолвятся от URL вызывающего модуля.** В dev-режиме (Vite middleware) это иногда срабатывает, но с непредсказуемыми результатами; в production-билде — никогда, потому что после хэширования URL chunk’а не совпадает с исходной структурой каталогов.
3. **На старте навигации** (например, переход на `/objects`) роутер выбрасывает `TypeError: Failed to fetch dynamically imported module`. Если включён error boundary — пользователь видит fallback; иначе — белый экран.
4. Vite на build выдаёт warning: «The above dynamic import cannot be analyzed by Vite». Этот warning сейчас, по всей видимости, проигнорирован или подавлен.

### Правильный подход

Нативный `import("@pages/ObjectsPage")` со **статической** строкой Vite видит, создаёт под неё отдельный chunk и пишет в манифест. Чтобы сохранить декларативный стиль роутов и хелпер `lazyLoader`, передаём не строку-путь, а **importer-функцию** (`() => import(...)`). Внутри функции литерал виден парсеру, статический анализ работает.

Этот паттерн — стандарт de-facto для React Router 6/7 + Vite ([React Router lazy docs](https://reactrouter.com/start/library/route-objects#lazy)).

## Interface

### Новый `LazyLoader.ts`

```ts
import type { ComponentType } from "react";
import type { LazyRouteFunction, RouteObject } from "react-router";

type LoadedRouteModule = { default: ComponentType };

type RouteImporter = () => Promise<LoadedRouteModule>;

export const lazyLoader =
  (importer: RouteImporter): LazyRouteFunction<RouteObject> =>
  async () => {
    const module = await importer();

    if (!module.default) {
      throw new Error(
        "lazyLoader: imported module has no default export — did you forget `export default`?",
      );
    }

    return {
      Component: module.default,
    };
  };
```

Требования к реализации:

- Тип `LoadedRouteModule` явно требует `default: ComponentType` — проверка на этапе TS-компиляции (если страница случайно экспортирует named-only — будет TS-ошибка на call-site).
- В рантайме на всякий случай — explicit guard с понятным сообщением. Эта проверка пригодится при перезапуске dev-сервера, когда модуль может вернуть пустой объект из-за HMR-инвалидации.
- Никаких runtime-параметров-строк в сигнатуре. Только функция-фабрика.

### Новый `routes.ts`

```ts
import { createElement } from "react";
import { Navigate, type RouteObject } from "react-router";

import { lazyLoader } from "./LazyLoader";

export const routePaths = {
  objects: "/objects",
  objectDetail: "/objects/:objectId",
  objectDevices: "/objects/:objectId/devices",
  objectTags: "/objects/:objectId/tags",
  objectDiagrams: "/objects/:objectId/diagrams",
  diagramEditor: "/objects/:objectId/diagrams/:diagramId/edit",
} as const;

export const routes: RouteObject[] = [
  {
    path: "/",
    element: createElement(Navigate, { to: routePaths.objects, replace: true }),
  },
  {
    lazy: lazyLoader(() => import("@widgets/ListLayout")),
    children: [
      {
        path: routePaths.objects,
        lazy: lazyLoader(() => import("@pages/ObjectsPage")),
        handle: { title: "Объекты мониторинга" },
      },
      {
        path: routePaths.objectDetail,
        lazy: lazyLoader(() => import("@pages/ObjectDetailPage")),
        handle: { title: "Объект" },
        children: [
          {
            index: true,
            element: createElement(Navigate, { to: "devices", replace: true }),
          },
          {
            path: "devices",
            lazy: lazyLoader(() => import("@pages/DevicesPage")),
            handle: { title: "Устройства" },
          },
          {
            path: "tags",
            lazy: lazyLoader(() => import("@pages/TagsPage")),
            handle: { title: "Теги" },
          },
          {
            path: "diagrams",
            lazy: lazyLoader(() => import("@pages/DiagramsPage")),
            handle: { title: "Мнемосхемы" },
          },
        ],
      },
    ],
  },
  {
    path: routePaths.diagramEditor,
    lazy: lazyLoader(() => import("@pages/EditorPage")),
    handle: { title: "Редактор" },
  },
];
```

Замены:
- `lazyLoader("../../../widgets/ListLayout")` → `lazyLoader(() => import("@widgets/ListLayout"))`.
- `"../../../pages/ObjectsPage"` → `"@pages/ObjectsPage"`.
- Аналогично для `ObjectDetailPage`, `DevicesPage`, `TagsPage`, `DiagramsPage`, `EditorPage`.

Алиасы `@pages` / `@widgets` уже зафиксированы в `editor-ui/vite.config.ts` и `editor-ui/tsconfig.json` (paths) — менять конфиг не нужно.

### Sanity-check для целевых страниц

Каждый из импортируемых модулей обязан иметь `export default`. Проверить вручную:

- `editor-ui/src/widgets/ListLayout/index.ts` (если export через barrel) или `editor-ui/src/widgets/ListLayout/ListLayout.tsx` — должен иметь `export default ListLayout` или re-export.
- `editor-ui/src/pages/ObjectsPage/index.ts` / `.tsx` — то же.
- `editor-ui/src/pages/ObjectDetailPage`, `DevicesPage`, `TagsPage`, `DiagramsPage`, `EditorPage` — то же.

Если какой-то модуль не имеет `export default` — добавить его в том же PR (либо `export { Foo as default }` в barrel, либо `export default Foo` в самом компоненте).

## Constraints

- **Не использовать** `import.meta.glob` — это другой паттерн (eager/lazy map), требует отдельного слоя кэширования и не нужен для статически известного списка из 7 роутов.
- **Не использовать** `/* @vite-ignore */` для подавления warning — это маскировка проблемы, не исправление.
- **Сохранить идентичность API роутера**: набор `path/handle/children` не меняется, меняются только значения `lazy:`.
- **Не трогать** `app/providers/RouterProvider/` — он принимает `routes` как есть.
- Не вводить error-boundary в этой спеке — это отдельная задача.
- Не добавлять `Suspense fallback` в этом коммите — RR7 `lazy` сам обрабатывает loading-состояние.
