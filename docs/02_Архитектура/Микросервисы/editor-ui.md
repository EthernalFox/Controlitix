# editor-ui — фронтенд редактора (MVP)

## Назначение

Единый интерфейс инженера для редактирования объектов, устройств, тегов, мнемосхем и фигур. Через этот UI инженер сначала настраивает объект и его устройства, затем использует созданные теги для привязки к фигурам и ручной публикации текущего состояния схемы (без версионности).

## Стек

- React 18.2
- TypeScript 5
- Zustand (история действий и локальное состояние редактора)
- KonvaJS (canvas-редактор; поддерживаются базовые фигуры Konva)
- Mantine UI 8 (панели, формы, диалоги)

## Интеграции

- REST к `ms-editor` — конфигурация объектов, устройств, тегов, мнемосхем и фигур.

## Основные функции (входит в MVP)

1. **Работа с объектами и схемами**
   - Список объектов, выбор активного.
   - Создание/редактирование/удаление мнемосхемы объекта.
   - Публикация схемы (простая кнопка «Опубликовать», без версионности/rollback).
   - Доступ к устройствам и тегам в контексте выбранного объекта.
2. **Редактор холста**
   - Добавление/удаление/копирование фигур из зафиксированного набора `editor-ui` (`rect`, `circle`, `ellipse`, `wedge`, `line`, `image`, `text`, `ring`, `arc`, `tag`, `path`).
   - Трансформации: перемещение, масштабирование, поворот, выравнивание по сетке, Z‑order.
   - Свойства: позиция, размеры, цвет/заливка/рамка, видимость.
   - **Динамика (МVP):** смена цвета и/или видимости на основе значения привязанного тега (простые правила).
3. **Привязка к тегам**
   - Выбор тега из справочника `ms-editor` и привязка к фигуре.
   - Конфигурация условий для цвета/видимости (>, >=, ==, диапазоны; маппинг булево → цвет/видимость).
4. **Редактирование устройств и тегов**
   - Создание/редактирование/удаление **Device** (Modbus TCP/RTU, SNMP).
   - Редактирование параметров подключения и опроса устройства в карточке объекта.
   - Создание/редактирование/удаление **Tag** для выбранного устройства.
   - Поля для тега в MVP: адрес/OID, тип данных, единица измерения; уставки и масштабирование доступны как часть конфигурации тега, но могут быть скрыты в UI до отдельной проработки UX.
5. **История действий**
   - Полноценный **undo/redo** для операций на холсте и изменений свойств фигур (цель — не менее 50 шагов).
   - История локальна для сессии и не влияет на «публикацию».
6. **Черновики**
   - Автосохранение черновика в браузере (localStorage/IndexedDB).
   - Сохранение черновика в backend — TBA/вне MVP.
7. **Обработка ошибок и подсказки**
   - Подсветка незаполненных или «битых» привязок на фигурах.
   - Тосты/диалоги об ошибках операций с backend и об успешных действиях.
8. **Права**
   - Базовый режим: редактирование доступно всем залогиненным (тонкий RBAC — вне MVP). Возможен флаг «только чтение».

## Пользовательские потоки (UX-скелет)

- **Создать схему:** Объект → «Новая схема» → пустой холст → добавить фигуры → привязать теги → настроить правила цвета/видимости → «Опубликовать».
- **Привязать фигуру к тегу:** Выбрать фигуру → панель «Данные» → поиск тега → выбрать → задать правило (например, `== 1 → зелёный`, иначе серый).
- **Создать устройство и теги:** Выбрать объект → вкладка «Устройства и теги» → «Создать устройство» → заполнить параметры протокола (например, Modbus TCP/IP) → «Сохранить» → «Добавить тег» → заполнить адрес/тип/единицу → «Сохранить».

## Интерфейс (минимальные панели)

- **Холст** (центр): Konva Stage + сетка/направляющие.
- **Левая панель**: Дерево объектов/схем; поиск; кнопки «Новая схема», «Удалить».
- **Правая панель (вкладки)**:
  - **Свойства**: геометрия, стиль, слой/Z‑order.
  - **Данные**: выбор тега, правила цвета/видимости.
  - **Устройства и теги**: список устройств объекта, формы устройства и его тегов, доступ к справочникам типов и единиц.
- **Верхняя панель**: Undo/Redo, Сохранить, Опубликовать, Зум, привязка к сетке.

## Нефункциональные требования (MVP)

- **Производительность холста:** целевая плавность ~60 fps при ≥ 500 фигурах (батч‑обновления, throttle/RAF).
- **Undo/Redo:** быстрые операции отката/повтора (ориентир ≤ 10 мс на шаг при типичных изменениях).
- **Автосохранение:** каждые ~5 секунд при наличии несохранённых изменений.
- **Стабильность форм:** оптимистичное сохранение с откатом при ошибке backend (визуальная индикация состояния).
- **Аксессибилити:** базовая навигация с клавиатуры (стрелки/модификаторы), фокус‑индикация.

## Логи и телеметрия (минимум)

- События: `diagram.saved`, `diagram.published`, `device.created`, `tag.created`.
- Ошибки: логирование текстов ошибок UI/сети и HTTP‑ответов; единый канал для сбора (интеграция TBA).

## Вне MVP (осознанно откладываем)

- Версионность схем и rollback.
- Realtime‑предпросмотр значений в редакторе.
- Уставки/масштабирование тегов в UI.
- Тест опроса устройства из UI.
- Тонкий RBAC/разрешения.
- Импорт/экспорт конфигурации.
