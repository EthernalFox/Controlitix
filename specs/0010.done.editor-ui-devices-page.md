# 0010: editor-ui — Страница устройств объекта

## Scope

`editor-ui` — `pages/DevicesPage`, `entities/devices`, `widgets/`. Вкладка «Устройства» внутри `ObjectDetailPage`.

## Context

Страница устройств — вкладка в карточке объекта (`/objects/:objectId/devices`). Инженер видит таблицу устройств текущего объекта, добавляет новые, редактирует настройки подключения и удаляет устройства.

Форма устройства зависит от типа (протокола): Modbus RTU/TCP, SNMP v1/v2c/v3. Каждый тип имеет свой набор полей настроек подключения (settings JSONB).

Зависимости:
- **0008** (Objects page) — маршрутизация, ListLayout, ObjectDetailPage, фасадные компоненты, API-клиент.
- **0003** (ms-editor device CRUD + Kafka) — бэкенд API, структура settings JSONB по типам устройств.
- **0007** (ms-editor validation) — валидация settings по типу устройства, RFC 7807 ошибки.
- `docs/03_Модель-данных/devices/Devices.md` — модель данных.
- `docs/03_Модель-данных/devices/Devices_params.md` — settings JSONB.
- `docs/03_Модель-данных/devices/Device_type.md` — справочник типов.

## 1. User Flow

### 1.1 Просмотр таблицы устройств

```
Пользователь на /objects/:objectId → кликает вкладку «Устройства»
  → Навигация на /objects/:objectId/devices
  → Контент: заголовок «Устройства» + кнопка «Добавить устройство» + фильтры + таблица

  Таблица:
  ┌──────────────────────────────────────────────────────────────┐
  │ Название       │ Тип          │ Описание            │       │
  ├──────────────────────────────────────────────────────────────┤
  │ PLC-01         │ Modbus TCP   │ Контроллер котла     │ ✏️ 🗑 │
  │ RTU-Sensors    │ Modbus RTU   │ Датчики 1 этажа      │ ✏️ 🗑 │
  │ Switch-Core    │ SNMP v2c     │ Коммутатор ядра      │ ✏️ 🗑 │
  └──────────────────────────────────────────────────────────────┘
```

### 1.2 Фильтрация и поиск

```
Над таблицей:
  [🔍 Поиск по имени...] [Тип: Все ▾]

  → Поиск: TextInput, фильтрует по name (локально в MVP)
  → Фильтр по типу: Select с опциями из GET /device-types
  → Фильтры комбинируются (AND)
```

### 1.3 Добавление устройства

```
Пользователь нажимает «Добавить устройство»
  → Открывается Drawer справа (width 400px)
  → Шапка Drawer: «Новое устройство»
  → Форма (шаг 1 — общие поля):
    - Название (TextInput, обязательное)
    - Описание (Textarea, опциональное)
    - Тип устройства (Select, обязательное) → опции из GET /device-types

  → Пользователь выбирает тип → появляются поля настроек (шаг 2)

  Если тип = modbus_tcp:
    - Host (TextInput, обязательное, placeholder «192.168.1.100»)
    - Port (NumberInput, обязательное, default 502)
    - Slave ID (NumberInput, обязательное, 1–247)
    - Timeout, мс (NumberInput, обязательное, default 3000)

  Если тип = modbus_rtu:
    - Serial Port (TextInput, обязательное, placeholder «/dev/ttyUSB0»)
    - Baud Rate (Select, обязательное, опции: 9600, 19200, 38400, 57600, 115200)
    - Data Bits (Select, default 8, опции: 7, 8)
    - Stop Bits (Select, default 1, опции: 1, 2)
    - Parity (Select, default «none», опции: none, even, odd)
    - Slave ID (NumberInput, обязательное, 1–247)
    - Timeout, мс (NumberInput, обязательное, default 3000)

  Если тип = snmp_v1 или snmp_v2c:
    - Host (TextInput, обязательное)
    - Port (NumberInput, обязательное, default 161)
    - Community (TextInput, обязательное, default «public»)
    - Timeout, мс (NumberInput, обязательное, default 5000)

  Если тип = snmp_v3:
    - Host (TextInput, обязательное)
    - Port (NumberInput, обязательное, default 161)
    - Security Name (TextInput, обязательное)
    - Auth Protocol (Select, опции: MD5, SHA)
    - Auth Password (TextInput, type password)
    - Priv Protocol (Select, опции: DES, AES)
    - Priv Password (TextInput, type password)
    - Timeout, мс (NumberInput, обязательное, default 5000)

  → Submit → POST /objects/:objectId/devices (body: { name, description, type_id, settings })
  → Drawer закрывается
  → Устройство появляется в таблице
  → При ошибке валидации: подсветка полей + текст ошибки (RFC 7807 errors[].field)
```

### 1.4 Редактирование устройства

```
Пользователь нажимает ✏️ в строке таблицы
  → GET /devices/:id → загрузка полных данных устройства
  → Открывается Drawer с предзаполненными полями
  → Шапка: «Редактирование: PLC-01»
  → Тип устройства — НЕ редактируемый (Select disabled)
  → Поля настроек показываются сразу (тип уже известен)
  → Submit → PATCH /devices/:id
  → Drawer закрывается, строка таблицы обновляется
```

### 1.5 Удаление устройства

```
Пользователь нажимает 🗑 в строке таблицы
  → Открывается Modal подтверждения:
    «Удалить устройство "PLC-01"?
     Все теги этого устройства (12 шт.) будут удалены.»
  → Кнопки: «Удалить» (danger) / «Отмена» (secondary)
  → Submit → DELETE /devices/:id
  → Строка исчезает из таблицы
```

### 1.6 Empty state

```
Нет устройств у объекта
  → Иконка + текст «У этого объекта нет устройств»
  → Кнопка «Добавить первое устройство»
```

## 5. API-интеграция

### 5.1 Типы

```ts
// entities/devices/types.ts

export interface DeviceType {
  id: number;
  name: string; // modbus_rtu, modbus_tcp, snmp_v1, snmp_v2c, snmp_v3
}

export interface Device {
  id: string;
  objectId: string | null;
  typeId: number;
  typeName: string;      // denormalized из join, или вычисляется на клиенте
  name: string;
  description: string | null;
  createdAt: string;
  updatedAt: string;
}

export interface DeviceWithParams extends Device {
  settings: DeviceSettings;
}

// --- Settings по типу устройства ---

export interface ModbusTcpSettings {
  host: string;
  port: number;
  slave_id: number;
  timeout_ms: number;
}

export interface ModbusRtuSettings {
  serial_port: string;
  baud_rate: number;
  data_bits: number;
  stop_bits: number;
  parity: "none" | "even" | "odd";
  slave_id: number;
  timeout_ms: number;
}

export interface SnmpV1V2cSettings {
  host: string;
  port: number;
  community: string;
  timeout_ms: number;
}

export interface SnmpV3Settings {
  host: string;
  port: number;
  security_name: string;
  auth_protocol: "MD5" | "SHA";
  auth_password: string;
  priv_protocol: "DES" | "AES";
  priv_password: string;
  timeout_ms: number;
}

export type DeviceSettings =
  | ModbusTcpSettings
  | ModbusRtuSettings
  | SnmpV1V2cSettings
  | SnmpV3Settings;

export interface CreateDevicePayload {
  name: string;
  description?: string;
  type_id: number;
  settings: DeviceSettings;
}

export interface UpdateDevicePayload {
  name?: string;
  description?: string;
  settings?: DeviceSettings;
}
```

### 5.2 API-функции

```ts
// entities/devices/api.ts

import { api } from "@shared/api";
import type { PaginatedResponse } from "@shared/api";
import type {
  Device,
  DeviceWithParams,
  DeviceType,
  CreateDevicePayload,
  UpdateDevicePayload,
} from "./types";

export const devicesApi = {
  listByObject: (objectId: string, params?: { offset?: number; limit?: number; name?: string; type_id?: number }) =>
    api.get<PaginatedResponse<Device>>(`/objects/${objectId}/devices`, params),

  get: (id: string) =>
    api.get<DeviceWithParams>(`/devices/${id}`),

  create: (objectId: string, payload: CreateDevicePayload) =>
    api.post<DeviceWithParams>(`/objects/${objectId}/devices`, payload),

  update: (id: string, payload: UpdateDevicePayload) =>
    api.patch<DeviceWithParams>(`/devices/${id}`, payload),

  delete: (id: string) =>
    api.delete(`/devices/${id}`),
};

export const deviceTypesApi = {
  list: () =>
    api.get<DeviceType[]>("/device-types"),
};
```

## 6. Компоненты

### 6.1 DevicesPage

```tsx
export default function DevicesPage() {
  const { objectId } = useParams<{ objectId: string }>();
  const { devices, deviceTypes, isLoading, fetchDevices, fetchDeviceTypes } = useDevicesStore();

  // Локальный state фильтров
  const [search, setSearch] = useState("");
  const [typeFilter, setTypeFilter] = useState<string | null>(null);

  // Загрузка при монтировании
  useEffect(() => { fetchDevices(objectId!); fetchDeviceTypes(); }, [objectId]);

  // Локальная фильтрация (MVP)
  const filtered = useMemo(() => devices.filter(...), [devices, search, typeFilter]);

  // Drawer state
  const [drawerMode, setDrawerMode] = useState<"closed" | "create" | "edit">("closed");
  const [editDeviceId, setEditDeviceId] = useState<string | null>(null);

  return (
    <>
      {/* Header */}
      <Group justify="space-between" mb="md">
        <Text size="xl" fw={600}>Устройства</Text>
        <Button variant="primary" onClick={() => setDrawerMode("create")}>
          Добавить устройство
        </Button>
      </Group>

      {/* Filters */}
      <Group mb="md" gap="sm">
        <TextInput placeholder="Поиск по имени..." value={search} onChange={...} />
        <Select placeholder="Тип" data={deviceTypes.map(...)} value={typeFilter} onChange={...} clearable />
      </Group>

      {/* Table or Empty/Loading state */}
      {isLoading ? <SkeletonTable /> : filtered.length === 0 ? <EmptyState /> : <DevicesTable />}

      {/* Drawer */}
      <DeviceDrawer
        opened={drawerMode !== "closed"}
        mode={drawerMode === "edit" ? "edit" : "create"}
        deviceId={editDeviceId}
        objectId={objectId!}
        onClose={() => { setDrawerMode("closed"); setEditDeviceId(null); }}
      />
    </>
  );
}
```

### 6.4 DeviceSettingsForm — динамические поля

```tsx
// widgets/DeviceDrawer/DeviceSettingsForm.tsx

interface DeviceSettingsFormProps {
  typeName: string | null;     // "modbus_tcp", "modbus_rtu", etc.
  settings: DeviceSettings;    // текущие значения
  onChange: (settings: DeviceSettings) => void;
  errors?: Record<string, string>;  // ошибки по полям из RFC 7807
}

export const DeviceSettingsForm = ({ typeName, settings, onChange, errors }: DeviceSettingsFormProps) => {
  switch (typeName) {
    case "modbus_tcp":  return <ModbusTcpFields settings={settings} onChange={onChange} errors={errors} />;
    case "modbus_rtu":  return <ModbusRtuFields settings={settings} onChange={onChange} errors={errors} />;
    case "snmp_v1":
    case "snmp_v2c":    return <SnmpV1V2cFields settings={settings} onChange={onChange} errors={errors} />;
    case "snmp_v3":     return <SnmpV3Fields settings={settings} onChange={onChange} errors={errors} />;
    default:            return null; // тип не выбран — поля не показываются
  }
};
```

Каждый `*Fields` компонент — набор полей в `Stack gap="sm"`. Значения по умолчанию (port, timeout, baud_rate) устанавливаются при первом выборе типа.

### 6.5 Валидация

**Клиентская (базовая):**
- `name` — не пустое.
- `type_id` — выбран.
- Обязательные поля settings (host, port, serial_port, etc.) — не пустые.
- `slave_id` — 1–247 (Modbus).
- `port` — 1–65535.

**Серверная (RFC 7807):**
- Если API вернул `application/problem+json` с `errors[]`, маппим `errors[i].field` на поля формы.
- Поля settings маппятся как `settings.host`, `settings.port`, etc. — для отображения нужен `field.replace("settings.", "")`.

## Constraints

- **Фасадный паттерн**: Drawer, NumberInput, PasswordInput — через `shared/ui/components/`. Не импортировать `@mantine/core` напрямую.
- **FSD**: DeviceDrawer — widget. *Fields-компоненты — внутренние модули DeviceDrawer (не экспортируются наружу).
- **Тип устройства нередактируемый**: при edit mode Select типа disabled. Смена типа требует удаления и создания нового устройства.
- **Store reset**: при смене objectId store сбрасывается.
- **Device types кешируются**: `fetchDeviceTypes()` загружается один раз, результат живёт в store.
- **Settings JSONB**: клиент формирует объект и отправляет как есть. Серверная валидация приоритетнее клиентской.
- **Не реализовывать**: теги устройства (отдельная спека), assign/unassign из пула (будущая спека).
