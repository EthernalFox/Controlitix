# ADR-0006: Nginx как единая точка входа (gateway)

- Статус: accepted
- Дата: 2026-04-15
- Авторы: команда Controlitix

## Контекст

Клиенты Controlitix (editor-ui, viewer-ui) должны обращаться к backend-сервисам по HTTPS через одно имя/порт. Требуется:

- Терминация TLS (корпоративный или самоподписанный сертификат).
- Маршрутизация REST-запросов к `ms-editor`, `ms-viewer`, `ms-auth`.
- Проксирование WebSocket к `ms-viewer`.
- Раздача статики фронтендов (`editor-ui`, `viewer-ui`).
- Базовая защита (rate limiting, ограничение размера тела запроса).
- Нет требований к сложным workflow вроде OIDC-прокси, JWT-валидации на gateway и т. п.

## Рассмотренные варианты

1. **Nginx** — широко известен, простая конфигурация, нативно умеет reverse proxy, WS, статику, TLS.
2. **Traefik** — удобен в k8s/Compose за счёт авто-discovery, но избыточен для статичной схемы MVP и добавляет слой конфигурационной магии.
3. **Kong / KrakenD / Tyk** — полноценный API Management, избыточен (плагины, БД для конфигов, оверхед).
4. **Envoy** — мощный, но требует существенной экспертизы в xDS-конфигурации.
5. **Без gateway, сервисы торчат напрямую** — отдельные порты, CORS, TLS на каждом сервисе, много дубля.

## Решение

Выбран **Nginx**:

- Разворачивается как отдельный сервис в `docker-compose.yml`.
- Терминирует TLS на 443 (внутри корпоративной сети).
- Маршрутизация по префиксам:
  - `/api/editor/*` → `ms-editor:8080`
  - `/api/viewer/*` → `ms-viewer:8080`
  - `/ws/viewer` → `ms-viewer:8080` (upgrade, long-lived)
  - `/api/auth/*` → `ms-auth:8080`
  - `/editor/*` → статика `editor-ui`
  - `/viewer/*` или `/` → статика `viewer-ui`
- Nginx **не валидирует JWT** сам — токены проверяются backend-сервисами. Gateway отвечает только за маршрутизацию и TLS.
- Rate limiting — базовый (например, `limit_req` для `/api/auth/login`).
- Заголовок `X-Forwarded-For` и `X-Real-IP` пробрасываются backend-ам для аудита.

## Последствия

**Позитивно:**

- Один домен, одно имя, один сертификат.
- Конфигурация Nginx — 1 файл, понятна без обучения.
- Поддержка WebSocket из коробки.
- Статика фронтендов раздаётся эффективно.

**Негативно:**

- Без динамической discovery — при добавлении сервисов нужно обновлять конфиг nginx (приемлемо для MVP, где сервисов 4).
- Нет централизованной валидации JWT на gateway (но для MVP это принято: каждый сервис валидирует сам, см. ADR-0007).
- В случае переезда в k8s конфиг будет переписан на Ingress (планируется уже вне MVP).
