# 0007: ms-editor — Validation + RFC 7807 error handling

## Scope

`ms-editor/internal/` — domain, usecase, api/http.

## Context

Currently ms-editor has minimal validation (only `strings.TrimSpace(name) == ""` checks) and simple error responses (`{"message":"..."}`). This task adds:

1. **JSONB validation** for device settings and tag address based on device type.
2. **Setpoint validation** (LoLo < Lo < Hi < HiHi).
3. **RFC 7807 error responses** (`application/problem+json`) with structured details.
4. **Input validation** across all endpoints.

Prerequisite: specs 0003, 0004 (device and tag CRUD).

## Files

### New files

- `ms-editor/internal/domain/validation.go` — validation functions and error types
- `ms-editor/internal/domain/device_settings_schema.go` — device settings schemas per type

## Interface

### RFC 7807 error response

Replace the current `errorResponse` struct:

```go
// api/http/models.go

type problemResponse struct {
    Type     string            `json:"type"`               // URI reference, e.g. "/problems/validation-error"
    Title    string            `json:"title"`              // Human-readable summary
    Status   int               `json:"status"`             // HTTP status code
    Detail   string            `json:"detail,omitempty"`   // Detailed explanation
    Instance string            `json:"instance,omitempty"` // Request path
    Errors   []fieldError      `json:"errors,omitempty"`   // Field-level errors (for 422)
}

type fieldError struct {
    Field   string `json:"field"`
    Message string `json:"message"`
}
```

### Error types

| Type URI | Status | When |
|----------|--------|------|
| `/problems/validation-error` | 422 | Field-level validation failures |
| `/problems/invalid-request` | 400 | Malformed JSON, missing required fields |
| `/problems/not-found` | 404 | Entity not found or soft-deleted |
| `/problems/conflict` | 409 | Unique constraint violation |
| `/problems/method-not-allowed` | 405 | Wrong HTTP method |
| `/problems/internal-error` | 500 | Unexpected server error |

### Device settings validation

```go
// domain/device_settings_schema.go

// ValidateDeviceSettings validates settings JSONB against device type.
// Returns nil if valid, *ValidationError if not.
func ValidateDeviceSettings(deviceTypeName string, settings json.RawMessage) *ValidationError
```

**Validation rules per device type:**

**modbus_rtu** (all required):
| Field | Type | Validation |
|-------|------|-----------|
| `serial_port` | string | non-empty |
| `baud_rate` | int | one of: 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200 |
| `data_bits` | int | one of: 7, 8 |
| `parity` | string | one of: `"none"`, `"even"`, `"odd"` |
| `stop_bits` | int | one of: 1, 2 |
| `slave_id` | int | 1..247 |
| `timeout_ms` | int | 100..30000 |

**modbus_tcp** (all required):
| Field | Type | Validation |
|-------|------|-----------|
| `host` | string | non-empty, valid IP or hostname |
| `port` | int | 1..65535 |
| `slave_id` | int | 0..247 (0 = broadcast) |
| `timeout_ms` | int | 100..30000 |

**snmp_v1, snmp_v2c** (all required):
| Field | Type | Validation |
|-------|------|-----------|
| `host` | string | non-empty, valid IP or hostname |
| `port` | int | 1..65535 |
| `community` | string | non-empty |
| `timeout_ms` | int | 100..30000 |
| `retry_count` | int | 0..10 |

**snmp_v3** (all required):
| Field | Type | Validation |
|-------|------|-----------|
| `host` | string | non-empty |
| `port` | int | 1..65535 |
| `security_name` | string | non-empty |
| `security_level` | string | one of: `"noAuthNoPriv"`, `"authNoPriv"`, `"authPriv"` |
| `auth_protocol` | string | one of: `"MD5"`, `"SHA"` (required if level != noAuthNoPriv) |
| `auth_password` | string | non-empty (required if level != noAuthNoPriv) |
| `priv_protocol` | string | one of: `"DES"`, `"AES"` (required if level == authPriv) |
| `priv_password` | string | non-empty (required if level == authPriv) |
| `timeout_ms` | int | 100..30000 |
| `retry_count` | int | 0..10 |

### Tag address validation

```go

```

**Modbus (modbus_rtu, modbus_tcp):**
| Field | Type | Validation |
|-------|------|-----------|
| `register_type` | string | one of: `"holding"`, `"input"`, `"coil"`, `"discrete"` |
| `address` | int | 0..65535 |

**SNMP (snmp_v1, snmp_v2c, snmp_v3):**
| Field | Type | Validation |
|-------|------|-----------|
| `oid` | string | non-empty, matches pattern `^[0-9]+(\.[0-9]+)+$` |

### Setpoint validation

```go
func ValidateSetpoints(setpoints TagSetpoints) *ValidationError
```

Rules:
- If all four are set: `LoLo < Lo < Hi < HiHi` (strict).
- If only some are set, validate the ones that are present: any pair with both present must satisfy the ordering.
- Each value must be a finite number (not NaN, not Inf).

### Scaling validation

```go
func ValidateScaling(scaling TagScaling) *ValidationError
```

Rules:
- If interpolation is used (`raw_min`/`raw_max`/`eng_min`/`eng_max`): all four must be present, `raw_min != raw_max`.
- If factor/offset is used: `factor` must not be zero (if set).
- Partial interpolation (e.g., `raw_min` set but `raw_max` not) → validation error.
- All values must be finite.

### General input validation

Applied in usecases before repository calls:

| Entity | Field | Rule |
|--------|-------|------|
| Object | `name` | non-empty, max 255 chars |
| Device | `name` | non-empty, max 255 chars |
| Device | `type_id` | must exist in `device_type` table |
| Tag | `name` | non-empty, max 255 chars |
| Tag params | `data_type_id` | must exist in `data_types` table |
| Tag params | `unit_id` | if set, must exist in `units` table |
| Diagram | `name` | max 255 chars (nullable, so empty is OK) |

## Updated error response format

**Before (current):**
```json
{"message": "invalid request"}
```

**After (RFC 7807):**
```json
{
  "type": "/problems/validation-error",
  "title": "Validation failed",
  "status": 422,
  "detail": "One or more fields have invalid values",
  "errors": [
    {"field": "settings.baud_rate", "message": "must be one of: 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200"},
    {"field": "settings.slave_id", "message": "must be between 1 and 247"}
  ]
}
```

**Content-Type** header: `application/problem+json` for error responses.

## Constraints

- Do NOT add external validation libraries (no `go-playground/validator`). Implement validation as plain Go functions in the domain layer.
- Validation runs in the usecase layer, NOT in the handler. Handlers only parse input.
- The tag address validation requires knowing the device type. The usecase must look up the device to get its `type_name` before validating the tag address.
- Preserve backwards compatibility of error detection in the handler's `mapDomainError` — existing error types (`ErrNotFound`, `ErrInvalidInput`, `ErrConflict`) must still work, plus the new `*ValidationError`.
- The `response.go` `writeError` function should be updated to write RFC 7807 format. All existing call sites (`writeError(w, 400, "...")`) must keep working — treat them as `invalid-request` type.

## Verify

- `go build ./...` passes.
- `POST /objects/{id}/devices` with invalid settings returns 422 with field-level errors.
- `POST /devices/{id}/tags` with invalid address returns 422 with `"field": "address.register_type"`.
- `PUT /tags/{id}/setpoints` with `{"lolo":50,"lo":10}` returns 422 (`lolo must be less than lo`).
- `PUT /tags/{id}/scaling` with `{"raw_min":0}` (incomplete) returns 422.
- `POST /objects` with `{"name":""}` returns 400 (`name is required`).
- All error responses have `Content-Type: application/problem+json`.
- All error responses include `type`, `title`, `status` fields.
- Successful responses still use `Content-Type: application/json` (not problem+json).
